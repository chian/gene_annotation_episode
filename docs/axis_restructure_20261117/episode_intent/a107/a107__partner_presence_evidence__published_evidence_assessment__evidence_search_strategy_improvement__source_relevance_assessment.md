Source of this note: the episode's own files at `97308b94c` (32 files directly in the folder; no grading/ or scoring/ subfolder). Child folders were not read.

## What it is for

Goal (goal.py, own words): `_ROLE_INSTRUCTIONS['literature_search']` = "Investigate which returned sources merit examination for the assigned question. Search results are source-discovery information. Examine original sources and their conditions before asserting biological evidence. A page child can investigate where and how to examine a selected source." followed by the A107 partner text: "Investigate reported partner removal, addback and coexpression evidence. Preserve the original molecule and partner roles, normalization, nonpartner conditions, physical measurement identity, source units and uncertainty. Condition-specific dependence does not establish universal necessity, genomic presence, target correspondence or annotation credit. A search or read earns no scientific credit by itself."

In short: given search results from the strategy parent, decide which returned sources deserve examination, and commission a per-source examination child.

## Task and instructions

- Task (task.py): decision loop - build a decision snapshot, call the model, apply its response; a model-call error records a source failure (`category: decision_source`) and ends the episode `source_failed`.
- Instructions (task_instructions.py): the base decision INSTRUCTIONS + this goal text; since `reason` and `wait` are not permitted here, the reasoning-commit and wait texts are not added; the pending-child redelivery text is always added; tool-knowledge and launch-instruction texts are added when those inputs are present; exchange protocol swaps the history guidance for "use request_context exchanges ... episode.history ...".
- Prompt (task_presentation.py + task_reading_prompt.py): a TASK / STEERING text prompt (marker `literature_experimental_work`), sections listed in the file table below.

## What it reads from the parent's assignment

`search_assignment_v1` (from_parent.py): `{version, question_context_refs: [ref], search_result_refs: [ref]}` plus the partner fields from `library.partner_source_contracts.assignment_schema_fields()` (shared-root library; not read). Every `*_refs` entry must be in scope; `search_result_refs` must be `source` records. Assignment is re-validated on every decision, every tool call and every report.

Observed: internal_summary.py builds `literature_source_custody` from `assignment.get('source_refs', [])` (or `page.source_ref`), but this assignment declares `search_result_refs`; unless the partner fields add `source_refs`/`page`, the custody list shown to the model is empty and tool calls are not confined to a page. The sibling leaf episodes read `page` from their own assignment.

## Tools it offers

From the services' tool catalog, only: access tools `state.query, source.read, source.locate, source.sequence.scan, source.sequence.references, source.experimental.records, image.view, source.archive.members, source.archive.extract, source.xlsx.sheets, source.xlsx.rows, source.pdf.info, source.pdf.text, source.pdf.page, execution.estimate` (estimate restricted to its xlsx sheets/rows branches) **plus acquisition tools** `public.literature.search, public.literature.read, public.literature.sequence_identity, public.ncbi.search (database restricted to pubmed), public.pmc.versions, public.pmc.files, public.pmc.asset`, plus the partner population operations (`literature.partner.populate`, `literature.partner.source.populate`). Every tool input passes `source_location_inputs`. `source.locate / sequence.scan / sequence.references / experimental.records` are authorised only on the received record refs. If the assignment has a `page`, every source_ref (and every source ref inside a population call) must lie within that page's source.

Common actions: `tool`, `child`, `redeliver_report`.

## Credit

`credit_kind` = `scientific`; `credit_view` = services.scientific_credit(context, receiver_selection); no projector. Credit is read after every observed action outcome (after automatic score updates); a `wait` keeps the last observed credit; a failed tool/reason execution is recorded as a failed outcome with its credit and enters the iterator. No bounds or rescaling anywhere in these files.

## Continuation

yield_estimator.py: `continuation_task` None and `yield_controller` None - no own continuation; the old runner's default controller ran it (`_category_yield_parameters(controller_binding)`, `yield_table` of own actions, `controller_value(index, credit)`). The files name no target, no quality bound and no settings, which fits the **accumulation** estimator with default settings; this choice is an inference, not stated in the files.

## What it reports to its parent

The parent's typed form, filled by `form_with_facts(report_values, contract schema, facts)`; facts = `_rate_facts` over committed record refs: per population route, the partner fact cells of received source records of that provider (version-checked) plus current sheet refs, restricted to the requested components. Before delivery, `validate_report` re-validates the assignment, the form references and the received partner cells. Without a parent contract: `{credit, pending_handles}` + current report facts ({}).
