## Purpose (own words)

The A107 scientific investigation of partner presence evidence. Its goal text (`goal.py`) is the A107 `INSTRUCTIONS` from `component_axis_workflow` plus:

> "Scientific descendants remain A107. Use available shared operations for specific parent information needs or useful received findings. The immediate parent chooses within its own options or relays the need upward; publication does not commission work or promise a reply. Preserve named scientific components separately from controller progress."

For an instruction-version evidence axis it continues: "Determine what the supplied target does within the parent's assigned question, scope and constraints. Start with the supplied sequence, selected file contents or snippets ... No initial candidate annotation or publicly searchable name is required. Possible functions can emerge from the evidence and be compared or revised. Apply the complete selected investigation instructions and thought-pattern guidance on every decision ... Missing information remains unknown." It then describes the actions it can take (tool, reasoning commit, scoped child with a typed form, wait), says process.revise prepares an alternative thought pattern/tool selection for a *new* child only, "Children own their iterative choices. The configured controller owns continuation. Waiting and unchanged observations do not manufacture progress." Older support-metadata axes get a separate goal text about `annotation_support_routes` (metadata earns no credit, never replaces projectors).

## Task and instructions

- `task_instructions.compose_instructions`: default runtime `INSTRUCTIONS`, replaced by the specialist's goal text when `replaces_default_instructions` (true when every configured evidence axis is instruction-version); adds REASONING_COMMIT_REQUIREMENT, tool-knowledge and launch-library instructions, the pending-child-delivery repair paragraph, the pending-child wait paragraph and the native-event wait paragraph when wait is permitted, and the decision-exchange history replacement.
- `task_decision.render_partner_presence_evidence_prompt` is this episode's own TASK prompt: assigned work and result contract, fixed scope, parent constraints and context, parent-selected evidence operands, supplied material and scoped access, selected source operands (metadata only — "Read the actual contents to establish what each source supports"), "Investigate the supplied target: <axis>" with the axis investigation instructions, "Reason about the evidence: <thought pattern>" (description, use_when, alternatives, decision guidance, outcome contingencies table, boundary), each selected tool's description/instructions, assigned launch manuals, callable operations with operand schemas, permitted child roles, child options, an "Evidence through child returns" paragraph (committed_record_refs carries acquired records; a job handle or usable handoff alone does not return search data; keep empty vs partial vs unavailable acquisition distinct from biological evidence), the contract-lookup paragraph (`episode.return_contract`, `$ref: episode-fact:<source>`, return saved grading results without a new verdict or invented threshold), parent return form and fact meanings, then the steering section.
- `task.py` / `decision_delivery.py`: the shared-shape decision loop, with this episode's own addition: before a new decision and before executing, `partner_presence_evidence_binding.validate_execution_context` (a closed request permits inspection/replay, never new dispatch).

## Credit

`credit_kind` scientific. Projector = `original_task_projector(assignment)` → A107 `finding_progress()` (checks any `a107_task` context matches `task_context`), only for instruction-version axes. `credit_view` = `services.scientific_credit(context, receiver_selection)`. Unbounded; no clamping in these files.

## Continuation

Yield estimator: accumulation only. `continuation_task` = `A107:<context.a107_task.name>` or `A107:<projector kind>`; the configured `yield_bindings[task]` must have kind/cutoff/parameters {uncertainty_alpha}/credit_definition, the credit_definition digest must equal the projector record and its `yield_method` must equal the kind; accumulation → `YieldController(epoch, initial_credit, cutoff, YieldParameters(uncertainty_alpha))`. Configuration accepts bounded_quality and completion declarations, but `yield_controller` raises `scientific_yield_method_unavailable` for them. With no yield bindings it returns None (old recorded controller).

## Report to parent

`to_parent.facts`: `partner_presence_evidence_results` (own process result + received ones, projected and merged), native-hpc `FACT_SOURCE`/`EXECUTION_SOURCE` rows when the form requests them, A107 qualification facts (received qualifications, execution findings), component scoring sheets. `validate_report`: form references resolve, component-axis report must be A107 and resolve against received component evidence, `partner_presence_evidence_results` fields must equal the frozen original results. `report_delivery.finish` writes the facts+interpretations form; `report_snapshot.complete_scientific_snapshot` records initial credit, credit, controller credit, episode_yield and the parent invocation ref.

## Differences from similar episodes

- Unlike the execution episodes below it, credit is scientific (finding progress) and the yield is accumulation; only the A107 axis option is admitted.
- Has a `monitor` child with its own non-envelope request/receive pair and three extra child kinds (hpc, literature, recursive self).
- Its decision loop adds `validate_execution_context` guards absent from the job episodes.
