## Purpose (own words)

`goal.py`: "Choose which permitted concrete execution request to commission on an explicit resource_id. Capabilities, recorded inventory and timing information inform the choice. Preserve the original job, immutable inputs, constraints and pinned instructions. A resource child owns iterative execution in the shared loop. Receive its requested typed handoff; no infrastructure chooses an approach. Actual received usable handoff completes this launch endpoint with exact zero future credit."

It is a dispatcher: it does not run jobs itself; it chooses a resource child (API, local or HPC) for each request and receives the handoff.

## Task and instructions

`replaces_default_instructions = True`, so the goal text above is the specialist instruction. `task_instructions.py` carries this episode's own copy of the full A107-era runtime `INSTRUCTIONS`, `REASONING_COMMIT_REQUIREMENT` and `DECISION_EXCHANGE_PROTOCOL` text and composes: specialist text, reasoning requirement when reason is permitted, tool knowledge, launch library instructions, pending-child-delivery repair, pending-child wait and native-event wait paragraphs when wait is permitted, and the exchange-protocol history replacement.

## What it reads from its parent's assignment

`execution_launch_assignment_v1` (`from_parent.assignment_schema`): `requests` = map resource_id → concrete request (for each configured resource, `launch_request_schema` over the API service schema or the practical `ASSIGNMENT_SCHEMA` with requested_job alternatives: native BLAST/masking/utility/database/standard database, HMMER and preparation, Infernal and preparation, RNA structure, expression NMF), `immutable_input_versions`, `constraints` (allowed_resource_ids, allowed_kinds, resource_id, kind), `launch_instructions` (frozen library selection). `prepare_assignment`: when the parent is `hpc`/`hpc_execution` it authenticates the launch through `hpc_work_planning.to_child_execution_job_submission.authenticate_launch`; validates BLAST-graded requests (ncbi_blast service, matching resource), API requests against the API service, masking/utility inputs, input versions, native BLAST database, standard BLAST database and RNA structure inputs.

## Children it may commission

`child_roles` = launch_api, launch_local, launch_hpc; `allowed_children` keeps only roles with a resource of that kind that the assignment permits.

| Role | Child folder | Sends | Takes back |

## Decision state and what the model sees

`internal_summary.decision_context`: `execution_assignment`, `execution_progress` (= this episode's facts) and, when the services supply the scientific parent task, `selected_execution_task` {scientific_question, selected_tool_info, per-request {resource_id, kind, endpoint, constraints, job view (HMMER/NMF scientific views), resource information}, constraints, selector, result_description}. For API resources only `ebi_hmmer` produces the task view. `LaunchDecisionState.decision_state` builds the common model context. `task_decision.call` captures `execution_expectations` for role `launch` (resource estimates added when an estimator is configured).

## Tools offered

`work_operations.catalog` = `launch_operation_catalog()` = only `execution.capabilities` ("Read the actual caller-bound resource configuration and already recorded inventory; no discovery or selection."), returning `execution_capability_information`. `resource_tool_contracts` declares, per resource, the launch/results/homology/native operations with commission routes (used to describe children). Common actions: tool, reason, child, wait, redeliver_report; under an `hpc` ancestor only tool, child, redeliver_report.

## Credit

`credit_kind` operational. Live credit (`credit._live_project_credit`): received usable handoffs from known record refs, counted by distinct `resource_id` not already present in the initial refs; `credit = handoff_unit × new_handoff_count + acquired_record_unit × 0` (acquired fraction fixed at 0 here); binding `execution_received_records_credit_v1`. A closed episode's credit is the captured closed view (`_CLOSED_CREDIT`), authenticated against the closed episode row, archive, observation history and receipt-inheritance prefix; never re-projected.

## Continuation

`_launch_yield_controller`: eligible = permitted requests; remaining = (eligible − resources already handed off in initial refs) × handoff_unit. If remaining > 0: profile `launch:<sorted request yield classes joined by +>` from `task_yield_profiles` → `BoundedYieldController(epoch, initial_credit, cutoff, remaining, parameters)` (bounded quality with that bound). If none remain: initial credit must be 0 and a `YieldController` with an exact-zero estimator `launch_original_request_exhaustion_v1`. Requires `require_private_yield`. Completion proof (`completion.py`): a completed action whose record refs include a usable handoff of this assignment → `practical_completion_v1`, endpoint `usable_handoff`.

## Report to parent

`to_parent.facts`: empty native fact families (HMMER, masking, BLAST utility, RNA comparison/structure, NMF, Infernal and preparation, BLAST standard DB and DB, HMMER preparation, pairwise BLAST) plus `execution_handoff_refs`, `bvbrc_appservice_support_refs` (if appservice), `execution_blast_hsps` [], `execution_result_refs`, `execution_file_source_refs`, `execution_file_capture_outcomes`, `execution_result_origin`, `execution_completed` (any returnable handoff completed), plus closed-credit facts. `validate_report`: native return adapters, UniProt/Rfam hosts, reference resolution and every `x-source` field equal to recorded facts. `context_receipts.required_return_sources`: `execution_handoff_refs` when the parent is partner_presence_evidence and an annotation task is required.

## Differences from similar episodes

- Versus its API/HPC children: it owns the multi-request map and constraint filter, offers only `execution.capabilities`, commissions children, and uses a bounded yield whose bound is the uncredited request slots (the children use a plain YieldController with a practical completion estimator).
- Its `terminal_execution.py` copy lacks the execution-agent instructions, decision_context, as_record and prepare_assignment present in the children's copies.
- Its `task_instructions.py` inlines the INSTRUCTIONS text rather than importing it.
