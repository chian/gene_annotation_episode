## What this episode is for

Its goal, in its own words (`goal.py` with `source_contracts.py`):

> For A103, identify the actual locus and genome before using a source claim. Keep neighboring-gene identity, order, orientation, spacing, fusion, cooccurrence, and alternative explanations tied to their source and scope.
>
> Investigate where and how this exact source should be examined. Choose ordinary source operations or selected table, ordered-reading or targeted-passage investigations as useful. Paragraph projections omit some XML headings, tables and footnotes; retained original bytes remain addressable.

In short: It is handed one exact source in one representation and decides where and how to examine it: by its own source reads, or by commissioning a table reading, a document-order reading or a targeted-passage reading of it.

## Task and instructions

One unit is one model-selected action: a tool call, or a child commission. There is no reasoning-commit action (`source_interpretation.py`) and no waiting (`waiting.py`).

The instructions (`task_instructions.py`, this folder's own copy) are composed in this order:

1. The literature investigation text `INSTRUCTIONS` ("You own an iterative scientific annotation improvement, not a tool itinerary. ..."), held in the file itself.
2. This episode's goal text above, appended (the binding's `instructions`).
3. The tool-knowledge text, when tool knowledge is in the context; the launch-instruction text, when the launch-instruction library is.
4. The paragraph on a pending child delivery (`redeliver_report`).
5. `REASONING_COMMIT_REQUIREMENT` and the two wait paragraphs are only added when `reason` / `wait` are permitted; they are not here.
6. Under the exchange protocol the old history guidance is replaced by: use `request_context` exchanges for own attempt metadata (no completed action or observation), and read earlier outcomes with `episode.history` (view=records).

## What it reads from its parent's assignment

Assignment form (`from_parent.py`): the page itself, `page_assignment_v1` (`_PAGE`):

| Field | Meaning | Check |
|---|---|---|
| `version` | constant `page_assignment_v1` | exact |
| `source_ref` | the source to examine | a `source` record in scope |
| `representation` | `text`, `original`, `stdout` or `stderr` | the source's artifact for that representation must equal `artifact_ref` (`literature_source_artifact_mismatch`) |
| `artifact_ref` | the artifact read | in scope as an `artifact` |
| `question_context_refs` | records framing the question | each in scope |
| `prior_delivery_refs` | earlier deliveries about this source | each in scope |

A non-empty operation key is required. Nothing is checked against the parent's assignment.

It also reads from the commissioning request: the goal (objective, result contract); the Store scope; the report contract (requested form and purpose); `initial_report`; `episode_assignment` with its selected launch instructions; `job_assignment` when present; `gene_context_evidence` (rendered by the TASK prompt as parent constraints, context, evidence operands and guidance).

## Tools it offers

Action kinds: `tool`, `child`, `redeliver_report`.

Tools are those below that the scope's tool catalog actually has:

- **Access (15):** `state.query`, `source.read`, `source.locate`, `source.sequence.scan`, `source.sequence.references`, `source.experimental.records`, `image.view`, `source.archive.members`, `source.archive.extract`, `source.xlsx.sheets`, `source.xlsx.rows`, `source.pdf.info`, `source.pdf.text`, `source.pdf.page`, `execution.estimate`.
- **No acquisition tools.** It cannot search for or fetch new sources.

Adjustments: `execution.estimate` keeps only its `source.xlsx.sheets` / `source.xlsx.rows` branches (dropped if neither exists); every input schema goes through `source_location_inputs`.

**Held to the assigned source.** Any call naming a `source_ref` (for `execution.estimate`, the inner arguments; for `source.archive.extract`, the member's source) must name the page's source or a source derived from it through `parent_source_refs`, else `literature_reading_outside_assigned_source`. Within that source any window may be read.

Execution: arguments are validated against the offered schema; a tool not offered (`tool_not_available_to_a103_literature_role`), a schema failure or a source outside the assignment returns an `invalid` outcome with `arguments_or_reference` feedback, which still enters the iterator. `source.locate`, `source.sequence.scan`, `source.sequence.references`, `source.experimental.records` are authorized over the episode's received record refs.

## How its credit is counted

- Credit kind `scientific` (`credit.py`): the axis's scientific credit view for this episode (`services.scientific_credit(context, receiver_selection)`). No projector and no score judgments of its own (`scientific_records.py`).
- After each own action whose outcome counts as observed, the credit view is read again; its `credit` is saved with the action and handed to the controller as that unit's input (`task.py`). A unit that fails while executing is recorded `failed` and still enters the iterator with the credit measured after it (`task_state.py`). A response that fails admission is recorded as a `rejected` decision effect and creates no unit. Request_context exchanges create no unit.
- Nothing in these files bounds, clamps or rescales credit.
- What a child return does to credit is not in these files: the from_child file only collects the refs the child delivered; the credit is whatever the axis credit view says afterwards.

## What it reports to its parent

- With a report contract (the normal case): the parent's requested form, filled from the model's latest admitted `report_update` together with the report facts, saved once and returned as `{'form': ...}` (`report_delivery.py`). The fields are whatever the parent composed when commissioning.
- No report facts of its own (`to_parent.py`: `fact_sources`, `facts`, `current_report_facts` all empty).
- Before delivery the report is validated: the assignment must still be valid and every reference in the form must resolve in this episode's context.
- Without a report contract: `{'credit': <current credit>, 'pending_handles': ...}`.

## Old-runner machinery to replace

- **Every hook takes an old role name** (`self._role(context.role)`), and children are looked up by old role (`literature_page`, `literature_table`, `literature_ordered`, `literature_targeted`). The new contract names bindings by path and children by slot.
- **`self.workflow.*`** in `call.py`, `decision_exchange.py`, `saved_decision_exchange.py`, `decision_contracts.py`, `decision_provider.py`, `decision_inputs.py`, `decision_state.py`, `report_delivery.py`, `task.py`, `task_state.py`, `task_instructions.py` (as `source.workflow`), `task_suspension.py`, and the to_child / from_child files (as the `workflow` argument).
- **`BindingContext`** (`context.role`, `.assignment`, `.scope`, `.episode_id`, `.received_record_refs`; `parent.role`) is the argument of every binding hook.
- **Per-axis services provider** (`self.services`): `scientific_credit`, `own_outcomes`, `tool_catalog`, `execute_tool`, `reference_in_scope`, `read_record`.
- **Journal tables read or written directly:** `runtime_model_calls`, `runtime_actions`, `runtime_episodes`, `runtime_forms`, `runtime_report_attempts`.
- **Old runtime module:** every task file ends with `from ...root.a103 import runtime as _live_original_runtime` and calls its helpers through that alias (and imports a long list of names from it, most unused).
- **Old shared prompt pieces:** `task_presentation.py` / `task_presentation_policy.py` import from `root.a103.gene_context_evidence_prompt`, `root.a103.decision_context`, `root.a103.execution_prompt`, `root.a103.native_profile_presentation`, `root.a103.library.hpc_prompt`, `root.a103.library.monitor_prompt`.
- **Other old shared root modules:** `root.a103.communication`, `root.a103.domain`, `root.a103.episode_bindings`, `root.a103.composition_information` (via `source_contracts.py`), `root.a103.library.action_contracts`, `root.a103.library.private_policy_call`, `root.a103.library.report_fact_assembly`, `root.a103.episode_work_report`, `root.a103.episode_source_failure`, `root.a103.providers`, `root.a103.episode_return_records`, `root.a103.delivery_counterpart`, `root.a103.episode_contract_information`.
