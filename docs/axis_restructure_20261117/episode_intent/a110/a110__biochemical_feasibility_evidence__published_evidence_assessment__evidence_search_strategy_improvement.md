## What this episode is for (its own words)

`goal.py` instructions = `_ROLE_INSTRUCTIONS['literature_strategy']` + the A110 paragraph:

> Investigate which search approach is productive. Keep the information objective and evidence context separate from a literal provider query. Revise terms or source choices in light of actual search/read outcomes; a search child can investigate which returned sources deserve examination.
> Investigate the reported reaction and resource evidence for this source. Preserve source identity, exact conditions, units, uncertainty and byte anchors. Keep reported product ratios, resource budgets and named predictions distinct. Unknown replication, calibration, alternative reactions and resource completeness remain unresolved. A search or read earns no scientific credit by itself.

`contracts.py` docstring: the binding supplies operands, ordinary operations, source custody and the commissioned task's private yield binding; the workflow owns decisions, reasoning commits, commissioning and report updates; "a reading selection is information for an investigation, never a script that this binding executes."

## Task and instructions

The task is `SourceInvestigationTask` (task.py with task_state, task_decision, task_suspension, task_action, task_report_delivery, internal_summary.SourceDecisionSummary), rendered with `task_presentation.present_source_context`. Instructions (`task_instructions.instructions`): the default scientific INSTRUCTIONS + this episode's goal instructions (appended, not replacing) + tool knowledge + launch instruction library when present + a fixed paragraph for `pending_child_delivery` (complete the finished child's typed return by `redeliver_report` with a corrected form, using only saved child facts, preserving `current_report_update`). With the decision-exchange protocol, the "fresh provider conversation" history guidance is replaced by: use `request_context` exchanges for own attempt metadata; read exact received outcomes through `episode.history` (view=records, selected decision_indices), which creates its own observation and does not credit the historical work again.

Permitted common actions: `tool`, `child`, `redeliver_report`. No reasoning action (`configuration.reasoning_action_schema` -> None).

Validation: JSON-serialisable without NaN, schema-valid, every `*_refs` entry in scope. `prepare_assignment` requires a non-empty string operation_key.

## How its credit is counted

`credit_kind` = `scientific`; `credit_view(context, receiver_selection)` = `services.scientific_credit(context, receiver_selection)`; `credit_projector` = None. The goal text states "A search or read earns no scientific credit by itself." Nothing in the folder bounds, clamps or rescales credit. A returned invalid/failed tool outcome still enters the iterator: argument errors return an `invalid` outcome with feedback (`execute`), and an execution failure is saved as a `failed` outcome with credit and controller value (`task_state.record_execution_failure`).

## What it reports to its parent

- `fact_sources(role)` = `literature_component_binding.fact_sources()` (reaction rate fact sources).
- `facts(context, completion_snapshot)` = `_rate_facts(context, committed_record_refs)`: for each population route, the reaction cells of received `literature_reaction_record_v2/v3` source rows of the route's provider whose version is the route adapter's record version, limited to the components requested in the assignment (route default otherwise); plus native observations (`reaction_native_observations.NAMESPACE`) from v3 records at the requested `POSITIONS_FIELD` positions (default `['all']`). Current sheet refs are added to the references first. A source row of another version raises `literature_reaction_projection_version_mismatch`.
- `current_report_facts` = {}.
- `validate_report`: re-validates the assignment, validates the form against the original schema with reference resolution, then `validate_received_report` (rows only from received/known sheets of this receiver, only requested components / native positions, empty-return family check when no companion family delivered).
- Finish (`task_report_delivery.finish`): with a report contract, the saved form or a form built from facts plus interpretations.

## Where it differs from similar episodes

- Against the A101 counterpart (`a101/sequence_homology_evidence/.../same role`): the A101 goal leads with sequence/homolog identification text before the role instruction, while A110 appends the reaction/resource paragraph after it. A110 has files A101 lacks (`contracts.py`, `initial_information.py`, `numerical_report_facts.py`, `parent_context.py`, `reaction_records.py`) and its configuration accepts `reference_parent_sources` and a `contract_information_profile` (A101 hard-sets both to None). A110's decision context adds `literature_experimental_work`, owned population sources, the latest failed population attempt and component-axis source origin/access; A101's history meaning reads "source discovery alone is not A101 evidence". A110's child receiver has no `is_job_source` branch and no native-timing block. A110 report facts are reaction cells and native observations (A101 has its own scientific-record files instead, not read here).
- Within this A110 literature chain the four episodes share most files byte-for-byte; differences are only role, assignment shape, child set and the tool boundary (acquisition tools in strategy and relevance assessment; page-bound access-only in source examination and passage extraction).
