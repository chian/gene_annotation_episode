## What this episode is for

It monitors one assigned execution target and returns the useful progress information it actually observed. In its own words (`goal.py`):

> Investigate which further exposed progress information is useful for the assigned target. Use actual status, measured quantities, committed references and source-bound logs. Liveness establishes process presence only; elapsed time alone establishes neither productive work nor a stall. Unknown information stays unknown. Earlier outcomes and your admitted child forms inform later decisions. You may explicitly commission an ordinary monitor for one exposed direct dependency; no descendant traversal, fanout, cadence or depth is prescribed. Return the original parent's typed form at your closure even while the target remains active. Do not report private reasoning, intentions or unrestricted findings. Recorded facts use saved delivered observations; closure does not poll or compose another report with a model.

followed by either "The monitor's information-credit projector and bound yield rule govern continuation." (private yield binding) or "The caller's monitoring projector and configured controller own credit and continuation.", and "Repeated observation identities and read timestamps alone earn no new information."

Planning context: objective (the request goal), target_handle, requested_fields, unresolved question "Which exposed progress information would improve the original requested report?", progress definition "Actual received information under the caller-bound monitoring projector; repeated identities and timestamps alone earn no credit.", yield settings.

## Task and instructions

- Role `monitor`, entry role `monitor`; commissioned by `biochemical_feasibility_evidence/hpc_work_planning` (and by itself, recursively).
- Permitted common actions: `tool`, `child`, `wait`, `redeliver_report`.
- `task_instructions.py` is this episode's own instruction text (not the default runtime text): goal, then
  - ACTION_BOUNDARY: "Do not emit a stop action or invent a turn budget, approval review, quality gate, experiment, term or observation."
  - CREDIT_COMPONENT_GUIDANCE: current_evidence_vector holds projector components from the same projection as current_credit; read with credit_binding; a progress proxy, not biological truth.
  - RESOURCE_ESTIMATE_GUIDANCE: resource_tool_estimates describe expected time/resources; a timing experiment earns monitoring credit for timing information learned; missing history means unknown duration; job elapsed time vs own action duration are distinct.
  - REPORT_GUIDANCE: a commissioned child returns only the parent's typed form; report_update is the interpretation before the next action; fact vs interpretive fields; redeliver_report repairs representation only; do not recommission to fix representation.
  - HISTORY_GUIDANCE (or EXCHANGE_HISTORY_GUIDANCE under `decision_exchange_v1`), HOST_EXECUTION_GUIDANCE, tool knowledge, launch library, REPAIR_GUIDANCE (pending_child_delivery), WAIT_GUIDANCE (pending_child_ handles, event returned, after_cursor 0; waiting earns no scientific credit) and NATIVE_EVENT_GUIDANCE (native_event_targets are registration metadata; state_changed means exit receipt committed, not result readiness) when wait is permitted.

## What it reads from its parent's assignment

`monitor_assignment_v1`: `target_handle` (must be in scope as `execution_handle`), `requested_fields` (subset of execution_status, measurements, log_windows, committed_record_refs, dependencies, result_available), `known_progress_refs` (each must be a progress snapshot of the same target), `permitted_committed_record_types` (record schema names).

## Children

One kind: another `execution_progress_assessment` (role `monitor`), allowed only when the target exposes direct dependencies.
- Sends (`to_child_execution_progress_assessment.py`): a monitor assignment whose target_handle is one of the parent target's exposed direct dependencies and whose permitted record types are a subset of the parent's. No descendant traversal, fan-out, cadence or depth is prescribed.
- Takes back (`from_child_execution_progress_assessment.py`): the child's typed form, validated against its schema; every `episode_progress` reference in it is read and recorded as received progress for this episode under the operation key with a digest of form, schema and scope.

## Decision state shown to the model

`decision_state.py`: goal, scope, working state, visible refs, current_credit, current_evidence_vector, investigation_progress (when receipt projection is on), credit_binding, time_accounting, pending_work, last_local_outcome, feedback, visual_evidence, report_deliveries, controller, controller_binding, tools, tool_knowledge, job_episode_options, available_report_facts, requested purpose/form, current report update/basis, monitoring_information_credit/binding, plus the binding's context (`internal_summary.py`): monitor_assignment, monitor_target_description, monitor_direct_dependencies, monitor_received_progress_refs, monitor_information_meaning ("Exposed direct relationships and already delivered observations. Empty measurements/log windows do not assert absence or a stall."), monitor_goal. `decision_inputs.py` adds resource context, launch library, child options, initial binding context, completed action reports, pending work, execution expectations for `monitor`, resource estimates, native expectations, waiting_support. Rendered by `render_monitor_prompt`.

## Tools

- `progress.observe` — observe selected requested fields of the assigned target (cannot expand the assignment's fields), optionally a `native_operation` declared by the target's selected observation schema; retains the observation identity when facts are unchanged; never traverses dependents. Committed records returned are filtered to permitted types.
- `progress.read` — read an already received progress observation.
- `progress.log` — read one retained log window of a received observation by exact byte range through `source.read`, checking source/artifact custody; empty windows return empty text.
Invalid arguments/references return an `invalid` outcome that still enters the iterator.

## Credit

Kind `monitoring`. `credit_view` is the caller-bound role credit (`services.bound_role_credit`). `information_credit` selects `ProgressInformationCredit(progress_reader, information_unit)`: newly informative received snapshots × information_unit; repeated identities and timestamps earn nothing. Not bounded.

## Continuation

Private yield binding with settings `{kind: information_accumulation, cutoff, uncertainty_alpha}` and `information_unit`. Estimator `monitor_information_accumulation_v1`: non-negative per-action credit (a decrease raises), forecast of the next action's information credit, stop when the predicted upper gain is at or below the cutoff; parameters only `uncertainty_alpha`. New estimator: **accumulation**.

## Report to parent

Facts: monitoring_progress_refs, monitoring_target_handle, monitoring_execution_state (pending/executing/returned/admitted or null), monitoring_result_available, monitoring_observed_at_unix_seconds (from the original UTC observation time), monitoring_committed_record_refs (permitted types only), monitoring_dependency_handles (latest observation; no descendants). `required_return_sources` is `('monitoring_progress_refs',)` when the parent is `biochemical_feasibility_evidence` and an annotation task is required. Report validation: recorded facts must match; any other record reference in the form must be a permitted committed record actually received.

## Differences from siblings

- The only one of these four that can commission a child (itself), wait, and redeliver reports.
- Own instruction text (task_instructions.py) instead of the default runtime instructions composed with a specialist.
- Credit kind `monitoring` (information accumulation) vs `operational` in the three execution episodes; no resources, no configuration of units or yield profiles per request class.
- Its task loop omits the reasoning-commit admission, job_child storage errors, contract-error detail branches and literature numerical contract freezing that the execution episodes' copies keep.
