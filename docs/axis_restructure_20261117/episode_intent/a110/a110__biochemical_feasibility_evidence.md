## Purpose (own words)

This is the A110 scientific investigation of biochemical-feasibility evidence: the axis head and also its own recursive child. `goal.scientific_guidance()` is `INSTRUCTIONS['A110']` (from the old shared `component_axis_workflow`) plus:

> "Scientific descendants remain A110. Use available shared operations for specific parent information needs or useful received findings. The immediate parent chooses within its own options or relays the need upward; publication does not commission work or promise a reply. Preserve named scientific components separately from controller progress."

For an instruction-version evidence axis it continues: "Determine what the supplied target does within the parent's assigned question, scope and constraints. Start with the supplied sequence, selected file contents or snippets, preserving their boundaries, completeness and known context. No initial candidate annotation or publicly searchable name is required. Possible functions can emerge from the evidence and be compared or revised. Apply the complete selected investigation instructions and thought-pattern guidance on every decision. ... Selected instructions describe how to investigate; they are not evidence about this target. Preserve the measured subject, conditions, controls, native measurements, uncertainty and limits of inference when interpreting evidence. Missing information remains unknown." Then the action menu (tool, reasoning commit, scoped child with its own typed return form, wait), "Keep the assigned evidence axis, thought pattern and selected tools for this episode. process.revise prepares a different thought pattern and/or tool selection for a new child; it does not change this episode or start that child ... Children own their iterative choices. The configured controller owns continuation. Waiting and unchanged observations do not manufacture progress."

For an older support-metadata axis entry it uses a separate text: investigate the parent's scientific support problem; `annotation_support_routes` describes the separately bound annotation policy's kind dispatch; "Metadata itself earns no credit and never replaces or filters the actual projectors, annotation formula or continuation rule"; request the `biochemical_feasibility_evidence_results` source in child forms for steering.

## Continuation

Yield estimator: accumulation. `continuation_task` = `A110:<context.a110_task.name>` or `A110:<projector kind>`. The configured `yield_bindings[task]` must be {kind, cutoff, parameters {uncertainty_alpha}, credit_definition}; the credit_definition digest must equal the projector record and the projector's `yield_method` must equal the kind; accumulation → `YieldController(epoch, initial_credit, cutoff, YieldParameters(uncertainty_alpha))`. Configuration validates bounded_quality and completion declarations too, but `yield_controller` raises `scientific_yield_method_unavailable` for them. With no yield bindings it returns None (old recorded controller), which the new runner must not carry over as a fallback.
