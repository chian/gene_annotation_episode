## What this episode is for (its own words)

`goal.py` instructions = `_ROLE_INSTRUCTIONS['literature_search']` + the A110 paragraph:

> Investigate which returned sources merit examination for the assigned question. Search results are source-discovery information. Examine original sources and their conditions before asserting biological evidence. A page child can investigate where and how to examine a selected source.
> Investigate the reported reaction and resource evidence for this source. Preserve source identity, exact conditions, units, uncertainty and byte anchors. Keep reported product ratios, resource budgets and named predictions distinct. Unknown replication, calibration, alternative reactions and resource completeness remain unresolved. A search or read earns no scientific credit by itself.

## Task and instructions

Same `SourceInvestigationTask` composition and instruction composer as the parent strategy episode (default INSTRUCTIONS + this goal + tool knowledge + launch library + pending_child_delivery repair paragraph; exchange-protocol history guidance). Permitted common actions: `tool`, `child`, `redeliver_report`. No reasoning action.

- `version`: const `search_assignment_v1`

## Decision state and what it shows the model

Own decision context (`internal_summary.LiteratureSummary.decision_context`, merged by the old snapshot through `specialist.decision_context`):

- `literature_assignment`: the validated assignment.
- `literature_source_custody`: for each source of the assignment (`[page.source_ref]` when the assignment carries a page, else `assignment['source_refs']`) its `version`, `artifact_ref`, `text_ref`, `stdout_ref`, `stderr_ref`, `parent_source_refs`. This assignment has no page and no `source_refs` field (it carries `search_result_refs`), so the custody list is empty.
- `own_literature_outcomes`: `services.own_outcomes(episode_id, tools=_ACQUISITION_TOOLS+_READ_TOOLS, offset=0, limit=outcome_page_size)` (page size 8 by default).
- `literature_history_meaning`: "Own outcome metadata only. Inspect original source records and exact prior operations before interpreting them."
- `literature_experimental_work`: `{version: literature_experimental_task_v1, aspect: source_experimental_evidence}`; this marks the context as a literature experimental TASK so `task_presentation.present_source_context` renders it with `render_literature_experimental_prompt` instead of raw JSON.
- `literature_owned_population_sources`: own successful population outputs classified from operation metadata only (completed, sheet received, operation_ref equals this episode's operation identity, provider/version match); no sheet cells are opened.
- `literature_selected_population_attempt`: the latest own tool action if it ended `invalid`/`failed`/`error` (tool, version, population_version, status), so the model sees its failed population attempt.
- `component_axis_source_origin` and `component_axis_source_access` when available.

The old generic snapshot (`SourceDecisionSummary._decision_snapshot`, carried in this folder) also showed: goal, scope, working state, visible record refs, current credit and evidence vector, investigation progress, credit binding, time accounting, pending work, last local outcome and feedback, visual evidence (last completed `image.view`), report deliveries, controller state and binding, tools, tool knowledge, job episode options, available report facts, requested report purpose/form, current report update and basis, report lifecycle note, child reports, annotation context. `task_decision.call` added resource context, shared information, launch instruction library, child options, initial binding context, completed action reports, pending work, execution expectations, resource estimates, contract information profile. Initial information: `resource_information(catalog.readers(<binding_path>, context))`; result readers: `catalog.configured/received(<binding_path>)`.

## How its credit is counted

`credit_kind` = `scientific`; `credit_view(context, receiver_selection)` = `services.scientific_credit(context, receiver_selection)`; `credit_projector` = None. The goal text states "A search or read earns no scientific credit by itself." Nothing in the folder bounds, clamps or rescales credit. A returned invalid/failed tool outcome still enters the iterator: argument errors return an `invalid` outcome with feedback (`execute`), and an execution failure is saved as a `failed` outcome with credit and controller value (`task_state.record_execution_failure`).

## Continuation

`yield_estimator.py`: `continuation_task` -> None and `yield_controller` -> None. The episode declares no private yield estimator or settings; under the old runner the generic controller (`controller_binding`, `_category_yield_parameters`, `yield_table`) governed continuation. The port must pick one of the three `yield_control/` estimators for it; the old files do not name one. `waiting.supports_wait` = False (no wait action).

## What it reports to its parent

- `fact_sources(role)` = `literature_component_binding.fact_sources()` (reaction rate fact sources).
- `facts(context, completion_snapshot)` = `_rate_facts(context, committed_record_refs)`: for each population route, the reaction cells of received `literature_reaction_record_v2/v3` source rows of the route's provider whose version is the route adapter's record version, limited to the components requested in the assignment (route default otherwise); plus native observations (`reaction_native_observations.NAMESPACE`) from v3 records at the requested `POSITIONS_FIELD` positions (default `['all']`). Current sheet refs are added to the references first. A source row of another version raises `literature_reaction_projection_version_mismatch`.
- `current_report_facts` = {}.
- `validate_report`: re-validates the assignment, validates the form against the original schema with reference resolution, then `validate_received_report` (rows only from received/known sheets of this receiver, only requested components / native positions, empty-return family check when no companion family delivered).
- Finish (`task_report_delivery.finish`): with a report contract, the saved form or a form built from facts plus interpretations.

## Where it differs from similar episodes

- Against the A101 counterpart (`a101/sequence_homology_evidence/.../same role`): the A101 goal leads with sequence/homolog identification text before the role instruction, while A110 appends the reaction/resource paragraph after it. A110 has files A101 lacks (`contracts.py`, `initial_information.py`, `numerical_report_facts.py`, `parent_context.py`, `reaction_records.py`) and its configuration accepts `reference_parent_sources` and a `contract_information_profile` (A101 hard-sets both to None). A110's decision context adds `literature_experimental_work`, owned population sources, the latest failed population attempt and component-axis source origin/access; A101's history meaning reads "source discovery alone is not A101 evidence". A110's child receiver has no `is_job_source` branch and no native-timing block. A110 report facts are reaction cells and native observations (A101 has its own scientific-record files instead, not read here).
- Within this A110 literature chain the four episodes share most files byte-for-byte; differences are only role, assignment shape, child set and the tool boundary (acquisition tools in strategy and relevance assessment; page-bound access-only in source examination and passage extraction).
