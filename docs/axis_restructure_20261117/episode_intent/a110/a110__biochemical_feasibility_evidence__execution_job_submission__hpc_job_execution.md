## Purpose (own words)

The A110 HPC resource executor (role `launch_hpc`): run the one concrete job assigned by the launch parent on a configured `pbs_ssh` resource by choosing and running shell commands, until the requested endpoint is validated. Its instructions come from its own `terminal_execution.TerminalExecutionBehavior.instructions`:

> "You are the execution agent for the actual job and resource assigned below. Use exec_command to write and run the shell code needed for that job. Choose scripts, environment preparation, software invocation and recovery from the actual resource instructions and observed results. No sequence of setup or job-stage operations is prescribed. Preserve the caller's scientific inputs, desired outputs and acceptance criteria. Historical inventory is context, not proof of present usability. Each command is one ordinary episode action: its actual result and earned credit enter the iterator, including failure or zero progress. Host bookkeeping records command versions and actual native job identities; do not maintain a parallel receipt ledger. If a submission outcome is uncertain, investigate that original submission rather than create a duplicate. Use the provided resource-specific instructions, account, storage and existing authentication route. workdir and env apply to the selected command only. target=resource runs on the assigned resource; target=coordinator runs in the local run directory for supplied-input and transport work. ... For coordinator-side transfers, execution_resource.ssh_argv, when present, is the exact configured transport prefix ... The episode iterator decides continuation from credit; add no stopping budget."

followed by "Resource instructions supplied from the frozen library:" and the launch-library sections for the assigned resource. `goal.py` delegates to that text; `replaces_default_instructions = True`.

## Task and instructions

`task_instructions.instructions`: the terminal text replaces the default; tool knowledge; launch library; pending-child redelivery paragraph; decision-exchange history replacement. It has no reasoning-commit or wait paragraphs (tool-only leaf). `task.py`/`task_decision.py`: shared-shape loop; decision state via `native_decision_snapshot`; wait through `perform_selected_native_wait`; execution expectations captured for its own grain; no waiting support.

## What it reads from its parent's assignment

`from_parent.assignment_schema(role)`: `anyOf` the concrete request schemas of configured resources of kind hpc (practical `ASSIGNMENT_SCHEMA` with `resource_id`/`resource_kind` consts and generic or FBA `requested_job`; `not {}` when none). When the parent is `launch` under an `hpc` ancestor, `child_assignment_schema` is an `enum` of the parent's frozen permitted hpc requests (`frozen_hpc_launch_request_missing` otherwise). `prepare_assignment`: the request is validated, its kind must match `launch_hpc`, the parent must be `launch` (`resource_child_role_owned_by_launch`), and FBA inputs / immutable input versions are checked against the parent's launch assignment. Compact FBA assignments are not accepted here. At initialisation (`science._check_parent_inputs`) the recorded parent launch request is re-read and inputs checked again.

## Children it may commission

None (`child_roles` and `allowed_children` are empty; no entry roles).

## Decision state and what the model sees

`terminal_execution.decision_context`: `execution_assignment`, `execution_resource` (resource kind, workspace, kind/policy/account/ssh_argv/python_executable/scheduler, inventory snapshot), `coordinator_workspace`, `execution_progress` (practical credit view), `execution_completion` (completion proof). `initial_decision_context`: `execution_resource_information`. The selected FBA task is added only for compact assignments. Plus the common decision state (`native_decision_snapshot`).

## Tools offered

Permitted actions: `tool` only. Catalog from `library.execution_operation_information.operation_catalog('hpc')` (the `exec_command`-style operations), validated per action by the resource's `TerminalExecution`; each executed command is recorded in the practical state (intent → finish), finalised by `finalize_scientific_command`, assessed against the assignment's validations, and published as a practical receipt record. Invalid arguments return an `invalid` outcome.

## Credit

`credit_kind` = `operational`. A closed episode returns its recorded closed view (same authentication as launch); otherwise credit = the assigned resource's practical-state credit view (validated endpoint predicates). Unbounded.

## Continuation

Yield estimator: accumulation with a completion-aware estimator. Requires `require_private_yield`; profile `task_yield_profiles['launch_hpc:' + request class]` → `YieldController(epoch, initial_credit, cutoff, YieldParameters(...), estimate_with_context=PracticalYieldEstimator(verify_completion))`. `verify_completion` checks a `practical_completion_v1` proof against the practical state (or a recorded closed verdict).

## Report to parent

`to_parent.facts`: terminal facts (`practical_completed`, `practical_receipt_digests`, `practical_receipt_refs`), `execution_handoff_refs` (handoffs from received records plus its own returnable practical receipts for this assignment), execution result/file facts, `execution_result_origin`, `execution_completed` (= practical_completed), FBA fact sources (empty when configured), closed credit snapshot. No required return sources. `validate_report`: FBA returns validated, references resolve, fact fields equal recorded facts.

## Differences from similar episodes

- Versus its sibling `local_job_execution` (otherwise identical copies): hpc restricts the child assignment to the launch parent's frozen hpc requests when under an `hpc` ancestor; it rejects compact FBA assignments (local accepts them from `launch`); its decision context shows the selected FBA task only for compact assignments (local also for a single ordinary FBA request); its yield profile key is `launch_hpc:<class>`. Configuration rejects `native_flux_balance` on non-local resources (`native_flux_balance_resource_execution_binding_unfinished`), so FBA runs on the local leaf.
- Versus its parent launch: tool-only, no children, credit from practical state rather than handoff count, accumulation rather than bounded yield.
