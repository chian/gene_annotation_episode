## What this episode is for

It is the execution agent for one actual job on one configured local resource (kind `local`), including native flux-balance (FBA) jobs, which are only permitted on local resources. In its own words (`terminal_execution.py`, identical text to hpc_job_execution):

> You are the execution agent for the actual job and resource assigned below. Use exec_command to write and run the shell code needed for that job. Choose scripts, environment preparation, software invocation and recovery from the actual resource instructions and observed results. No sequence of setup or job-stage operations is prescribed. Preserve the caller's scientific inputs, desired outputs and acceptance criteria. Historical inventory is context, not proof of present usability. Each command is one ordinary episode action: its actual result and earned credit enter the iterator, including failure or zero progress. Host bookkeeping records command versions and actual native job identities; do not maintain a parallel receipt ledger. If a submission outcome is uncertain, investigate that original submission rather than create a duplicate. Use the provided resource-specific instructions, account, storage and existing authentication route. workdir and env apply to the selected command only. target=resource runs on the assigned resource; target=coordinator runs in the local run directory for supplied-input and transport work. Both are ordinary journaled actions; resource computation belongs on its actual allocation. For coordinator-side transfers, execution_resource.ssh_argv, when present, is the exact configured transport prefix. Append the remote shell command as its final argument and preserve stdin. The supplied configuration gives the existing connection details. target=resource uses that transport directly. The episode iterator decides continuation from credit; add no stopping budget.

Followed, when configured, by "Resource instructions supplied from the frozen library:" and the sections selected for this resource.

The goal is a validated completion of the assignment's requested endpoint (`usable_handoff` or `completed_job_outputs`) with recorded command receipts.

## Task and instructions

- Role `launch_local`; commissioned by `biochemical_feasibility_evidence/hpc_work_planning/execution_job_submission` (from its `launch` role). Entry roles: none.
- `replaces_default_instructions=True`; `task_instructions.py` appends tool knowledge, launch instruction library text, the pending-child redelivery repair paragraph and the exchange-protocol history guidance.
- Only common action: `tool`.

## What it reads from its parent's assignment

Either a concrete practical assignment for one configured local resource (`resource_id` const, `resource_kind` = `local`, `requested_job` generic or FBA alternatives, endpoint, workspace, initial_context, constraints) or, on a local resource with native flux balance, a compact resource assignment (`flux_balance_request_binding.resource_assignment_schema`). For a compact assignment the parent must be `launch`; the episode reads the parent's request binding, takes the row whose `selection` equals this assignment, validates its FBA inputs and input versions, and keeps the compact selection. Otherwise it requires parent `launch`, a matching resource kind and valid launch `immutable_input_versions`. There is no frozen-hpc-request enum (`child_assignment_schema` falls through to `assignment_schema`). For `launch_local` the FBA input check may reuse the frozen received FBA inputs when the assignment matches.

## Children

None.

## Decision state shown to the model

Same model inputs as hpc_job_execution (`native_decision_snapshot`: goal, scope, working state, visible refs, credit, credit binding, time accounting, pending work, last outcome, feedback, visual evidence, deliveries, controller, tools, tool knowledge, report facts, requested form, current report update) plus the terminal behaviour's execution_assignment, execution_resource, coordinator_workspace, execution_progress, execution_completion. Compact FBA assignments instead show practical_assignment, practical_progress (credit, satisfied_keys) and practical_completed. For non-compact FBA assignments it builds `{resource_id: assignment}` and adds `selected_execution_task` (scientific question, selected tool info, requests with FBA job view and resource) — hpc does not do this for non-compact assignments.

## Tools

`operation_catalog('local')` command execution (target resource/coordinator, workdir, env), with receipts and validations as in hpc_job_execution; FBA tool contracts are merged into the resource contracts when configured (unless direct FBA is registered). Compact FBA outcomes are reduced to `practical_outcome_view` and lose `operation_ref`.

## Credit

Kind `operational`. Live: the practical state's credit view (old shared `practical_execution_state`). After closure: only the authenticated closed credit view. Not bounded or rescaled.

## Continuation

Requires `require_private_yield=True`. Profile `task_yield_profiles['launch_local:<request class>']` (`practical_local[_native_flux_balance…]_{handoff|outputs}` or `compact_<version>`), controller with that cutoff/parameters and the endpoint estimator verifying the completion proof. For compact assignments `practical_estimator` uses the same endpoint estimator directly. New estimator: **completion with a target**.

## Report to parent

Same facts as hpc_job_execution: practical_completed/receipt_digests/receipt_refs, execution_handoff_refs, execution_result_refs, execution_file_source_refs, execution_file_capture_outcomes, execution_result_origin, execution_completed, FBA fact sources (empty lists when FBA configured), closed credit snapshot. FBA returns validate the received report first when configured. `required_return_sources` returns `()`.

## Differences from siblings

- vs hpc_job_execution: role and yield prefix (`launch_local`), compact FBA assignment admission in `prepare_assignment`, no frozen hpc enum, `internal_summary` line 58 builds the request map. All other 24 files differ only in their own path strings.
- vs execution_result_acquisition: this episode runs commands; result acquisition reads result windows with byte-coverage credit.
