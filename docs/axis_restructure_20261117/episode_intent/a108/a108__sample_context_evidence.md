## What this episode is for (its goal, in its own words)

`goal.py` `ScientificGoal.instructions`. There are two texts, chosen by the selected evidence-axis library entry.

- **Instruction entry** (`entry_version == evidence_axis_instructions.VERSION`). The text replaces the default instructions completely, because `replaces_default_instructions` is set when every evidence_axis header is an instruction entry. It begins: "Determine what the supplied target does within the parent's assigned question, scope and constraints. Start with the supplied sequence, selected file contents or snippets, preserving their boundaries, completeness and known context. No initial candidate annotation or publicly searchable name is required. Possible functions can emerge from the evidence and be compared or revised. Apply the complete selected investigation instructions and thought-pattern guidance on every decision. Use actual outcomes and received child results to choose and revise your approach. Selected instructions describe how to investigate; they are not evidence about this target. Preserve the measured subject, conditions, controls, native measurements, uncertainty and limits of inference when interpreting evidence. Missing information remains unknown." It continues with the action rules:
  - choose a tool, commit an interpretation through reason, commission a scoped child with its own typed return form, or wait for selected pending work;
  - preserve the parent's exact requested result meanings;
  - keep inherited information distinct from new findings;
  - keep the assigned axis, thought pattern and tools; `process.revise` only prepares a child alternative;
  - the controller owns continuation, and waiting or unchanged observations do not manufacture progress.
- **Evidence-axis entry**. The text is appended to the default instructions: "Investigate the parent's assigned scientific problem iteratively in the shared Episode loop. The selected scientific support proposition and operands define the support problem; the thought pattern supplies alternatives and outcome-sensitive guidance; the selected real tools supply their exact callable contracts..." It adds:
  - library sources are instruction provenance, not evidence;
  - `annotation_support_routes` describes the separately bound annotation policy;
  - metadata earns no credit and never adds form fields or scoring axes;
  - request `sample_context_evidence_results` in child forms when process relationships and closed credit/yield are needed.

In short, the head runs one A108 (organism and sample context) investigation for a target. It works from a parent-selected evidence axis A108, a thought pattern P*, and a selected set of real tools. It can recurse into itself and commission a published-literature assessment.

## Task and instructions

- `task.py` / `task_decision.py` / `task_state.py` hold the old decision source `ScientificTask(ScientificTaskState, ScientificTaskDecision, ScientificWaiting)`. Nearly all of it is old-runner machinery: replay, completion slots, journal rows, decision exchanges and contract-information freezing. Its own intent:
  - A reason selection with an entirely empty commit is rejected (`empty_reasoning_commit`). The exceptions are `evidence_processing.kind == 'no_applicable_evidence'` and a binding whose `reasoning_has_task_content` accepts the selection.
  - A reason action runs the binding's `execute_reasoning` when present. Otherwise it runs `store.commit_reasoning(...)`, with `account_invocation` when interpretation_accounts are present.
  - Wait selections run `perform_selected_wait`. They earn `last_observed_credit`, meaning no new credit.
  - Tool or reason outcomes that are invalid or failed still enter the iterator with their credit from `source_credit_view`.
  - A model-call failure is recorded and the episode ends with `SourceEnd('source_failed')`.
  - A `pending_child_delivery` repair must keep `report_update` unchanged.
  - `shared.read_information` outcomes retain shared grading results.
  - Finish: with a report contract, the result is `form_with_facts(report_values, schema, facts)`. Without one, it is `{credit, pending_handles, **current_report_facts}`.
  - Before every new model call and execution, `validate_execution_context` checks that the filled request still matches this binding.
- `task_instructions.py` builds the instructions in this order:
  - the base `runtime_prompt.INSTRUCTIONS`, or the goal text above when `replaces_default_instructions`;
  - `REASONING_COMMIT_REQUIREMENT` when reason is permitted;
  - tool-knowledge text and launch-instruction text;
  - the pending_child_delivery / `redeliver_report` repair text;
  - the wait text ("A pending_child_ handle names your original in-process child ... select wait with that handle, event returned, after_cursor 0 and reconsider_at null ... Waiting only reports readiness and earns no scientific credit");
  - the native_event_targets text ("A target is registration metadata, not proof that submission succeeded ... No event probability, gain or scientific credit follows from registration or passing time alone");
  - the decision-exchange history replacement.

## What it reads from its parent's assignment (`from_parent.py`, `scientific_contracts.py`)

`_ASSIGNMENT` (required `selection, evidence_refs, constraints, context`):
- `selection` (`SELECTION_VERSION`):
  - `evidence_axis`: option ref with `slot evidence_axis`, `option_id` fixed to `A108`, `library_id` = this head's library, and `entry_sha256`;
  - `thought_pattern`: option ref with `option_id P<n>`;
  - `child_tool_info[]`: `{name, resources ∈ api/local/hpc}`, materialized to `{name, resources, description, instructions}`.

  The axis entry must be an instruction entry or an evidence-axis entry; otherwise `scientific_support_metadata_required`.
- `proposed_annotation_ref`: the proposed annotation this task evaluates. It must be in scope as a `hypothesis` and received by the parent. It is inherited from the parent's own task and may not differ. It is required when `annotation_task_required()`.
- `evidence_refs[]`: each must match the reference pattern and be in scope.
- `constraints` (object). `context.evidence_task` = `{version evidence_axis_task_v1, kind whole_axis_findings, evidence_axis A108, credit_unit > 0}`. The model is told: "Use the finding unit in the explicitly configured credit definition for this exact task; do not select or change its cutoff."
- `revision_origin` (optional) = `{parent_invocation_ref, preparation_operation_ref}`. It is authenticated against the parent's own `process.revise` preparation: the same invocation, the parent selection digest, and the identical proposed selection.

The filled request carries `message.sample_context_evidence` = `filled_sample_context_evidence_v1 {selection, assignment_sha256, invocation_sha256, mechanics_binding: as_record()}` together with `episode_assignment`, `scope` and `scientific_invocation_ref`. All of them are checked on every context.

## Tools it offers (`scientific_operations.py`, `scientific_contracts.py`, `execution_planning.py`, `library_operations.py`)

- Common tools (`_COMMON_TOOLS`): process.search/entry/sources/tools, knowledge.search/entry/read, episode.history/credit/annotation_score/monitoring_information/estimate_wait, and shared.request_information/publish_information/resolve_information_need/read_information/list_information.
- The selection's own resolved direct tools. A selected tool may not reuse a common name or `process.revise`.
- `process.revise` (`{thought_pattern, child_tool_info}`) prepares a different thought pattern and/or tool set for a new child on the same axis. It returns `sample_context_evidence_child_selection_v1` and a `revision_origin`, changes nothing now, and starts no child.
- `process.execution` reads the execution recipe, resource context, timing history, known timing profiles and HPC commissions. It is operational only, with scientific_credit 0. The old code has `profiles maxItems 8` and `history(limit=64)`; those are count limits that the current rules forbid.
- Byte operands of material.* and source.* tools are authenticated. `source.locate` is limited to received refs.
- Common actions: `tool, reason, child, wait, redeliver_report`.

## How its credit is counted (`credit.py`)

- Credit kind `scientific`. The projector is `ScientificFindingProgress(FindingProgressPolicy(credit_unit))`, built from `assignment.context.evidence_task` (`whole_axis_findings`, A108). Credit counts retained A108 findings in finding units. The projector is outside this tree and was not read. There is no clamp in this file.
- When yield bindings are configured, a task without `proposed_annotation_ref` is refused. When the axis entry is neither kind, there is no projector.
- `credit_view` runs the projector with the local commission (goal, scope, purpose, schema, initial_report, proposed_annotation_ref) and the receipt arguments.

## Continuation (`yield_estimator.py`, `configuration.py`)

- Task key `A108:whole_axis_findings`.
- `yield_bindings[task] = {kind, cutoff, parameters{uncertainty_alpha}, credit_definition}`. The digest of `credit_definition` must equal the projector's `as_record()`, and `kind` must equal the projector's `yield_method`. The kinds map as follows:
  - `accumulation` → accumulation controller;
  - `bounded_quality` → bounded controller with `projector.native_score_maximum`;
  - `completion` → completion controller.

  These map onto the three current `yield_control` estimators (`AccumulationYieldEstimator`, `BoundedQualityYieldEstimator`, `CompletionYieldEstimator`).
- With no yield bindings, the old recorded controller contract is used. The new runner has no equivalent of that contract.

## What it reports to its parent (`to_parent.py`, `report_snapshot.py`)

- Fact source `sample_context_evidence_results` (from `report_sources(library, tool_library)`). Its value merges this episode's own process result, projected through `project_process_result`, with the received children's projected results.
- Required return sources: `sample_context_evidence_results` and `committed_record_refs` when commissioned by the root under the annotation task, otherwise `committed_record_refs`.
- Report validation: each `sample_context_evidence_results` field must validate and must equal this episode's frozen closing source (`runtime_forms.facts`).
- Completion snapshot: initial_credit, credit, controller_credit, episode_yield, parent_invocation_ref.

## Differences from the sibling/similar episodes

- Its child `published_evidence_assessment` (a `LiteratureEpisode`) shares none of these files. That child has:
  - credit `credit_unit × answers` for a commissioned literature task, against this head's whole-axis finding progress;
  - its own `yield_bindings` keyed by literature task, including a remaining-commissioned-credit forecast;
  - no wait;
  - a filtered host tool catalogue plus the A108 grading/aggregation population tools, where this head offers a selection-resolved tool set with `process.revise` / `process.execution`;
  - grading/scoring mixins;
  - a `render_literature_experimental_prompt` renderer.
- Only this head has the A/P selection, `revision_origin`, the filled-process identity and `sample_context_evidence_results`.
- `from_child_*.py` are byte-identical between its two children. `to_child_*.py` differ: recursion uses `prepare_invocation` with the closed-child replay branch, and literature uses `prepare_assignment`.
- `credit.py` also carries unused relative imports (`..communication`, `..domain`, `..investigation_progress`) alongside the `scientific_contracts` imports.
