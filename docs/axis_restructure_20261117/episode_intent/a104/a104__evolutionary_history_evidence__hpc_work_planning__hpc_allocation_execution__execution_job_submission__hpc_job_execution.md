## What this episode is for

Be the execution agent for one assigned job on the assigned HPC resource (role `launch_hpc`, resource kind `pbs_ssh` -> `hpc`), writing and running the shell code the job needs. In its own words (native_goal.py):

> You are the execution agent for the actual job and resource assigned below. Use exec_command to write and run the shell code needed for that job. Choose scripts, environment preparation, software invocation and recovery from the actual resource instructions and observed results. No sequence of setup or job-stage operations is prescribed. Preserve the caller's scientific inputs, desired outputs and acceptance criteria. Historical inventory is context, not proof of present usability. Each command is one ordinary episode action: its actual result and earned credit enter the iterator, including failure or zero progress. Host bookkeeping records command versions and actual native job identities; do not maintain a parallel receipt ledger. If a submission outcome is uncertain, investigate that original submission rather than create a duplicate. Use the provided resource-specific instructions, account, storage and existing authentication route. workdir and env apply to the selected command only. target=resource runs on the assigned resource; target=coordinator runs in the local run directory for supplied-input and transport work. Both are ordinary journaled actions; resource computation belongs on its actual allocation. For coordinator-side transfers, execution_resource.ssh_argv, when present, is the exact configured transport prefix. Append the remote shell command as its final argument and preserve stdin. The supplied configuration gives the existing connection details. target=resource uses that transport directly. The episode iterator decides continuation from credit; add no stopping budget.

## Task and instructions

- Task statement above, followed by "Resource instructions supplied from the frozen library:" and the sections that the launch instruction library selects for this resource (`launch_instructions.for_resource`, reached through `services.workflow`).
- `goal.py` delegates `instructions` to the practical executor (`TerminalExecutionBehavior`, native_execution_service.py) for the assigned resource.
- instructions.py is the composer (same text as api's task_instructions.py): specialist text replaces the default (`replaces_default_instructions = True`), then tool knowledge, launch library, child-delivery repair text, wait/native-event guidance (not active: only `tool` is permitted), exchange-protocol history text.

## What it reads from its parent's assignment

- Parent must be `launch` of execution_job_submission.
- Assignment: `practical_assignment_v1` (`ASSIGNMENT_SCHEMA`) with `resource_id`, `resource_kind` = `hpc`, `workspace` (confined inside the resource workspace), `endpoint` (`usable_handoff` or `completed_job_outputs`), `requested_job` (generic, or one of the seven A104 native jobs), `initial_context`.
- Own rule: when the launch parent sits under an `hpc` ancestor path, the child assignment schema is an `enum` of exactly the parent's already authorised hpc requests (`frozen_hpc_launch_request_missing` if none). This restriction is only in hpc.
- `_check_parent_inputs` (parent_request_contracts.py): original launch request, masking/utility inputs, pinned input versions, native/standard BLAST database job inputs.

## Children

None.

## Decision state and what the model sees

- Generic decision context (decision_context.py; same as siblings).
- Own view (native_internal_summary.py): `execution_assignment`, `execution_resource` (resource kind, workspace, kind, policy, account, `ssh_argv`, python_executable, scheduler, inventory snapshot), `coordinator_workspace`, `execution_progress` (PracticalState credit view), `execution_completion` (proof); initial `execution_resource_information` (inventory). hpc adds no selected-execution-task view (`_with_selected_execution_task` returns the value unchanged).
- Renderer `present_execution_context` (hpc prompt renderer chosen when the state is an HPC context).

## Tools it offers

One tool, `exec_command`: `cmd` (string or argv), `workdir`, `env`, `target` (`resource` default, or `coordinator`). Each call: validate, `PracticalState.begin` with the operation key (idempotent), run through `TerminalExecution` (old shared library native_terminal_transport), `finalize_scientific_command`, track cwd/environment revision for `target=resource` inside the workspace, `assess_validations`, `finish`, publish the receipt as a `PracticalReceiptInformation` source. A failed command is still a completed action with its receipt. Common actions: `tool` only.

## How credit is counted

`credit_kind = 'operational'`. Live credit = `PracticalState.credit_view()` of the practical state for this episode (defined in old shared-root practical_execution_state; not read here); the report text calls `practical_receipt_refs` "original selected command, actual result and earned operational credit sources". After closure the frozen closed-credit view (closed_credit.py, `execution_closed_operational_credit_v1`) is the only credit returned. Not bounded.

## Continuation

Private yield binding required. Profile `launch_hpc:<request class>` (`practical_hpc_<sorted native job names>_<handoff|outputs>`) from `task_yield_profiles` = `{cutoff, parameters}`; estimator `PracticalYieldEstimator(verify_completion)` (completion with a target). `verify_completion` accepts a `practical_completion_v1` proof that PracticalState verifies, or a historical verdict matched by exactly one recorded observation with exact-zero expected next gain. New layout: the completion-with-target estimator with these per-class settings.

## What it reports to its parent

Facts (to_parent.py): `practical_completed`, `practical_receipt_digests`, `practical_receipt_refs`, `execution_handoff_refs` (received handoffs plus practical receipt refs that the progress provider's handoff reader accepts as returnable targets), `execution_result_refs`, `execution_completed` (= practical_completed), empty native result families, `execution_blast_hsps` empty, BV-BRC AppService support refs when bound, plus closed-credit facts. `validate_report`: masking/utility/UniProt received-report checks, form validation, every `x-source` field equal to recorded facts.

## Differences from siblings

- Identical in content to local_job_execution except: role/resource kind (`launch_hpc`/`hpc`), the frozen-request `enum` in `child_assignment_schema`, and no selected-execution-task view in internal_summary.py (local adds `selected_execution_task_v1`).
- Versus api: practical `exec_command` executor instead of a service executor; no `wait`; task statement in native_goal.py; configuration uses the shared-library `APIRecordAccess` for any api resources.
