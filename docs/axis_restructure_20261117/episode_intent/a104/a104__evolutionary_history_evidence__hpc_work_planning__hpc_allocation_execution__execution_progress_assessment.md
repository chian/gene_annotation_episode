Only this folder's own files were read; it has no child episode folder (its child is itself, recursively).

## What this episode is for

Monitor one assigned execution target (role `monitor`) and report actually delivered progress information about it. In its own words (goal.py):

> Investigate which further exposed progress information is useful for the assigned target. Use actual status, measured quantities, committed references and source-bound logs. Liveness establishes process presence only; elapsed time alone establishes neither productive work nor a stall. Unknown information stays unknown. Earlier outcomes and your admitted child forms inform later decisions. You may explicitly commission an ordinary monitor for one exposed direct dependency; no descendant traversal, fanout, cadence or depth is prescribed. Return the original parent's typed form at your closure even while the target remains active. Do not report private reasoning, intentions or unrestricted findings. Recorded facts use saved delivered observations; closure does not poll or compose another report with a model. {credit_instruction} Repeated observation identities and read timestamps alone earn no new information.

`credit_instruction` = "The monitor's information-credit projector and bound yield rule govern continuation." with a private yield binding, else "The caller's monitoring projector and configured controller own credit and continuation."

Planning context (goal.py `planning_context`, shown as `monitor_goal`): objective (parent goal), target handle, requested fields, unresolved question "Which exposed progress information would improve the original requested report?", progress definition "Actual received information under the caller-bound monitoring projector; repeated identities and timestamps alone earn no credit.", yield settings.

## Task and instructions

task_instructions.py composes: goal text + ACTION_BOUNDARY ("Do not emit a stop action or invent a turn budget, approval review, quality gate, experiment, term or observation.") + CREDIT_COMPONENT_GUIDANCE (current_evidence_vector is the progress proxy, not biological truth) + RESOURCE_ESTIMATE_GUIDANCE (resource_tool_estimates; a timing experiment earns monitoring credit for timing information; job elapsed time vs own action duration) + REPORT_GUIDANCE (child returns only the parent's typed form; report_update before the next action; redeliver_report for delivery failures, never recommission to fix representation) + history guidance (exchange or plain) + HOST_EXECUTION_GUIDANCE + tool knowledge + launch library + REPAIR_GUIDANCE + WAIT_GUIDANCE (+ NATIVE_EVENT_GUIDANCE). This is the episode's own text, not the runner default.

## What it reads from its parent's assignment

`monitor_assignment_v1` (contracts.py): `target_handle` (must be in scope as `execution_handle`), `requested_fields` subset of `execution_status`, `measurements`, `log_windows`, `committed_record_refs`, `dependencies`, `result_available`; `known_progress_refs` (each must read back as a snapshot of the same target); `permitted_committed_record_types` (subset of RECORD_SCHEMAS). `prepare_assignment` requires an operation key. Commissioning parent: hpc_allocation_execution (entry role `monitor`).

## Children

- Child role: `monitor` (this same episode), allowed only when `services.dependencies(target_handle)` exposes direct dependencies.
- Sends (to_child_execution_progress_assessment.py): a `monitor_assignment_v1` whose `target_handle` must be one of the parent target's exposed direct dependencies (`monitor_child_target_not_exposed_direct_dependency`) and whose `permitted_committed_record_types` must not widen the parent's. `assemble_request` builds the old-runner child request (goal, scope, initial report, report contract declaration, knowledge inheritance).
- Takes back (from_child_execution_progress_assessment.py): the child's typed form; every `episode_progress` reference in it is read through the provider and admitted into this monitor's received progress under a content signature of form, schema and scope plus the operation key.

## Decision state and what the model sees

Generic decision state (decision_state.py, same content as the job siblings' decision_context) with `monitoring_information_credit` / `monitoring_information_binding` when the credit view carries them, and monitor inputs (decision_inputs.py: no HPC action history and no job-source estimate branch, unlike the job siblings). Own view (internal_summary.py): `monitor_assignment`, `monitor_target_description` (`services.describe_progress_target`), `monitor_direct_dependencies`, `monitor_received_progress_refs`, `monitor_information_meaning` ("Exposed direct relationships and already delivered observations. Empty measurements/log windows do not assert absence or a stall."), `monitor_goal`. Rendered by `present_task_context` (monitor renderer).

## Tools it offers

- `progress.observe(requested_fields[, native_operation])`: observe the assigned target; fields may not exceed the assignment; never traverses dependencies; `native_operation` only if the target descriptor declares a `selected_observation_schema`.
- `progress.read(progress_ref)`: re-read an already delivered observation (only received refs).
- `progress.log(progress_ref, log_index)`: one exact retained log window via `source.read`, checking source/artifact custody.
- Observers in this folder: APIObserver (one immutable observation per operation key; AppService targets to AppServiceObserver; legacy HMMER to HMMERObserver; failures become state `unknown` with error facts).
- Common actions: `tool`, `child`, `wait`, `redeliver_report`. Invalid tool calls return `invalid` outcomes that still enter the iterator.

## How credit is counted

`credit_kind = 'monitoring'`. `credit_view` = the caller-bound projector `services.bound_role_credit(context, receiver_selection)`. `information_credit` selects `ProgressInformationCredit(progress_reader, information_unit)`: newly informative received snapshot count times `information_unit` (per the yield binding text "newly_informative_received_snapshot_count_times_information_unit"). Repeated identities/timestamps earn nothing. Not bounded.

## Continuation

Private yield binding when `yield_settings = {kind: information_accumulation, cutoff >= 0, uncertainty_alpha in (0,1)}` with positive `information_unit`. `YieldController(epoch, initial_credit, cutoff, YieldParameters(uncertainty_alpha))` with `_monitor_information_yield` = `estimate_nonnegative_yield` (credit may not decrease; forecast = next monitor action's information credit; continue while predicted upper gain is above cutoff). New layout: the accumulation estimator in yield_control/ with `cutoff` and `uncertainty_alpha` as settings and `information_unit` as the credit unit.

## What it reports to its parent

Fact sources (to_parent.py): `monitoring_progress_refs`, `monitoring_target_handle`, `monitoring_execution_state` (latest delivered target observation; null if none), `monitoring_result_available`, `monitoring_observed_at_unix_seconds` (UTC, not refreshed), `monitoring_committed_record_refs` (parent-permitted types only), `monitoring_dependency_handles`. `required_return_sources` = `monitoring_progress_refs` when the parent is evolutionary_history_evidence and an annotation task is required. `validate_report`: recorded facts must match and any cited record must be a permitted, received committed record. Closure does not poll again.

## Differences from siblings

- Only episode of the four with a child (recursive monitor) and with `child`, `wait` and `redeliver_report` permitted.
- Credit kind `monitoring` (caller projector) instead of `operational`; accumulation estimator instead of completion with a target; no closed-credit freeze.
- Own instruction text (task_instructions.py) instead of the runner default composer.
- Its task is split into action_admission.py / action_execution.py; `execute` has no reasoning branch and no automatic score updates (job siblings have both).
- Has its own tests/ (three wrappers over old shared-root `root.tests` check classes plus test_progress_task.py).
