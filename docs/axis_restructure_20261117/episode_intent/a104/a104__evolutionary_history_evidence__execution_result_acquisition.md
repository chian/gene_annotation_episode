## What it is for (its goal, in its own words)

`goal.py`:

> Acquire the original selected execution results through the original handoff. Choose bounded status or requested
> file/page reads using actual preceding outcomes. Preserve partial bytes and native scores. Native paths expose the
> current resource filesystem: the exact attempt observation does not establish that current file bytes were produced
> by that attempt. Separate read windows are not an atomic file snapshot. The scientific parent interprets the
> returned records. Original work, resource and selector stay fixed. Only actual complete acquisition establishes
> this endpoint.

## Task and instructions

`instructions.py` is the same composition as the launch-local owner: the goal replaces the default prompt; tool
knowledge / launch library; the `pending_child_delivery` repair paragraph; wait paragraphs when `wait` is permitted
(it is for API service jobs); the exchange-history paragraph under `decision_exchange_v1`. The task loop files are
old-runner copies with grain / planning role `results`.

## What it reads from its parent's assignment

`RESULTS_SCHEMA` `{version: 'execution_results_assignment_v1', handoff_ref, selector}`; the selector additionally
admits `local_file_source_selector_v1` and the native result selector conditions. `prepare_assignment`: restore a
successfully returned recorded Results commission (`saved_commission.py`), otherwise resolve the target (retained
masking / utility target, else `read_target(handoff_ref)`), validate the selector against it, admit local file
sources, validate masking / utility / standard / native BLAST database selected inputs and BV-BRC inputs.
`required_return_sources = ('execution_result_refs',)` when the parent is `evolutionary_history_evidence` and the
annotation task is required.

## Children

None.

## Decision state shown to the model

Old runner context plus: `execution_assignment`, `execution_progress` (its own current facts), `execution_target`

annotation / evolutionary parent, received BLAST jobs with locally recomputed schedule estimates.

## Tools

Chosen by the target family (`work_operations.py`): masking / utility / standard / native BLAST database / HMMER
preparation / HMMER / BLAST result catalogs from the old shared library, the API service's `result_catalog`, or the
generic `execution.results.status` (observe the exact handed-off attempt once), `execution.results.collect` (observe
and acquire first bounded windows of the requested paths), `execution.results.read` (one selected window ≤1 MiB).
Argument and reference errors become `invalid` outcomes; retained-artifact custody failures for local files raise.

## Credit

`operational`, own family's `credit_view` when a native family or API applies. Generic native results
(`credit.py`): `credit = handoff_unit * 0 + acquired_record_unit * fraction`, fraction = mean over requested paths
of newly covered byte positions (union of all windows minus windows already known initially) / requested length
(`execution_received_selector_coverage_credit_v2`, qualification "original selector byte position union, current
filesystem version unverified"); with local file sources `acquired_record_unit * count`
(`execution_received_records_credit_v1`). Handoffs earn nothing here. Frozen at closure by `closed_credit.py`.

## Continuation

`yield_estimator.py` `_results_yield_controller` (requires `require_private_yield`):
- generic native target, open-ended window → `results_yield_profiles['native_unbounded_<local|hpc>']`, plain
  controller with its parameters → new runner **accumulation**;
- generic native target, finite windows → `task_yield_profiles['results:native_finite_<kind>']`, estimator
  `finite_result_yield`: verified endpoint → completion estimate; no uncredited bytes left → exact 0
  (`finite_result_selector_exhaustion_v1`); else `estimate_bounded_credit_yield(maximum_credit = acquired_record_unit *
  (1 - fraction already known))` → new runner **bounded quality** (maximum = remaining selector credit);
- API target → `task_yield_profiles['results:api_<service>[_<selector version>]']`, typed native target →
  `results:typed_<kind>_<selector version>`, both with `PracticalYieldEstimator(verify_completion)` → new runner
  **completion with a target**.

## What it reports to its parent

The selected family's facts (masking, utility, BLAST databases, HMMER preparation, BLAST, HMMER) or API facts (with
BLAST database grader rows when the target requires them; origin null), or generic: `execution_handoff_refs`,
`execution_result_refs` (results with windows), `execution_file_source_refs`, `execution_file_capture_outcomes`,
`execution_result_origin` (`NATIVE_RESULT_ORIGIN`), `execution_completed` (`_native_results_complete`: a completed
attempt with return code 0 whose windows cover every requested byte range contiguously), `execution_blast_hsps`
(empty), plus closed credit facts. Recorded `x-source` fields must equal the facts.
