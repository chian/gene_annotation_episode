# Stage 2 blockers, lib8 (records/, without records/documents/)

Operations the library needs from the scoped store that "System operations built in stage 1" does not offer.

1. Original read library, page of members. Was `libraries.member_page(store, library_ref, *, selection_ref=None, offset=0, limit=50, scope=None)` in `records/<axis>/library_targets.py` (nine copies; callers `tools/<axis>/tools.py` for six axes). It joined `material_members` of the library's collections with `library_selection_members` and resolved each read subject. Needed call: `store.library_members(library_ref, *, selection_ref=None, offset=0, limit=50, scope=None)` returning the page (`members`, `total`, `next_offset`). The copies are deleted; the Store's own `gene_annotation_episode/library_targets.py` is the one copy.
2. Original read library, freeze an explicit selection. Was `libraries.select(store, library_ref, *, member_refs=None, ordinal_ranges=None, scope=None)` (same files). It wrote a `read_selection` record and its rows in `library_selection_members` (a table the Store's scope arithmetic reads). Needed call: `store.select_library_members(library_ref, *, member_refs=None, ordinal_ranges=None, scope=None)` returning the `read_selection` record, held as produced.
3. Diagnostic references of a tool's outcome. `records/sequence_and_context_sources/genomic_source_receipts.py` `source_reference_restriction` used to deny a reference that was the `feedback.diagnostic_ref` of a `tool_operations` result (the operation ledger, deleted). It now judges only held sources. Needed to restore that denial: a reader call that says whether a held reference is the diagnostic of a unit outcome of the Episode, for example `reader.is_diagnostic_ref(ref)`; or the reader's `outcomes` view offered to library functions.
4. Writers of tables declared by readers here. `a102_structure_bindings`, `a102_derived_publications` (`records/structural_homology_evidence/attachments.py`), `a103_bindings` (`records/gene_context_evidence/publication.py`, `records/partner_presence_evidence/publication.py`), `homology_result_snapshots` (`records/similarity_search/<axis>/homology_search_receipt.py`) and `a104_attachments` (`records/evolutionary_history_evidence/attachments.py`) are written by modules outside this scope (tools, jobs); those writers must import the declaration (`TableDeclaration`) from the module named and write through `store.table(DECLARATION).put(...)`. Not an operation; a note for the families that write them.
5. `records/similarity_search/tests/test_blast_vdb_capture_failure_674.py` (12 tests) builds its capture with `controlled_capture` in `forms/similarity_search/sequence_homology_evidence/tests/test_blast_vdb_native_context_668.py`, which opens a raw `Store(tmp_path / "store")` and writes artifacts to it; the library functions it calls (`native_blast_utility_result_publication`) now take the scoped store, so the test fails. It needs the helper's capture built through `ctx.store` in a tool unit of a probe episode (forms family).
6. `records/documents/perturbation_evidence/tests/test_private_material_custody.py` imports `artifact_path` from `readers/perturbation_evidence/source_bytes.py` (readers family; documents are outside this scope).
