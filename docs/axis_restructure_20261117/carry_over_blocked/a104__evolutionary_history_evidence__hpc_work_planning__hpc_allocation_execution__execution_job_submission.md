## Contract misfits
- new field: execution_job_submission record_refs (the records the job inputs name, passed in custody; the old code read them from the commissioning request and the receipts ledger).
- new field: execution_job_submission handoff_unit, acquired_record_unit (old `LaunchConfiguration` operands; `msg_to_child`, `credit` and `yield_controller` get no `ctx.settings`, so the units must come from the parent input; the API child is also commissioned with them).
- new field: execution_job_submission scientific_task (old `services.scientific_parent_task`; the API child reads `scientific_question` and `selected_tool_info` from the message, the local child takes `scientific_task` in its assignment).
- new field: execution_job_submission received_handoff_resources (the resource ids that already had a usable handoff when the launch began: the old `initial_known_record_refs` read through `job_progress_provider.targets`; credit baseline and the yield maximum need it, and no handoff record kind exists to read it from records).
- The old usable-handoff test of a received record (`job_progress_provider.targets.usable_handoff`, in `_received`) has no counterpart: a launch child's report (`execution_completed` with `execution_handoff_refs`) is the count, so the parent trusts the child's completion. The handoff record kind is not defined (MECHANICS "Not provided yet" item 5).
- The old exact-zero estimator (`no_remaining_requests`, a launch whose every eligible request already had a handoff) is not carried and no controller has maximum 0 (`bounded_credit_range_invalid`): such a launch fails in `yield_controller` (`launch_every_original_request_already_has_a_handoff`). The old controller was `BoundedYieldController` with maximum `remaining`; it is `BoundedQualityYieldController` (README 7b). The old `practical_estimator` (completion proof) is not carried; the intent record's "completion with a target" reading was not followed because the live `yield_controller` method was the bounded one. The credit cannot pass the maximum while every commissioned resource is a permitted one (`action` refuses others), so no "completion credit may pass its target" case.
- `task_yield_profiles` of `ctx.settings`/`settings` must hold the key `launch:<sorted request classes joined by +>` with `{cutoff, parameters}`, cutoff above 0 (an accumulating or bounded controller at cost 0 never stops on its forecast).
- The 21 masking and utility fact sources are named `execution.<name>` (not lowercase identifiers), so no `RecordForm` field can carry them; they are not declared.
- `execution_result_origin` was `None` when nothing was retained and a form has no null type: declared as `record`, selecting it raises `NotImplementedError('no_null_form_type:execution_result_origin')`. Object family sources raise `native_result_family_empty_object_not_defined:<name>` (as in the children).
- `execution_handoff_refs` and `execution_completed` are required fields here (the old `required_return_sources` made the first required only under an annotation-task parent; a static form cannot be conditional). The API child declares both required, the local and HPC children declare them selectable, so `msg_to_child` selects both for those two and nothing for the API child (selecting a required field raises `FormError`).
- The frozen-request `enum` of the HPC parent (`authenticate_launch`) is a check of a commission and is not carried; the HPC allocation parent must copy its authorised request into the launch assignment.
- The old closed credit ("later delivery never reprices it") has no counterpart: the system's closure credit (`completion['credit']`) is returned.
- Real runner test not written: the first decision after the capabilities lookup needs a model (`-m model_run`) and the job service does not exist; the tests cover the class definition checks, the ten files, the import rule, the assignment, the controller, the credit, the result and the admission of each commission by the real form of the three children.
