## CONTRACT MISFITS

- BLOCKED-ON-JOB-SERVICE: hpc_ledger; wanted call: `ctx.services['hpc_ledger'].open_existing(ctx.run_id, owner_episode_id)` (see above). Also job_access (`run_remote`, `observe_queue`) and estimate_table (see above).
- new field: hpc_resource_prediction scope (assignment, `record`): the old code read `context.scope` of the binding context; the owner scope equality, the commission grant read and the received-source scope check need it. Its subject references must also be passed in custody (`validate_scope` reads each subject); no `record_refs` field was added for them.
- new field: hpc_resource_prediction received_record_refs (assignment, `record_refs`, optional): the old `context.received_record_refs`; result sources (and each source's artifact) the commissioner passes for `hpc_read` and for the `hpc_result_refs` return field.
- `commission_source_ref` is a `record_refs` field holding exactly one reference (a form has no single-reference type); `commission_id` is `text` (a form cannot enumerate the configured commissions); "exactly one of the two" (old `oneOf`) is checked in `read_from_parent`.
- The commission's `yield_bindings['hpc_prediction'] = {cutoff, parameters}` cannot reach `yield_controller`: the commission is a Store record read by a tool, and `read_from_parent` cannot read it. The controller reads `settings['cost']` and `settings['parameters']` of the run's `continuation` entry instead (old `require_commission_yield` -> `hpc_commission_yield_binding_required:hpc_prediction`). Cost zero never stops an accumulating controller; the settings must give a cost above zero.
- The old `PredictionState.initialize` ran only when the ledger had no model, so a prediction episode on an already initialized ledger got no `model_entry` (its gain was always 0). `hpc_open` calls the same idempotent `_initialize` (identities, `once`) on every open, so each episode records its own entry as the old docs state ("one model_entry record per episode").
- Count/time cutoffs of the old code not carried (README rule 2): the discovery `timeout=90`, the 64 KiB / 8 KiB output truncation (and the `truncated` key), and the `[:2000]` slice of the shared history observations. `ExecutionMemory.history(..., limit=2000)` keeps its own default limit inside the library, which this episode does not edit.
- A model argument error that the old code raised (training ids not original non-validation cases; training not preceding the temporal validation) is an `invalid` outcome now (a returned tool outcome is a unit with its credit); a returned invalid outcome enters the iterator.
- credit: the validation term and the model quality come from the ledger view of the latest tool outcome (`credit` has no services); before the ledger is opened credit is 0. Credit is never bounded; it can decrease (the model credit is a signed correction) and the accumulation controller takes signed credit. `hpc_credit` in the return is `completion['credit']`, the same value the old `credit_view` gave.
- `final_to_parent` raises `hpc_report_requires_the_opened_ledger` if the Episode is closed before its first unit.
- Tool names: old `hpc.read`, `hpc.compare`, `hpc.history.refresh`, `hpc.discovery.run`, `hpc.candidate.propose`, `hpc.queue.observe`, `hpc.model.fit` are `hpc_read`, `hpc_compare`, `hpc_history_refresh`, `hpc_discovery_run`, `hpc_candidate_propose`, `hpc_queue_observe`, `hpc_model_fit` (tool names match `[a-z][a-z0-9_]*`); `hpc_open` is new (the initial lookup of the old `state`/`initialize`).
- `hpc_work_planning/hpc_runtime.py` and `hpc_work_planning/tests/` (owned by the parent episode's job) still hold the hook-era runtime shared with the allocation sister; not touched.
- The old finding was not typed (the old report had facts only): `finding` is a new typed record (model identity, measured improvement, validation credit, available training count, candidate count, comparison made, qualification).
- No test runs the real runner: a run needs the three blocked services. The old tests (four shared check classes over the old runner) are retired (`retired_tests/a107__partner_presence_evidence__hpc_work_planning__hpc_resource_prediction.tsv`).
