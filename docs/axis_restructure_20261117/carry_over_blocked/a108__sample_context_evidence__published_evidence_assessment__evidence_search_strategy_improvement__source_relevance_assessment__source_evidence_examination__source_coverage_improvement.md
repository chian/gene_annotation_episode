## CONTRACT MISFITS

- new field: source_coverage_improvement scope (assignment)
- new field: source_coverage_improvement received_record_refs (assignment)
- new field: source_coverage_improvement finding (return; typed investigation findings: actual source claim, actual source subject, qualification; and source-grounded no_applicable_evidence declarations; the old form was written by the parent)
- new field: source_coverage_improvement finding_refs (return; the records the findings name, a pass carries only the records named)
- new field: source_coverage_improvement literature_sheet_refs (return, selectable; the sheets the selected cells belong to)
- validate_form_not_built:A108: the old `validate_report` called `validate_form(form, original_schema, resolver)`; A108 has none (`forms/sample_context_evidence/communication.py` has no `validate_form`). `messages/final_to_parent.py validate_report` runs the episode's own checks (assignment agreement, requested components, `FINDING_FORM.admit`) and then raises `NotImplementedError('validate_form_not_built:A108')`, so `final_to_parent` cannot return a result until the A108 validator is built. Nothing is borrowed.
- The library's grading and sheet functions (`literature_required_grading.execute`, the repositories) take a context object carrying run, Episode, role, scope, assignment and received records (the old `BindingContext`). The final form has none; `task.py GradingContext` is a plain data bundle of exactly those six attributes that the library reads, built per tool call from `ctx` and the envelope. It goes when the library functions take `store` and explicit values.
- The coupled grading is called as written (`execute(context, selection, ctx.operation_key, repository, authorize_source_access=...)`); `selection` carries `kind: 'reason'`, `commit` and `evidence_processing` (the tool arguments of `reason`) so that the library's own schema check passes.
- `ASSIGNMENT_FORM` has a `literature_task` record with its old schema (including the optional `yield_settings` with `cutoff` and `uncertainty_alpha`); those two values were filled from the owner's yield bindings. The controller's cost and parameters are now the episode's settings (`settings['cost']`, `settings['parameters']`); `yield_settings` of the task is validated and not read.
- Settings read: `cost` and `parameters` (yield controller), `tool_registry` (the keyword arguments of the A108 `ToolRegistry`: `clients`, `job_limits`, `native_statistics`, ...; `execution_estimate` is offered only when `tool_registry.native_statistics` is set), `knowledge_library_directory` (optional).
- Tool names cannot contain dots: `source_read`, ..., `literature_a108_grading_populate`, `literature_a108_aggregate` name the registry operations `source.read`, ..., `literature.a108_grading.populate`, `literature.a108.aggregate` (`ACCESS_NAMES`, `POPULATE_NAMES` in task.py).
- `action` wraps the tool arguments in an envelope `{arguments, scope, page_source_ref, proposed_annotation_ref, requested}` so that a tool (handed no summary) can apply the page-source restriction and the requested components and return an `invalid` outcome that enters the iterator.
- Completion credit: for `verified_source_leads` the controller is accumulating. For the two `source_answer` kinds credit is `credit_unit` times the number of answers, at most one (assessment: the first answer only; screening: one), so it equals the target at most. completion credit may pass its target: no for the carried kinds.
- `max(covered, end)` in `credit.py screening_answers` merges the examined intervals (old logic); it is not a bound on the credit.
- The old `credit.py` did not check the sheet before crediting an assessment; the sheet requirement is enforced inside the one `reason` action (the library's `execute` admits no interpretation without its sheet), so a held assessment of this episode always has its sheet. `credit.py` is unchanged on this point.
