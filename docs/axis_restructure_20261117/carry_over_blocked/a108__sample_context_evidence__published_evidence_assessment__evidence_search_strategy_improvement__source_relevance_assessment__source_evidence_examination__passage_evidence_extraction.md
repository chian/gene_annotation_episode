## CONTRACT MISFITS

- validate_form_not_built:a108. The old `to_parent.py validate_report` called `validate_form(form, original_schema, resolver)`. A108 has no `validate_form` (`forms/sample_context_evidence/communication.py` has none), so `messages/final_to_parent.py validate_report` raises `NotImplementedError('validate_form_not_built:a108')` after its own checks. The consequence is that `final_to_parent` can never return a result, so no Episode of this binding can close until the owner builds `validate_form` for A108 or states that the call is not needed (the system admits the result exactly against `RETURN_FORM` and the typed finding form).
- new field: passage_evidence_extraction scope (assignment; the old episode took the Store scope from its request)
- new field: passage_evidence_extraction received_record_refs (assignment, record_refs; the old episode read context.received_record_refs). The parent must name the source, its artifact, the sources it derives from, the proposed annotation and, for a lead, the lead's reference subject.
- new field: passage_evidence_extraction finding (return; the old episode returned the parent-written form). The episode declares the typed A108 finding (written, source_claim, source_subject, qualification, target_correspondence, passages, assessment_refs) and a `report` tool for the model's closing statement. A saved numerical sheet does not supply it; no target support is manufactured (`NOT_WRITTEN` states the claim absent, correspondence unresolved).
- new field: passage_evidence_extraction assessment_refs (inside the finding, record_refs): the assessments the finding rests on, returned in custody; `action` rejects a report that names a record the Episode does not hold.
- A child's old selectable report facts `literature_a108_grading_cells`, `literature_a108_aggregation_cells`, `literature_screening_answers`, `literature_source_lead_dispositions`, `literature_completed_work`, `literature_current_scoring_sheets` are the selectable fields of `RETURN_FORM` under their old names. The grading and aggregation requested components are `SubsetField`s of `ASSIGNMENT_FORM` under their old names.
- `LibraryCallContext` (`task.py`, frozen dataclass: scope, run_id, episode_id, received_record_refs, assignment): the old library repositories and `required_grading.execute` read these attributes from a `context` argument and call `dataclasses.replace` on it. It is a plain value, not the deleted binding context; it goes away when the library is carried and reads `records` / `ctx.store` and the parent input instead. `run_id` is the one value the new tool context offers that the repositories key their old ledgers by.
- Tool names cannot contain dots: library names (`source.read`, ...) are carried as `source_read`, ... (`LIBRARY_NAMES` / `POPULATION_NAMES` in `task.py`).
- The tool arguments are wrapped by `action` into an envelope `{'arguments', 'scope', 'page_source_ref', 'proposed_annotation_ref', 'assignment'}` so tools (handed no summary) can apply the page-source restriction and give the repositories the requested components. The `report` tool takes the arguments as they are.
- Settings read: `cost`, `parameters`, optional `tool_registry`, optional `knowledge_library_directory`.
- The old no-private-binding case is not carried: the controller is always built from the commissioned task (accumulation for verified_source_leads, completion otherwise).
- completion credit may pass its target: not expected. For assessment and screening `credit.py` counts at most one answer (`credit_unit`) and the target is `credit_unit`; verified_source_leads is accumulation (no target).
- `material.annotations`, `material.parse` and `material.from_source` of the old `_A108_ACCESS_TOOLS` and the A108 acquisition tools are not in the A108 `ToolRegistry.catalog` (the old catalog kept only the intersection), so they are not offered.
- The base investigation text and reasoning-commit requirement are imported from the library `literature/prompts/sample_context_evidence/literature_investigation_prompt.py`; `GOAL` imports `A108_CONTEXT_TASK` and `A108_READING_TASK` from the library (constants, not behaviour). The library `literature/grading/literature_task_credit.py` is the A104 file and is not used (its `lead_schema` reads the A104 witness schema); `task.py lead_schema` / `resolve_aliases` are private copies.
