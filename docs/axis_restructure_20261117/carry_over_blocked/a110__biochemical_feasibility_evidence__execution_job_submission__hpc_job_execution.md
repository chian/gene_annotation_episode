## Contract misfits
- BLOCKED-ON-JOB-SERVICE: `job_access` service; wanted call: `await ctx.services['job_access'].exec_command(assignment, command, run_id=ctx.run_id, episode_id=ctx.episode_id, key=ctx.operation_key, resumed=ctx.resumed)`.
- BLOCKED-ON-JOB-SERVICE: job record kind (handoff row of the job ledger); wanted call: `ctx.store.table(JOB_LEDGER).put({'job': ..., 'event': 'handoff', 'at': ..., 'detail': ..., 'source_ref': receipt_ref})`.
- new field: hpc_job_execution none from the record side. The old role read no record from the parent (`initial_references` was empty for `launch_hpc`), so no `record_refs` field is added. New: `completion_target` (the old code had a completion proof, not a number). It is derived inside `read_from_parent` (not an assignment field) as the sum of the credits of every original `progress_requirements` entry. The launch parent's job context (objective, scientific manifest, acceptance) can only arrive in `ChildMessage.message`, which `read_from_parent` keeps in the parent input as `message` and the model is shown.
- completion credit may pass its target: no. The target is the sum of all requirement credits (each at least zero in `validate_assignment`) and the practical credit is the sum of the satisfied ones, so it cannot pass it; the controller's `ValueError` is the failure if it ever did. Consequence: the controller stops on its forecast or at the target (all requirements satisfied), not at the verified completion alone. The `cutoff` (cost) of the profile must be above zero and below the target (`completion_cutoff_must_be_below_target`). (The allocation sibling used the credit of the completion keys only as target, which a satisfied non-completion requirement can exceed; this copy does not.)
- validate_form_not_built:biochemical_feasibility. The old `validate_report` called `validate_form(form, original_schema, resolver)` on the parent-written JSON-Schema form. A110 has no `validate_form` (`communication` has `plain` only). None is written or borrowed: `messages/final_to_parent.py::validate_report` keeps the fact-equality check and then raises `NotImplementedError('validate_form_not_built:biochemical_feasibility')` at the place of the old call, so every return of this episode raises until an A110 validator exists or the owner removes the step.
- `execution_result_origin` was `null` for a launch and a form has no null type: declared selectable; selecting it raises `NotImplementedError('no_null_form_type:execution_result_origin')`.
- The old frozen closed credit ("later delivery never reprices it") has no counterpart; `completion['credit']` is returned.
- The frozen-request enum, the resource constraints of the launch parent and the pinned input versions are checks of a commission and not carried; the commissioning `execution_job_submission` parent must copy its authorised request into the assignment (`msg_to_child`).
- The old `require_private_yield` flag (`execution_private_yield_binding_not_enabled`) is configuration machinery; the per-class profile selection (`launch_hpc:<request class>`, `{cutoff, parameters}`) is kept in `yield_estimator.py` and read from `settings['task_yield_profiles']`.
