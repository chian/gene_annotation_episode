## CONTRACT MISFITS

- new field: source_coverage_improvement scope (assignment; the old episode took the Store scope from its request)
- new field: source_coverage_improvement received_record_refs (assignment, `record_refs`; the old episode read `context.received_record_refs`). The parent must name the source, its artifact, the sources it derives from (`parent_source_refs`) and every record the credit reads (the scope's subjects and held assessments), since a pass carries only the records named.
- new field: source_coverage_improvement literature_partner_components (assignment, optional; the old name came from `partner_source_contracts.assignment_schema_fields()`, which has no placement).
- new field: source_coverage_improvement finding (return; the old episode returned the parent's requested form filled from the model's report update). The episode declares its own finding form (`written`, `source_claim`, `source_subject`, `qualification`, `target_correspondence`, `windows`) and a `report` tool for the model's closing text. A107 is not an A105/A108 episode, so no saved subscoring sheet or grader selection applies.
- return field `literature_partner_cells` is declared selectable (old fact source `literature_partner_cells`); the parent selects it in its `msg_to_child`.
- `validate_form` of A107 (`forms/partner_presence_evidence/communication.py`) checks a parent-written JSON-Schema form with `x-source` fields; the parent now writes no return form, so `validate_report` checks the finding with the episode's own `RecordForm`, the assignment agreement, the held references (`records.holds`, computed in `internal_summary`) and the returned cells.
- Credit: the old `services.scientific_credit` with no projector lived in the old shared root. Carried as the A107 finding-progress credit with `FINDING_UNIT = 1.0` (the old unit is unknown). This episode has no reasoning commit, so the credit counts only the assessments it holds in its scope; population units and reads earn nothing by themselves ("A search or read earns no scientific credit by itself"). Because nothing here earns credit by itself, an accumulation controller with a positive `cost` stops it once the forecast falls to the cost.
- Controller: the old default controller (None) is carried as accumulation (README 7b); settings read: `cost` and `parameters` (yield controller), `tool_registry` (keyword arguments of `A107ToolRegistry`).
- Tool names cannot contain dots: the library names (`source.read`, `literature.partner.populate`, ...) are carried as `source_read`, `literature_partner_populate`, ... (`ACCESS`, `POPULATION` in `task.py`).
- `action` wraps the model's arguments into an envelope `{'arguments', 'scope', 'page_source_ref', 'input_schema'}` so that the tool, which is handed no summary, can apply the old argument admission and source restriction and still return an `invalid` outcome that enters the iterator.
- The population tool adds `population_context` (`run_id`, `episode_id`) to the library outcome so that `internal_summary`, which is handed no run id, can build the old repository context.
- The model answers in the strict transport `{tool, arguments_json}` (as the A103 sibling); the old strict transport of `model_exchange/strict_output.py` was not used.
- The old `validate_report` and `fact_cells` needed the Store; in the final form `internal_summary` reads them through `view.records` (so a library call in old form raises as soon as a sheet exists).
- No old tests exist for this episode (its tests folder held only an empty `__init__.py`), so the retired-tests file has only its header.
- completion credit may pass its target: not applicable (accumulation controller).
