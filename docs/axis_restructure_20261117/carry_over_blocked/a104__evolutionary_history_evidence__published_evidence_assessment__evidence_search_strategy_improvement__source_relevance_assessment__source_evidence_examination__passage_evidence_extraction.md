## CONTRACT MISFITS

- new field: passage_evidence_extraction scope (assignment; the old episode took the Store scope from its request)
- new field: passage_evidence_extraction received_record_refs (assignment, `record_refs`; the old episode read `context.received_record_refs`). The parent must name the source, its artifact, the sources it derives from (`parent_source_refs`), the proposed annotation and, for a lead, the lead's reference subject, because a pass carries only the records named.
- new field: passage_evidence_extraction finding (return; the old episode returned the parent's requested form filled from the model's report update and had no finding). The episode declares its own finding form (`written`, `interpretation`, `passages`, `qualification`) and a `report` tool for the model's closing text. The old parent-written form cannot be carried (rule 5). The old `report_update` field of every model answer is the `report` tool.
- A104's `validate_form` (closed report schema; KEYWORDS has no `minLength`, strings need semantic formats) admits no free text, so the old `validate_report` call `validate_form(form, schema, resolver)` cannot validate this episode's free-text finding; `validate_report` checks the finding with the episode's own `RecordForm` (`FINDING_FORM.admit`), the assignment agreement and the held references.
- Tool names cannot contain dots: the library names (`source.read`, ...) are carried as `source_read`, ... (`LIBRARY_NAMES` in `task.py`).
- The tool arguments the model fills are wrapped by `action` into an envelope `{'arguments', 'scope', 'page_source_ref', 'proposed_annotation_ref'}` so that the tools, which are handed no summary, can apply the old page-source restriction and still return an `invalid` outcome that enters the iterator, as the old `execute` did.
- Settings the episode reads: `cost` and `parameters` (yield controller), optional `tool_registry` (keyword arguments of `ToolRegistry`; `native_statistics` makes `execution_estimate` available), optional `knowledge_library_directory`.
- The old no-private-binding case (default controller of the old runner) is not carried: the controller is always built from the commissioned task (accumulation for `verified_source_leads`, completion otherwise; README 7b).
- completion credit may pass its target: not expected. For `source_answer` assessment/screening `credit.py` counts at most one answer and the target is `credit_unit`; for `a105_*` kinds the credit raises. A later check is the controller's own ValueError.
- `decide` shows the model the tool catalog built from `task.py` constants (`DESCRIPTIONS`, `INPUT_SCHEMAS`) instead of the old `services.tool_catalog(scope)`; the descriptions are a private copy of the tool library's text.
