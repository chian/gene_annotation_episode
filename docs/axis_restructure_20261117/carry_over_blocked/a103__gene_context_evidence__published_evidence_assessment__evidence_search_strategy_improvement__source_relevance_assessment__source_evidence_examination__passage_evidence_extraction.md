# Blocked, unplaced and misfit items: A103 passage_evidence_extraction (19 November 2026)

## blocked_on_store_access

- `episode_support/tools/gene_context_evidence/tools.py::ToolRegistry` (called in `task.py` `tool_catalog` and `_access` as `ToolRegistry(ctx.store)`, then `.catalog(scope)` and `.execute_async(...)`). Pattern: "library not carried". Old call `ToolRegistry(store)` runs `store.db.execute(CREATE TABLE tool_operations ...)`, `store.path / 'cache'`, `RemoteSearches(store, ...)` and `execute_async` reads `tool_operations` through `store.db`. Intended: `ToolRegistry(ctx.store)` over the custody operations only; the operation ledger is the system's attempts journal (`ctx.operation_key`). The call stays as written; it raises `AttributeError` on the scoped store until the library is carried.
- `episode_support/grading/gene_context_evidence/credit.py::A103ContextCredit` (called in `credit.py` as `A103ContextCredit()(records, scope, known_record_refs=records.refs())`). Pattern: "library not carried". Old: `received_attachments(store, known)` and `received_measurement(store, ref)` read the tables `a103_attachments`, `a103_publications`, `a103_bindings` with `store.db.execute(...)` and `sqlite_master`; `component_assessment_dependencies.assigned_annotation` uses `store._assessment_write_extent`. Intended: declared work tables read with `records.table(T).select(...)`, and custody-aware reads. The call stays as written.
- Consequence: `credit(summary, records)` is real code but raises (`AttributeError` on `records.db`) at the library call until A103ContextCredit is carried; the episode as a whole cannot run until ToolRegistry and A103ContextCredit are carried.

Under the owner's rules a wrong commission fails at form admission and custody; no episode check is added. Not carried.
- `from_parent.py::SourceAssignment._validate_assignment`: the schema constraints are carried in `read_from_parent` (representation choices, at least one span, offset at least 0, limit at least 1). The cross-field checks (`literature_reading_source_mismatch`, `literature_reading_representation_mismatch`, `source_offset_out_of_bounds`) are checks of the commission and are not carried.
- `from_parent.py::SourceAssignment.prepare_assignment` and `parent_page_custody.py` (`_parent_page_schema`, `_validate_parent_page`): the parent's page re-validation and `literature_reading_outside_assigned_source` check of the commission against the commissioning parent's own assignment. Not carried: it is a link-time comparison of one episode's names with another's and a check of the commission (rule 1). The tool-time restriction of every operation to the assigned source (a different old check, in `source_operations._tool_arguments`) is carried in `task.py`.
- `task_presentation.py::_guidance` and the parent form rendering `render_requested_return`: the guidance fields came from the old parent request (evidence axis, thought pattern, child tool info); the parent now passes `gene_context_evidence` and the episode shows its `assignment` parts. - `decision_inputs`: resource context, shared-information context, launch-instruction library and selected launch instructions, execution expectations, job execution options, resource estimates, native execution expectations and event targets, requested-action history are not carried: nothing supplies them (no settings or services), and the leaf offers no job or HPC tool. The tool-knowledge and launch-instruction text paragraphs of the old instructions are not appended for the same reason.
- `source_interpretation.py` (reasoning action), `scientific_records.py` (automatic judgments): nothing to carry; neither was offered.

## contract_misfits

- new field: passage_evidence_extraction scope (the old code read the scope from the commissioning request, not the assignment)
- new field: passage_evidence_extraction record_refs (page records and their derived sources must be named in a top-level `record_refs` field; `page.source_ref`, `artifact_ref` and the context refs are nested text, not custody)
- new field: passage_evidence_extraction gene_context_evidence (optional; the parent's constraints, context, evidence operands and guidance, which the old TASK prompt rendered)
- new field: passage_evidence_extraction finding (the typed finding: source_claim, source_subject, qualification, target_correspondence, passages). The old report was the parent's own requested form filled from model `report_update` values; no parent form exists now. RETURN_FORM has no other field because the old episode had no fact sources.
- The axis `validate_form` (`forms/gene_context_evidence/communication.py`) requires every string of a schema to be a declared code or semantic format, so a free-text finding cannot be validated with it; `final_to_parent.validate_report` uses the domain `validate_schema` plus a held-source check instead.
- `final_to_parent` raises `a103_passage_evidence_finding_not_reported` when the controller stops the Episode before the model selected the report tool: the finding is required and nothing may be invented. With a bounded-quality controller over a credit that does not depend on the report this can happen.
- The first unit of every Episode is the `tool_catalog` lookup (the registry catalog needs a store, `decide` has none); it earns no credit and the first controller observation is a zero gain.
- A bounded-quality controller was chosen (A103ContextCredit declares `yield_method = 'bounded_quality'`, `native_score_maximum = 1.`); the old yield_estimator returned None, so the old default applied and the owner has not stated the kind (intent record, "Continuation"). `settings` must carry `cost` and `parameters`.
- `A103ContextCredit` was called as `credit(records, scope, known_record_refs=records.refs())` with no `assignment`; what the old `services.scientific_credit(context, receiver_selection)` passed as assignment and receiver selection is not in the episode files.
- The access tools are one module-level tool per operation (15) because a tool name has no dots and a tool must be a module-level function of `task.py`; each wraps the shared `_access`.
- `ctx.model`, services and settings are not used; the outcome-page size is a constant.
