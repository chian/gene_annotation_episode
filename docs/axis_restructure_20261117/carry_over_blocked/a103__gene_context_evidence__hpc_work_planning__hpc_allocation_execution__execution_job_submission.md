None of this episode's own calls goes through the Store: it reads its commission, its settings and the reports of its children. The library functions that the old launch admission called through the old store are in no library module, so they are not called; the pattern for each:

- `native_blast_masking_results.validate_job_inputs` / `native_blast_utility_results.validate_job_inputs` (old `ExecutionResultRecords._masking_inputs`, `_utility_inputs`). Pattern: "library not carried (module absent)". - `execution_input_versions.validate_execution_input_versions` (old `_versions`). Pattern: "library not carried (module absent)". Old `validate_execution_input_versions(self, versions, scope, context=parent)` -> intended the same over `records` (`records.get`, `records.holds`).

## contract_misfits

- BLOCKED-ON-JOB-SERVICE: estimate_table; wanted call: `ctx.services['estimate_table'].read('resource_tool_estimates', 'launch')`.
- BLOCKED-ON-JOB-SERVICE: job_access; wanted call: `ctx.services['job_access'].capabilities(resource_id)` (tool) and `ctx.services['job_access'].read('capabilities', resource_id)` (decision).
- new field: execution_job_submission input_refs (record_refs of ASSIGNMENT_FORM, optional: the records the jobs read; the old code re-read them from the parent's assignment).
- new field: execution_job_submission handoff_unit (the credit one usable handoff earns; the old code read it from its configuration and `credit` has no settings).
- new field: execution_job_submission already_handed_off (the resource ids with a usable handoff when the commission began; the old code derived them from received records).
- new field: execution_job_submission scientific_task (the ancestor's scientific_question and selected_tool_info; the old code asked a services callback).
- new field: execution_job_submission hpc_execution_job (the plan's job under an HPC parent; the old code was handed it at its first decision).
- new field: api_job_execution completion_target and input_refs, hpc_job_execution input_refs, local_job_execution record_refs and scientific_task (added by the children; this episode fills them: completion_target is `handoff_unit`, the records are `input_refs`).
- The children's assignment forms have no field for `immutable_input_versions` (nor `scope`): the pinned input versions of the launch assignment are shown to the model and are not passed to a child. new field wanted: api/hpc/local_job_execution immutable_input_versions.
- A form field name is a lowercase identifier: the 7 `execution.masking_*` and 14 `execution.blast_utility_*` fact sources are declared as `execution_masking_*` and `execution_blast_utility_*` here and in the API and HPC children, while the local child leaves them out. Declared under a renamed name against "names both sides use are the old names".
- A form has no null and no empty-object value for the native result families: `execution_result_origin` (old value null when no result was retained) is returned as the empty record; a family source typed as a record cannot be returned and raises `NotImplementedError('native_result_family_empty_object_not_defined:<name>')`.
- Continuation: bounded quality, maximum = `handoff_unit` x permitted requests not already handed off. Credit cannot pass it: only a permitted resource can be commissioned and a resource counts once. When no request remains the maximum is zero (the old exact-zero estimator is not carried): the controller's forecast is zero and stops the Episode after its first unit.
- Settings: the caller's `continuation` entry for this binding path must carry `resources` and `initial_information` (the caller-bound resource configuration and inventory by resource_id), `task_yield_profiles` keyed `launch:<request classes joined by +>` with `{'cutoff', 'parameters'}` (a missing profile raises `execution_original_task_yield_profile_required:<key>`), and optionally `tool_knowledge_directory` and `launch_instructions_directory` (a pinned `launch_instructions` selection without the directory raises). `cutoff` must be above zero so that a controller with a zero forecast stops.
- A usable handoff is decided from the child's own finding (the API child's `handoff_established`, the HPC child's `handed_off`) and its returned `execution_handoff_refs`; the old code read the handoff record's target and tested `usable_handoff(target)`. The local child's finding has no such flag, so returned references decide.
- Custody (T5): the parent returns the children's `execution_handoff_refs` only. The records those name (the receipt artifacts a command wrote) are not named in this return; the HPC allocation parent reads handoff references only (the old `hpc_launch_report_form` was `{execution_handoff_refs}`).
- `ASSIGNMENT_FORM.requests` is a `record` (the old map resource_id -> request) and the admitted record is key-sorted, so `permitted_resource_ids` follows the sorted resource ids. The old selection null of `launch_instructions` is expressed by omitting the optional field.
- Hook-era `episode.py` (class `ExecutionEpisode(JobSubmissionBinding, A103ContractBinding)`, a stub over the shared `a103/gene_context_evidence/execution_job_submission/submission_source.py`) was deleted. The shared per-kind source `submission_source.py` and `contract_binding` are still imported by the other A103 execution_job_submission folder (`a103/gene_context_evidence/execution_job_submission`) and were not touched.
