## contract_misfits
- new field: execution_job_submission record_refs (the job inputs the old code read from the Store by reference: the commission names them; the child commissions pass them on)
- new field: execution_job_submission handoff_unit (old configuration value; `credit` has no settings)
- new field: execution_job_submission acquired_record_unit (old configuration value; a launch acquires none, so its term in `credit` is 0)
- new field: execution_job_submission scientific_task (old `services.scientific_parent_task`)
- new field: execution_job_submission received_handoff_resources (the resources whose usable handoff the old receipts ledger held at the start)
- new field: hpc_job_execution record_refs: the HPC child's `ASSIGNMENT_FORM` has no `record_refs` field, so this parent cannot pass the records an HPC job's inputs name (masking, utility, native BLAST database, RNA structure); `msg_to_child` for `launch_hpc` passes the request only.
- local_job_execution was not yet carried (only the hook-era `episode.py`): `msg_to_child` for `launch_local` is written against the assumed form of its sibling copy (`hpc_work_planning/execution_job_submission/local_job_execution`): the practical request plus `record_refs` and `scientific_task`, selecting `execution_handoff_refs` and `execution_completed`. Verify when the child is carried.
- API child: `completion_target` is passed as `handoff_unit`. Its credit may pass that target when operations acquire records (the child's own misfit).
- The fact-source names `execution.masking_*` and `execution.blast_utility_*` contain dots, which a form field name refuses; the fields are named with underscores (as the API child does), so the parent and the child agree, but the old names are not kept.
- `execution_result_origin` was `null` for a launch with no retained result; a form has no null: the field is the empty record. Every object-typed fact source is likewise `{}`.
- `BoundedQualityYieldController` refuses a maximum of 0 (`bounded_credit_range_invalid`): the old exact-zero estimator for a launch whose every eligible request already had a usable handoff cannot be a bounded controller. That case gets `AccumulationYieldController` on the same profile cost (a unit that earns nothing brings the forecast down to the cost). The old forecast of zero from the start becomes at least one unit before the controller stops it; the old key `launch:<classes>` of `task_yield_profiles` is now required in that case too.
- `execution_private_yield_binding_not_enabled` (old `require_private_yield` false) is not carried: every Episode has a controller; `settings['task_yield_profiles']` is required.
- The old validation of the commission (`prepare_assignment`: `authenticate_launch`, native BLAST database / standard database / RNA structure job inputs, masking and utility inputs, pinned input versions) is not carried (rule 1); the receiving custody (`CustodyError`) is the check.
- The old `validate_report` called the axis `validate_form(form, original_schema, resolver)` on the parent-written JSON-Schema form; that form no longer exists, so the check is the fact comparison only. (A107 has a `validate_form`; there is no form to give it.)
