## CONTRACT MISFITS

- new field: perturbation_evidence scope (assignment, record): the old runner's request scope (`context.scope`).
- new field: perturbation_evidence received_record_refs (assignment, record_refs, optional): the old binding context's `received_record_refs`; `proposed_annotation_ref` is one text and gives no custody.
- new field: perturbation_evidence committed_record_refs (return, record_refs, selectable): the records the process committed; the old `required_return_sources` required it of the root's child.
- new field: perturbation_evidence settings keys of the episode's `continuation` entry: `cost`, `parameters` (yield controller), `child_roles` (the old `child_roles` configuration), `execution_handoff_unit` (the launch child's `handoff_unit`), `monitoring_information_unit` (the monitor's `information_unit`), `process_library_directory`, `tool_library_directory`, optional `knowledge_library_directory`, `launch_instruction_directory`, `tool_registry`.
- The old `required_return_sources(parent, role)` depended on the commissioning parent's path length (`len(parent.path) == 1`: both `perturbation_evidence_results` and `committed_record_refs`; deeper only `committed_record_refs`) and on `annotation_task_required`. A form cannot make a field depend on the parent's path: the head always selects both from a child of its own kind (`msg_to_child.REQUIRED`), and every head's parent selects what it wants. The path length is a runner concept (the root episode is now above the axis head).
- The old assignment `selection` carried library entries resolved by a read of the process and tool libraries (a check of a commission). Nothing checks it now: a selection the libraries do not know fails where `decide` or `process_revise` resolves it from the frozen directories.
- The old `proposed_annotation_ref` was required only when yield bindings were configured; the controller is always built now, so `read_from_parent` requires it (the credit reads its hypothesis).
- Completion credit does not apply: the controller is accumulation (the projector's `yield_method`), so no completion-target trap. `credit.py` is `credit_unit` times the distinct retained findings and is unbounded; it needs a cost above zero in the settings for the controller to stop.
- `credit(summary, records)` receives the summary, and `finding_progress` reads `scope`, `proposed_annotation_ref` and `task` from it (`internal_summary` spreads the parent input into the summary). `read_snapshot` is not offered on `records` and `project_finding_progress` takes a store with it (see BLOCKED).
- Hook-era sources still imported elsewhere: `root/axes.py` imports `episode_contract.home` and `episode.PerturbationEvidenceEpisode` of this folder (deleted; not touched, not mine). The three `published_evidence_assessment/literature_*.py` hook-era files are no longer imported by this folder.
- Tests: no model-run test (the real run needs `project_finding_progress` and `ToolRegistry` in custody form); no real-runner test either, for the same reason: `internal_summary` calls `project_finding_progress` at the first unit.
