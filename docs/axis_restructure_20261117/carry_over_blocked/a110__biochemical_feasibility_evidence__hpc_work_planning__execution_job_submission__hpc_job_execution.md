## CONTRACT MISFITS

- BLOCKED-ON-JOB-SERVICE: job_access; wanted call: `await ctx.services['job_access'].exec_command(configuration, coordinator_workspace, assignment, command, run_id, episode_id, key)` (see above).
- BLOCKED-ON-JOB-SERVICE: job records; the handoff of the actual job is kept as the practical command receipt (`practical_receipt_refs`, `execution_handoff_refs`); no job handoff record kind or work table exists yet (mechanics section 6), so the episode defines none and returns the receipts it would have written once `PracticalReceiptInformation` is carried.
- validate_form_not_built:biochemical_feasibility_evidence: the old `validate_report` called the axis `validate_form(form, original_schema, resolver)` on the parent-written report form. The axis has none; `final_to_parent.validate_report` raises `NotImplementedError('validate_form_not_built:biochemical_feasibility_evidence')` where that call was, so `final_to_parent` raises on every run until a validator exists (the new form has no parent-written JSON-schema form to validate).
- completion credit may pass its target: the target is the sum of the credits of all `progress_requirements` (`parent_input['credit_target']`), which the credit (the sum of satisfied requirement credits) cannot pass. But the old estimator stopped when the completion proof verified; credit reaches the target exactly then only when every requirement is a completion key or satisfied by then. A verified completion with other requirements unsatisfied leaves the controller running until the forecast falls to the cost. Nothing is bounded or added.
- new field: hpc_job_execution (none). The assignment form has one field per property of the old schema. `launch_instructions` is nullable in the old schema (`anyOf null | object`) and `native_flux_balance_execution` is optional: both are `required=False` record fields; an explicit null cannot be expressed (no null type, README 5 item 11), so the parent omits the field.
- `execution_result_origin` is null in the old facts when no result windows exist, and a form field has no null: it is a selectable `record` field and `final_to_parent` raises `ValueError('execution_result_origin_not_available...')` when selected (an hpc launch acquires no result bytes). `execution_result_refs`, `execution_file_source_refs` and `execution_file_capture_outcomes` are always empty here (they came from the old results role and local file sources).
- `execution_handoff_refs`: the old returnable-handoff test came from the removed `job_progress_provider.targets._handoff_reader`. `final_to_parent.facts` takes the receipts in which a validation of the requirement kind `requested_job_handoff` is satisfied (the library's own handoff predicate). This reading is an assumption of this carry-over.
- The parent's immutable input versions and its frozen hpc request enum were checked by the child through the parent's recorded assignment (README 5 item 14); the child cannot read its parent's assignment. The parent's own `msg_to_child` must supply a valid practical assignment; `read_from_parent` runs the practical assignment contract (`validate_assignment`) and fails on a wrong one.
- Settings the episode reads (`continuation['biochemical_feasibility_evidence/.../hpc_job_execution']`): `resource` (the pbs_ssh configuration: kind, workspace, ssh_argv, python_executable, account, scheduler), `coordinator_workspace`, `task_yield_profiles` (`'launch_hpc:<class>'` -> `{'cutoff', 'parameters'}`), optional `launch_instructions_directory`. The old `require_private_yield` flag, results profiles, handoff/acquired units and log window belong to the other roles of the old shared configuration and are not read.
- The `ASSIGNMENT_FORM` has no `record_refs` field: the old assignment named no records. A record the exec commands read (inputs) is named by the launching parent in its own commission; none is declared here.
