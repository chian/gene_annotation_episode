## BLOCKED-ON-STORE-ACCESS
None. The episode writes nothing to the Store. `progress_log` reads through `ctx.store.holds/get/open_artifact`; `internal_summary` reads committed records through `view.records.get`. The library functions called (`ProgressInformationCredit`, `selected_wait`, `strict_output_schema`, `decode_strict_output`, `LaunchInstructions`, `ToolKnowledge`, `time_accounting`, `yield_table`, `extend_context`, `rejection_feedback`) take no Store.

## contract_misfits
- BLOCKED-ON-JOB-SERVICE: job_access and estimate_table and native_events (above); wanted calls as listed.
- validate_form_not_built:a110: the old `validate_report` called the axis `validate_form` first; A110 has none (`forms/biochemical_feasibility_evidence/communication.py` has `plain` only). `messages/final_to_parent.py validate_report` runs the recorded-fact checks and then raises `NotImplementedError('validate_form_not_built:a110')`, so `final_to_parent` of this episode raises until A110 has a `validate_form`.
- new field: execution_progress_assessment information_unit (assignment `number`: the old monitor took it from its configuration; `credit(summary, records)` has no settings; the commissioning parent must send it; this episode sends its own to its dependency monitor).
- new field: execution_progress_assessment known_progress_snapshots (assignment, optional `record`: the snapshots of `known_progress_refs` by reference; the old provider held them; credit and the summary have no provider, so the commissioner passes the snapshots it received).
- new field: execution_progress_assessment monitoring_progress_snapshots (return, selectable `record`: the delivered snapshots by reference); the self-nesting commission selects it with `monitoring_progress_refs`. Any commissioning parent that counts child progress must select both.
- the old assignment carried no scope field and none is added: the old scope came from the old request. The wanted job_access calls therefore name the target only; the old `scope`-bound admission (`reference_in_scope`, `read_progress(reference, scope)`) is a job_access concern.
- the exposed direct dependencies come from the latest delivered observation of the assigned target (`kind == 'job'`), not from a provider read of `services.dependencies` before the first observation (the provider has no object here). Until an observation is delivered, no dependency monitor is offered.
- A form has no null: `monitoring_execution_state`, `monitoring_result_available`, `monitoring_observed_at_unix_seconds` are `record` fields holding `{'value': ...}` (null without an observation, as the old report returned null).
- `monitoring_*` fields are selectable, not required: the old parent `biochemical_feasibility_evidence` named its required sources in its own `to_child_execution_progress_assessment.py`; that parent must select what it needs.
- records of the old `_ASSIGNMENT` with no property in the new form: none dropped (`version` is a `DeclaredField` with the old constant `monitor_assignment_v1`; `requested_fields` and `permitted_committed_record_types` are `SubsetField`s over the old enums).
- committed records a monitor returns (`monitoring_committed_record_refs`, a `record_refs` field) and reads (`ctx.store.get`, `view.records.get`) must be held by the monitor: records published by an execution owner through a service are in no receipt, so reading them raises `CustodyError` unless the job service writes them through custody or the parent passes them in custody (no such property existed in the old assignment).
- `progress.log` reads the window with `ctx.store.open_artifact` (source and artifact must be held) in place of the old `source.read` tool through `services.execute_tool`.
- the old `outcome_page_size` setting is not needed: every outcome is in the view. The old private-yield validation (`monitor_private_yield_binding_not_enabled`, cutoff and alpha checks) is kept in `yield_estimator.py` over `settings['cost']` and `settings['parameters']['uncertainty_alpha']`. Cost zero passes the check but an accumulating controller then never stops: the run's settings must give a cost above zero.
- the monitor's credit raises `monitor_information_credit_cannot_decrease` against the credit of its previous received refs (README 7b); the projection is monotonic by construction, so it cannot fire today.
- completion credit may pass its target: not applicable (accumulation controller; A110 has no BLAST status target).
- GOAL is the old goal instruction text; UNIT and RESULT are written for this binding (the old `goal.py` had instructions only). The old goal's credit sentence had two variants (own yield binding, or the caller's projector); only the own-yield variant is carried, as the episode always builds its own controller.
- Self-nesting: the job names no child folder, but the old episode commissions a monitor of its own kind (`CHILD_SLOTS = {'monitor': <own binding path>}`), so `msg_to_child.py` and `read_from_child.py` exist. A wrong dependency commission (target not exposed, record types beyond its own, a baseline ref it holds no snapshot of) fails the run from `msg_to_child`; `action` rejects only a model pick naming a progress ref the monitor does not hold.
- the finding is the monitor's own typed finding (target, observed, execution state, result availability, progress count, newly informative count, qualification): not an A105/A108 evidence episode.
- git: the repo root of this working tree has no `.git`; old files were read from the sibling checkout `/home/chia/repos/gene_annotation_episode_disk` at commit 97308b94c.
