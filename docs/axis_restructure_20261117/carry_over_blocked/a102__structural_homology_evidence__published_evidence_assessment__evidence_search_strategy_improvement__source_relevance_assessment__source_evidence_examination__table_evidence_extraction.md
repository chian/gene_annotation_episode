## CONTRACT MISFITS

- new field: table_evidence_extraction scope (assignment; the old episode took the Store scope from its request).
- new field: table_evidence_extraction received_record_refs (assignment, `record_refs`; the old episode read `context.received_record_refs`). The parent must name the source, its artifact, the sources it derives from (`parent_source_refs`) and the proposed annotation (`proposed_annotation_ref`), because a pass carries only the records named.
- The old `LiteratureTaskCredit` projector lived in the old shared root (`root/a102/literature_task_credit.py`), which is not read. The library has one `literature/grading/literature_task_credit.py`, which is the A104 copy (task schema `evidence_axis` enum A105/A106/A108, A104 imports, old-runner `context` objects and `runtime_*` reads). `credit.py` is a private re-expression of its credit for the task kinds an A102 table episode takes (verified_source_leads, source_answer assessment and screening), `credit_unit` times the number of answers, over the unit outcomes and held records. Whether A102's own old projector differed (other task kinds, other counting) is not known; any other task kind raises `literature_task_kind_not_carried:<key>`.
- `read_from_parent` accepts any `evidence_axis` in the task (the key is `<axis>:<kind>`); the library `task_schema` cannot validate an A102 task (axis enum). `literature_task` is an untyped `record` field; only `kind`, `answer_kind` and `credit_unit` are checked.
- Yield settings: the old cutoff and `uncertainty_alpha` came from the commissioned task's `yield_settings` (checked against the episode's declared bindings). They are now the episode's own settings: `settings['cost']` (the cutoff) and `settings['parameters']`. `private_yield_binding=False` used to give no controller; the controller is now always built from the task. Controller: `verified_source_leads` accumulation; a source answer completion with target `credit_unit`. The completion credit cannot pass its target: screening and assessment each return at most one answer, so credit is at most one `credit_unit`.
- `evidence_processing` (`no_applicable_evidence`) was part of the old shared reasoning action; its schema is not in any episode file. It is declared in `task.py` (`EVIDENCE_PROCESSING`, an optional property of the `reason` tool for a screening task) as the old code's reading of it shows (`reason`, examined spans with source, representation, start, end); the old shared schema was not read.
- Tool names cannot contain dots: the library names (`source.read`, ...) are carried as `source_read`, ... (`LIBRARY_NAMES` in `task.py`); outcomes keep the library's shape. The model's tool arguments are wrapped by `action` into an envelope (`arguments`/`scope`/`page_source_ref`, and `proposed_annotation_ref` for `reason`) so that a tool, which is handed no summary, can apply the old source restriction and still return an `invalid` outcome that enters the iterator.
- The strict transport uses `strict_output_schema(..., open_records_as_text=False, ...)` (the A101 variant); the old `_ASSIGNMENT_TRANSPORT` is machinery and A102's own variant is not recorded in any episode file.
- The instruction text is the A102 `runtime_prompt.INSTRUCTIONS` (a head-level text). Three spans that describe deleted actions (the parent-written report form with `report_update`, `redeliver_report`, the decision-exchange history) are replaced in `task.py instructions`.
- Settings the episode reads: `cost` and `parameters` (yield controller), optional `tool_registry` (keyword arguments of `ToolRegistry`; `native_statistics` there makes `execution_estimate` available), optional `knowledge_library_directory`, optional `structure_population`.
- `selection` of the assignment (new form detail): the old schema was `anyOf` a table selector or a byte window, with `header_row` and `where` nullable. A `RecordForm` has no union and no null, so `selection` is one untyped `record` field and `read_from_parent` checks its exact shape (`check_selection`, `check_where`). Same for the table's `where` members.
- The `literature_table_sheet_mismatch` check (a `source.xlsx.rows` call must use the commissioned `sheet_key`) is a validation of the model's tool arguments, kept as `task.py admitted`; the tool is handed only its arguments, so `action` adds the key to the tool envelope as `sheet_key`.
- The sibling's wording "span by span" is `readings` here: the old table episode read rows and cells, not only byte windows, so a reading carries a free-text `locator` (sheet, rows, header, conditions, cells, footnotes or window) instead of `offset` and `limit`.
