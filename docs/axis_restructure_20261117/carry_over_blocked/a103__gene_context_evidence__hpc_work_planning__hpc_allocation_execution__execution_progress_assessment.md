## BLOCKED-ON-JOB-SERVICE
- `job_access.observe_progress(target_handle, fields, permitted_committed_record_types=..., operation_key=...)`: one observation of the assigned target, idempotent on `ctx.operation_key`, returning the `progress_snapshot_v1` record. Wanted call, in `task.observe_target` (raises `NotImplementedError('BLOCKED-ON-JOB-SERVICE: job_access; ...')`): `await ctx.services['job_access'].observe_progress(assignment['target_handle'], fields, permitted_committed_record_types=assignment['permitted_committed_record_types'], operation_key=ctx.operation_key)`. The old provider (`jobs/service_calls/gene_context_evidence/progress_provider.py`) stores observations by `store.db` in `a103_progress_observations`.
- `job_access.read('describe_progress_target', target_handle)`: the target descriptor (its optional `selected_observation_schema` makes `native_operation` an argument of `progress_observe`). Wanted call, in `task.describe_target` (raises BLOCKED at the first decision and the first action): `ctx.services['job_access'].read('describe_progress_target', target_handle)` as a recorded read.
- `job_access.read_progress(reference)`: a received observation the summary holds no snapshot of (a commissioner's `known_progress_refs` passed without `known_progress_snapshots`). Wanted call, in `task.snapshot_read` and `credit.snapshot_of` (credit has no services, so the check tool or the commissioner must supply the snapshot): `ctx.services['job_access'].read_progress(reference)`.
- `native_events` (the native event ledger as a service): `selected_wait(ctx.services['native_events'], condition)` in tool `wait_for_events` needs an object with `validate_event_targets` and `wait_events` (`NativeEventLedger`). No such service is supplied; a run that does not provide the factory fails at `link` (`service_required`).
- `estimate_table` (README 5 item 19): the old `decision_inputs` added execution expectations, resource tool estimates and native execution expectations for role `monitor` when an expectation binding was configured. Wanted call, in `task.execution_expectations` (reached only when `ctx.settings['execution_expectations']` is present; raises BLOCKED): `ctx.services['estimate_table'].read('execution_expectations', 'monitor')`. The service is not declared in `SERVICES` (no run can supply it yet).
- Job record kind: the old monitor kept each delivered observation in the provider's own table; MECHANICS section 6 wants a check row (`ctx.store.table(JOB_LEDGER).put({'job': ..., 'event': 'check', 'at': ..., 'detail': ..., 'source_ref': ...})`) so the observation travels in custody. No `JOB_LEDGER` declaration exists; the snapshots travel in the tool outcome and in the child's `monitoring_progress_snapshots` field instead (JSON, not records).

## Contract misfits
- new field: execution_progress_assessment information_unit (assignment; the old binding took it from its configuration and `credit(summary, records)` has no settings).
- new field: execution_progress_assessment known_progress_snapshots (assignment, optional; the old `known_progress_refs` named observations the old provider held, a commission carries no provider).
- new field: execution_progress_assessment monitoring_progress_snapshots (return, selectable; what a child monitor returns so that its parent's credit can read the delivered observations; the parent's `msg_to_child` selects it).
- Tool names cannot contain a dot: `progress.observe`, `progress.read`, `progress.log` are `progress_observe`, `progress_read`, `progress_log`.
- A form has no null type: `monitoring_execution_state`, `monitoring_result_available`, `monitoring_observed_at_unix_seconds` are `record` fields holding `{'value': ...}`.
- The old child admission and the old known-ref admission asked the progress provider (target in scope as an execution handle, known refs readable): no read-only provider operation is available to `read_from_parent` (it is handed no services), so only the same-target check of a passed snapshot is made there.
- The exposed direct dependencies (old `services.dependencies`, live from the provider) are now those of the latest delivered observation of the target, which has them only when `dependencies` was among the observed fields; the monitor child is offered only then.
- The old `wait` on pending in-process children and `redeliver_report` have no counterpart (a child completes inside its unit; one admitted result per commission). The wait on native events is the tool `wait_for_events` over the `native_events` service.
- The old rule requiring `monitoring_progress_refs` for a `gene_context_evidence` parent with an annotation task does not apply to this episode's parent (`hpc_allocation_execution`); the field is selectable and the parent (not yet carried) must select it.
- `monitoring_committed_record_refs` is a `record_refs` field: returning it requires the monitor to hold those records (`returned_record_not_held`), see BLOCKED-ON-STORE-ACCESS above.
- Settings this episode needs in its `continuation` entry: `cost` (>= 0, an accumulating controller never stops at cost zero) and `parameters` `{'uncertainty_alpha': (0, 1)}`; optional `launch_instructions_directory`, `knowledge_library_directory`, `execution_expectations`. Services `job_access` and `native_events` must be supplied to `link`.
- The tool reads no clock; the snapshots carry the provider's own `observed_at`. Two attempts of one unit (resume) produce observations that differ in that time (the service must be idempotent on `ctx.operation_key`).
- Credit is the information credit and is not bounded; credit is checked against the controller's last credit and raises `monitor_information_credit_cannot_decrease` when it would fall (old estimator rule moved into `credit.py` per README 7b). No completion target is involved (accumulation controller).
- Old `MonitorEpisode.required_return_sources`/`allowed_children`/`prepare_child_request` took the parent context; the commission now fails with `ContractError` (`monitor_child_target_not_exposed_direct_dependency`, `monitor_child_expands_permitted_record_types`) in `msg_to_child`, as a wrong commission.
