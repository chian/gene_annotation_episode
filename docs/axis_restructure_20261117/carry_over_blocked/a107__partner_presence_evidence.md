## contract_misfits

- new field: partner_presence_evidence scope, received_record_refs, finding_unit, handoff_unit, acquired_record_unit, information_unit (assignment form). `scope` and `finding_unit` replace what the old runner and the old yield binding held; `received_record_refs` names the records beyond `evidence_refs` (among them the scope's subjects, which the credit's `records.list('assessment', scope)` needs held); the three units are the old configuration values of the launch, results and monitor children, which the head now passes in their assignments (the old `evidence_task.credit_unit` stays in `context`, and `finding_unit` must agree with it: nothing checks it).
- type change, same name: `proposed_annotation_ref` is a `record_refs` field holding at most one reference (a form has no single-reference type), as `hpc_work_planning` did for `commission_source_ref`; `read_from_parent` raises when it holds more than one.
- new field (child side, filled by this head from its own parent input in `msg_to_child`): each child's `scope`, `finding_unit`, `received_record_refs`, `handoff_unit`, `acquired_record_unit`, `information_unit`, `scientific_task` and `version`; the model supplies only what the old model supplied (the objective, the purpose, the child's own assignment fields and `return_fields`). The `literature` child's and the recursive child's `received_record_refs` are every record the head holds (a pass carries only the records named).
- new field: the recursive child's `process_selection` and `revision_origin` (arguments of the commission): the old model copied `result.selection` and `revision_origin` from `process.revise` into the child's assignment; `msg_to_child` turns the canonical selection into the selector form the assignment takes (`selector_selection`).
- `process.revise`: the old parent invocation reference came from the old runner's path (`scientific_invocation_ref(run_id, path)`); `task.py` `process_revise` identifies it by run and Episode (`identity('scientific_invocation', {'run_id', 'episode_id'})`, same pattern). The old authentication of `revision_origin` against the parent's recorded preparation is a check of a commission and is not carried.
- The launch and results children declare about 83 and 82 selectable fields that are generated from library constants; `SELECTABLE` in `messages/msg_to_child.py` was read from their finished `final_to_parent.py` as data and is a copy of the names (the test checks the literal part of each child's form against it with `ast`; the generated part needs a runner test with both episodes linked, not written because it needs the carried library).
