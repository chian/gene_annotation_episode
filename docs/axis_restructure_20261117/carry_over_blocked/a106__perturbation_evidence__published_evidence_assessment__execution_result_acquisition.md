## CONTRACT MISFITS

- BLOCKED-ON-JOB-SERVICE: job ledger handoff record; wanted call: `ctx.store.table(JOB_LEDGER).get(handoff_ref)`.
- BLOCKED-ON-JOB-SERVICE: job_access; wanted call: `ctx.services['job_access'].api_result_catalog(target, selector)`.
- BLOCKED-ON-JOB-SERVICE: job_access; wanted call: `ctx.services['job_access'].api_result_operation(target, selector, operation, arguments, key=ctx.operation_key)`.
- BLOCKED-ON-JOB-SERVICE: job_access; wanted call: `await ctx.services['job_access'].api_wait(target, handle, after_cursor, reconsider_at)`.
- new field: execution_result_acquisition service (assignment, text). The old continuation read the service through the original target behind the handoff (BLOCKED-ON-JOB-SERVICE) and `yield_controller` is handed only the parent input; the parent copies the service of the job it handed off. It builds the profile key `results:api_<service>[_<selector version>]` (old key kept).
- `handoff_ref` is a `record_refs` field holding exactly one reference (a form has no single-reference type; `read_from_parent` raises `execution_results_one_handoff_required` otherwise). The old field was one text. `version` is a `DeclaredField` (`execution_results_assignment_v1`), as the old schema's `const`.
- finding (return, new): `FINDING_FORM` of `final_to_parent.py`: `handoff_ref`, `results_acquired`, `execution_completed`, `qualification`. The old episode had fact sources only.
- RETURN_FORM: `execution_result_refs` is required (the old `required_return_sources` returned it for the scientific parent); `execution_handoff_refs`, `execution_completed`, `bvbrc_appservice_support_refs` and `bvbrc_application_outcomes` are selectable. `bvbrc_application_outcomes` is a `list` field (array of objects; there is no typed array-of-objects field). The old condition (parent path ends in `perturbation_evidence` and `annotation_task_required()`) cannot be evaluated by a child; the field is required for every commission. The returned references are the artifacts the tool wrote through `ctx.store` (the system requires the Episode to hold every returned record), so `job_access` replies carry content, not references.
- yield controller: the old `PracticalYieldEstimator(verify_completion)` maps to completion (README 7b) only when the episode's own credit reaches a finite target exactly when the completion is verified. The number of results a selector yields is not known from the commission, so no target exists; accumulation is built (`AccumulationYieldController`, cost = the old profile `cutoff`). The exact zero forecast on a verified completion proof is not carried (the proof is not a controller input). "completion credit may pass its target" therefore does not arise. If the owner wants the completion controller, the parent must send the credit of a complete acquisition as a new assignment field.
- credit formula: `handoff_unit` x new handoff identities + `acquired_record_unit` x new result identities, against the initial handoff identity (the original handoff earns nothing). The old `operational_credit_from_identities` (old shared root, not read) is reconstructed from the intent record (counts of new unique handoff and result identities times the two units); the owner must check it. Credit is unbounded.
- the old refusal of a result action after a verified completion is a stop rule and is not carried: only the controller ends the Episode.
- settings read (`continuation` entry of the binding path): `task_yield_profiles` (`results:api_<service>[_<selector version>]` -> `cutoff` as controller cost, `parameters`), `handoff_unit`, `acquired_record_unit`, `initial_information` (old configuration value, shown to the model), `tool_knowledge_directory`, `launch_instructions_directory`. Old settings not read: `resources`, `log_window_bytes`, `log_roles`, `require_private_yield`.
- The tool is handed no summary: `action` wraps the model's operation arguments in an envelope with the original handoff and selector.
- The old wait offered through `permitted_common_actions` (`tool`, `wait`) is the tool `wait_for_service_job`, always offered.
- The old recorded-Results-commission restoration (`_recorded_results_assignment`) and the target/assignment re-check (`_context_target`, `_check_parent_inputs`) are old-runner machinery or checks of a commission and are not carried; a selector the service does not admit fails where the service is asked.
- credit.py is real code (not a stub); no `min`/`max` appears in credit.py or yield_estimator.py.
