# local_job_execution (A102): blocked, unplaced and contract misfits

## BLOCKED-ON-JOB-SERVICE

- BLOCKED-ON-JOB-SERVICE: `job_access`; wanted call: `ctx.services['job_access'].begin_command(assignment, run_id, episode_id, key, 'exec_command', command)` (the old `PracticalState.begin`: durable command intent, idempotent on the operation key, returns `{'state': 'new'|'pending'|'completed', 'intent', 'receipt'}`), then `await ctx.services['job_access'].execute_command(assignment, run_id, episode_id, key, 'exec_command', command)` (the old `TerminalExecution.execute`: the command run on the configured local resource or the coordinator, returns the outcome), then `ctx.services['job_access'].finish_command(assignment, run_id, episode_id, key, outcome, validations, context_after)` (the old `PracticalState.finish`: the immutable receipt). All three are in `task.py exec_command`. No service exists; the run cannot be linked until the caller supplies a `job_access` factory (`LinkError('service_required:...')`). The library classes behind it (`TerminalExecution`, `PracticalState`) are in `episode_support/jobs/` in their old form and are not wrapped.
- BLOCKED-ON-JOB-SERVICE: `estimate_table`; wanted call: `ctx.services['estimate_table'].read('resource_tool_estimates', 'launch_local')` in `task.py decide` (the old `resource_estimator.estimate_context(execution_expectations)` shown to the model as `resource_tool_estimates`; the old `execution_expectations` and `native_execution_expectations` capture is part of the same read). No estimate table exists (MECHANICS section "Not provided yet", item 2). The old estimator was optional; a declared service is not.

## BLOCKED-ON-STORE-ACCESS

- None for functions this episode calls. `task.py _publish_receipt` writes the receipt through `ctx.store` (`artifact`, `put('source', ..., origin='tool')` inside `transaction()`), which the old `PracticalReceiptInformation.publish` also did.
- function = `.../episode_support/records/practical_receipt_information.py::PracticalReceiptInformation`, pattern = "library not carried". It is not called: `publish(context, receipt)` needs the old `BindingContext` and `_selected` reads `runtime_actions` through `store.db` (`store.db.execute('SELECT action,result FROM runtime_actions ...')`, `sqlite_master` probes, `runtime_episodes`); the downstream reader (`read`, `resolve`) is the result-acquisition episode's. Intended replacement: the receipt source written as in `_publish_receipt`; the selected-action check is the system's attempts journal.

- The `report_update` the model wrote with every decision and its validation for grain `launch_local`: the parent writes no return form and this episode has no model-written return field; report machinery.

## CONTRACT MISFITS

- new field: local_job_execution scope (assignment, `record`): the old episode took the subject scope from its request.
- new field: local_job_execution input_refs (assignment, `record_refs`, optional): the records the job reads (protein-structure job inputs) which the old episode re-read from its parent's launch assignment. The parent must name every record the job reads, including the artifacts they name.
- new field: local_job_execution scientific_task (assignment, `record`, optional): the ancestor's `scientific_question` and `selected_tool_info` for a native protein-structure job (the old `services.scientific_parent_task` callback).
- new field: local_job_execution practical_receipt_artifact_refs (return, `record_refs`, required): the artifacts (receipt body, assignment snapshot) the receipt source records name; a pass carries only the records named, and a reader of a source reads its artifact.
- The assignment form has no `launch_instructions` alternatives beyond one open `record`, and `requested_job`, `progress_requirements`, `completion_keys`, `initial_context`, `inventory_snapshot`, `constraints` are open `record` or `list` fields (forms have no JSON-Schema alternatives, README section 5 item 11). `read_from_parent` runs the library's `validate_assignment` on them, which raises for an assignment it does not admit.
- Completion target (the old estimator had none, it had a proof check): the target is the total requirement credit of the assignment (`completion_target` in `read_from_parent`). The controller stops when every credited requirement is satisfied. Two cases do not coincide with the old completion proof: a completion key worth zero credit is not needed to reach the target, so the Episode can stop with `practical_completed` false; and when a completion proof verifies while a credited requirement outside `completion_keys` is still open, the target is not reached, the controller goes on, and the next command fails in the service (`practical_assignment_already_completed`). Credit cannot pass the target (credits are non-negative and the sum is over distinct keys), so no "completion credit may pass its target" case arises; `cost` must be below the target (`completion_cutoff_must_be_below_target`).
- `yield_estimator.py` reads `settings['task_yield_profiles']['launch_local:<class>']` = `{'cutoff', 'parameters'}` (the old `task_yield_profiles` entry; the cutoff is the controller's cost). The old `require_private_yield` flag is not carried.
- Settings the episode reads in `decide`/`action` (the old configuration): `resource` (the configuration of the assigned local resource, as `TerminalExecution` accepts it), `coordinator_workspace`, `initial_information` (inventory snapshots by resource id), `launch_instruction_directory`. The `job_access` service must be built from the same resource configuration.
- `execution_result_origin` is `null` in the old report when no result window exists; forms have no null, so the selectable field is a `record` and carries `{}` for none. `execution_handoff_refs`: the old test (`job_progress_provider.targets.returnable_handoff` over received and own receipts) has no current copy; it is carried as "this episode's own command receipts that satisfy a `requested_job_handoff` validation"; received handoffs do not exist (no children, the assignment passes none). `execution_result_refs`, `execution_file_source_refs`, `execution_file_capture_outcomes` are declared (old fact sources) and always empty: this episode acquires no result and captures no file.
- `decide` reads the launch instruction library from disk (`settings['launch_instruction_directory']`), the old frozen-library read; it is not a recorded service read. A resumed run asks for the same frozen library.
- Tool names cannot contain dots; `exec_command` is unchanged. The model's selection is the flat object `{cmd, workdir, target, env}` (env as a list of name/value items for a strict provider); the old selection wrapper with `tool` and `report_update` is gone.
- Initial baseline validations are assessed with the fixed instant `1970-01-01T00:00:00+00:00` (the instant the library's own `validate_validations` uses) because `read_from_parent` has no clock and the parent input must be reproducible on resume.
- The `exec_command` tool receives the assignment and scope in its arguments (built by `action` from the summary), because a tool is handed no summary.
