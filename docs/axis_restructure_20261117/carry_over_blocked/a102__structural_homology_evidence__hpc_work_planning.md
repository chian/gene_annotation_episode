Episode: `gene_annotation_episode/episodic_workflow/root/a102/structural_homology_evidence/hpc_work_planning`. Job episode (the owner of an HPC commission's ledger: it plans, launches, monitors and collects HPC work, directly with twelve tools or through five children). Five children, slots `hpc_prediction`, `hpc_execution`, `launch`, `monitor`, `results` (the old child roles). The old source was read from `gene_annotation_episode_disk` (`git show 97308b94c:<path>`); this working tree has no `.git`. It is carried the way its child `hpc_allocation_execution` is: the owner ledger is the library `HPCLedger` as written.

## UNPLACED OLD FUNCTIONS

- `from_parent.py HPCAssignment._tool_request` (carried as `task.py resolve_tool_request`, which raises `NotImplementedError('scientific_tool_library_required_for_hpc_tool_request')`): the old code resolved the request against `structural_homology_evidence_binding.tool_library` (the A102 head's `resolve_invocations` and `parent_tool_info`) reached through `services.workflow`, and raised that same error when the binding was absent. No library module holds the head's tool library and this episode may not reach another episode; so a commission with a `tool_request` fails at `hpc_initialize`.
- `decision_inputs.py HPCWorkDecisionInputs.decision_inputs` (parts): `completed_action_reports` and `requested_action_history` in the HPC form (`episode_work_report`, `library.hpc_prompt` of the old shared root, not read; replaced by the summary's `actions` over `view.outcomes`), `pending_work` (pending machinery), `execution_expectations`, `resource_tool_estimates` and `native_execution_expectations` (the resource estimator is not provided: only the `estimate_table` read above, README 5 item 19).
- `episode.py HPCEpisode.decision_prompt_renderer = render_hpc_prompt` (`library/hpc_prompt.py` of the old shared root, not read and not in `episode_support/`): the prompt is the JSON context built in `decide`.
- `waiting.py HPCActivityAdvice.activity_advice` (`hpc_activity_decision`: wait or collect advice read from the old estimator's journaled diagnostics) and `yield_estimator.py continuation_for_action`, `practical_estimator` (the pending-value forecast of `HPCContinuationEstimator`): deleted with the estimator (README 3d, 7b); nothing replaces them.
- `internal_summary.py` `hpc_launch_report_form` and `hpc_report_form` (the forms the old model repaired a report with): not carried (the system admits the child's result against its own form).

## CONTRACT MISFITS

- BLOCKED-ON-JOB-SERVICE: HPC ledger evidence record and HPC ledger credit record; wanted call: `records.table(HPC_LEDGER).select({'owner': owner})` (for `ledger_refs` of the prediction commission).
- BLOCKED-ON-JOB-SERVICE: job ledger handoff record; wanted call: `ctx.store.table(JOB_LEDGER).get(handoff_ref)`.
- BLOCKED-ON-JOB-SERVICE: job_access; wanted call: `await ctx.services['job_access'].observe_target(target, key=key, resumed=ctx.resumed)` (and `read_file`, `write_allocation_control`, `observe_queue`, `run_command`).
- BLOCKED-ON-JOB-SERVICE: estimate_table; wanted call: `ctx.services['estimate_table'].latest(resource, kind)` (and `observe`, `history`, `policy`, `record`, `read`).
- validate_form_not_built:A102: the old `validate_report` called `validate_form(form, original_schema, resolver)` first; A102 has no report-form validator, so `messages/final_to_parent.py validate_report` raises `NotImplementedError('validate_form_not_built:A102')` after its fact-agreement check, and `final_to_parent` raises every time it is reached (tested). The parent-written JSON-Schema form that call validated no longer exists.
- new field: hpc_work_planning scope (assignment, record; the old code took it from the request message), new field: hpc_work_planning input_refs (assignment, `record_refs`; the records the planned jobs read: the launch child's form requires them).
- `commission_source_ref` of the assignment is a `record_refs` field holding exactly one reference (`read_from_parent` raises `hpc_commission_source_ref_must_hold_exactly_one_reference` otherwise); the old field was a single text. `commission_id` is free text (the old `enum` came from the construction settings, which a form cannot read); exactly one of the two is required. `tool_request` must name all five keys (the old `obj` required all).
- new field (sent to the prediction child): hpc_resource_prediction ledger_refs and yield_binding (the commission's `yield_bindings['hpc_prediction']`); (sent to the execution sister): hpc_allocation_execution scope and input_refs; (sent to the launch child): execution_job_submission scope, input_refs, handoff_unit and already_handed_off_resource_ids. The launch child's form has no `hpc_execution_job` field, so what the old `LaunchPreparation.initial_decision_context` supplied rides in `ChildMessage.message`; the sister `hpc_allocation_execution/messages/msg_to_child.py` sends the launch child fields (`already_handed_off`, `hpc_execution_job`, `requests` as a list) that the launch child's current form does not have: this episode follows the child's form.
- the two sisters disagree on the ledger: `hpc_resource_prediction` reads the owner ledger as custody rows (`HPC_LEDGER`, `HPC_CREDITS`), `hpc_allocation_execution` opens the `HPCLedger` file by `settings['directory']`. This episode writes the file, so the execution sister can open it and the prediction sister cannot be given its records (above).
- the tools are handed no summary, so `action` adds `scope` to the arguments of every model-selected tool call, and `decide` adds `commission_identity`, `scope` and the tool request to `hpc_initialize`.
- `hpc_initialize` is a new tool: the old `state` and `initialize` ran as a side effect of the first decision context and of every `execute`; `decide` cannot write, so it offers `hpc_initialize` as the first unit (no model call). Credit before that unit is zero.
- the ledger a sister writes is read again by the unit after a commission of it: `decide` offers `hpc_read` of the commission when the last unit was `hpc_prediction` or `hpc_execution` (the old decision context read the ledger live at every decision). `credit` has no ledger: it takes the ledger credit from the last tool outcome, or from the `hpc_credit` the execution sister returned (its credit is that same ledger view; this is not a sum of children's credits). After an `hpc_prediction` unit the model credit it wrote shows only at the next unit, so that unit's marginal credit is understated.
- RETURN_FORM: `finding` is `FINDING_FORM` (accepted and remaining obligations, plans frozen and closed, results held, the credit components, a qualification). The four old fact sources `hpc_credit`, `hpc_model_ref`, `hpc_accepted_obligations`, `hpc_result_refs` are selectable (`required=False`); `hpc_model_ref` is text; `hpc_result_refs` is `record_refs` and returns the result sources only: a parent that reads their bytes also needs each source's artifact (decision T5), which the old fact did not name (no field is added).
- the old `hpc_report_form` the model repaired a report with and the old `report_update`/`report_values` are not carried: every old report field was a recorded fact, now selected by the parent.
- yield: `AccumulationYieldController('hpc_work_planning', initial_credit, settings['cutoff'], settings['parameters'])` (README 7b: `HPCContinuationEstimator` has no controller of its own; the credit is a signed measured gain with no maximum or target; the old commission `yield_bindings['hpc']` is the settings). The controller stops the Episode only when its cost (`cutoff`) is above zero and units stop earning. Completion credit does not apply, so "completion credit may pass its target" does not arise.
- `selection` of the commissions: `hpc_prediction` and `hpc_execution` select the four facts; `launch` selects `execution_handoff_refs` and `execution_completed`; `monitor` the seven `monitoring_*` fields the monitor's form declares (not `monitoring_dependency_handles`); `results` selects `execution_result_refs` and `execution_completed`. The `hpc_work_planning` parent of the old code took the typed form of each child under the same names.
- `a102/structural_homology_evidence/tests/test_model_run.py` (the head's test, not this episode's) still imports the deleted `hpc_work_planning/hpc_runtime.py`: it breaks until the head is carried. `hpc_work_planning/episode.py` of the earlier port (`HPCEpisode(HPCRuntime, A102ContractBinding)`) is replaced by `HPCWorkPlanning(EpisodeBinding)`; the head's `home.py` or registry, if it names `HPCEpisode`, fails the same way.
- the old tests of this episode bound shared old-root test classes and are retired; the new tests are structural and exercise the pure parts (form, controller, credit, commissions, report, blocked primitives): no real-runner test is possible while the ledger handoff record and both services are blocked.
