## BLOCKED-ON-STORE-ACCESS

- function = `gene_annotation_episode/episodic_workflow/episode_support/tools/structural_homology_evidence/tools.py::source.read` (the registry operation the old `progress.log` called), pattern = "library not carried" (raw Store registry). Old call `tools.execute_async('source.read', {source_ref, representation, offset, limit}, scope=..., operation_key=..., permitted_record_refs=[source_ref])` -> intended call `ctx.store.open_artifact(window['artifact_ref'])` with a seek and an exact byte read, after `ctx.store.get(window['source_ref'])` (the old representation/artifact match). `task.py progress_log` does this itself (an own few lines, not a copy of the library function); it needs the source and its artifact to be held (the commission must name both), else `CustodyError`.
- function = `gene_annotation_episode/episodic_workflow/episode_support/grading/structural_homology_evidence/progress_information_credit.py::ProgressInformationCredit`, pattern = none: it takes a reader with `read_progress(reference, scope)` and touches no Store; `credit.py` hands it a reader over the summary's snapshots.
- committed records: old `store.get(reference)['record_type'] in permitted` over the committed record refs of a snapshot -> intended `ctx.store.get(ref)['record_type']` (tools) and `view.records.get(ref)['record_type']` (`internal_summary`). The refs are records the job owner publishes; the episode does not hold them unless the commission names them, so the read raises `CustodyError` for an unheld one. The commission of the monitor (its parent's `msg_to_child`) must pass every committed record the target can expose in a `record_refs` field, and the assignment form has no such field: see "new field" below.

## CONTRACT MISFITS

- BLOCKED-ON-JOB-SERVICE: job_access; wanted call: `ctx.services['job_access'].observe_progress(...)` (see above).
- validate_form_not_built:A102: `messages/final_to_parent.py validate_report` checks the facts of the report against the recorded facts and then raises `NotImplementedError('validate_form_not_built:A102')` (A102 has no report-form validator, and the old `to_parent.py` called `validate_form`), so `final_to_parent` raises every time it is reached.
- new field: execution_progress_assessment information_unit (assignment: the old monitor took it from its configuration; `credit` needs it and has no settings).
- new field: execution_progress_assessment monitoring_progress_snapshots (return, selectable: the delivered snapshots by identity, which the commissioning monitor's `credit` needs because it has no services; the old parent read them through the shared progress provider).
- new field: execution_progress_assessment version (assignment, declared `monitor_assignment_v1`: the old schema's `version` property; the parent copies it).
- new field: execution_progress_assessment committed record refs the monitor may read (assignment `record_refs`): the old monitor read committed records of any permitted type from the shared Store; under custody they must be passed. Not added to the form (the old assignment had no such property); the parent's `msg_to_child` cannot pass them today.
- the old `null` facts (`monitoring_execution_state`, `monitoring_result_available`, `monitoring_observed_at_unix_seconds` without an observation) are `record` fields holding `{'value': ...}`: a form has no null.
- tool names: the old `progress.observe`, `progress.read` and `progress.log` are `progress_observe`, `progress_read`, `progress_log` (a tool name matches `[a-z][a-z0-9_]*`). The model's commission selection `monitor_dependency` carries `dependency_handle` (from the library mirror), not a nested assignment.
- progress observation identities and `known_progress_refs` are provider identities, not Store records: they travel in `list` fields, not `record_refs`, and are not custody. `monitoring_committed_record_refs` is `record_refs` (a read by the monitor already needed them held).
- the old `monitor_private_yield_binding_not_enabled` and the cutoff value check are kept in `yield_estimator.py` over `settings['cost']` and `settings['parameters']['uncertainty_alpha']`. Cost zero is allowed by the old check but an accumulating controller then never stops (the guide: the settings must give units a cost above zero); the settings of a run decide.
- the monitor's credit raises `monitor_information_credit_cannot_decrease` against the credit the controller last saw (old estimator behaviour moved into `credit.py` as README 7b says); the projection is monotonic by construction, so it cannot fire today.
- the old rule "when the parent is the axis head and an annotation task is required, the parent must request `monitoring_progress_refs`" belongs to that parent's `msg_to_child`; not this episode's file.
- the old goal text had two variants (with the monitor's own yield settings, or "the caller's monitoring projector and configured controller own credit and continuation"); only the first is carried: this episode always builds its own accumulation controller from its settings (an entry without them raises).
- the old `outcome_page_size` setting (paging of own outcomes) is not needed: every outcome is in the view.
