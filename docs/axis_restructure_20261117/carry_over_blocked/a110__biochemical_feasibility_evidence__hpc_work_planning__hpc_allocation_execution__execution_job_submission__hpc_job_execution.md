## Contract misfits
- new field: hpc_job_execution none. The old role read no record from the parent (`initial_references` was empty for `launch_hpc`), so no `record_refs` field is added. The job context the parent HPC binding added (`hpc_execution_job`: plan_id, objective, scientific_manifest, acceptance, supplied_input_file, coordinator_workspace, instructions) was the parent's `initial_decision_context`; here it can only arrive in `ChildMessage.message` (shown to the model as `message`), and a supplied input file the job needs would have to be passed as a record, which needs a `record_refs` field the old code did not have and no operation to stage its bytes on the resource.
- completion credit may pass its target: credit is the sum of all satisfied original requirements, the target is the credit of the completion keys only. A satisfied non-completion requirement before the completion keys are satisfied can lift the credit above the target; the controller then raises `ValueError('completion_credit_exceeds_target')`. The initial credit (requirements satisfied by the initial context) can also pass the target at controller build. The credit formula is the old one, unchanged.
- The old code had a completion proof, not a number (`PracticalYieldEstimator`); the target is new: the credit the completion keys earn, computed in `read_from_parent`.
- `execution_result_origin` was `null` for a launch and a form has no null type: declared selectable, selecting it raises `NotImplementedError('no_null_form_type:execution_result_origin')`.
- The old frozen closed credit ("later delivery never reprices it") has no counterpart; `completion['credit']` is returned.
- The frozen-request enum, the resource constraints of the launch parent and the pinned input versions are checks of a commission and not carried; the commissioning `launch` parent must copy its authorised request into the assignment (`msg_to_child`).
- The old `require_private_yield` flag (`execution_private_yield_binding_not_enabled`) is configuration machinery; the per-class profile selection (`launch_hpc:<request class>`, `{cutoff, parameters}`) is kept in `yield_estimator.py` and read from `settings['task_yield_profiles']`. Its cost must be above zero and below the completion target.
- `ctx.settings` of this episode must hold: `resources` (by resource id; the assigned one has kind `pbs_ssh`), `coordinator_workspace`, `task_yield_profiles`; optional: `initial_information`, `launch_instructions_directory`, `tool_knowledge_directory`. The service `job_access` must be supplied to `link`.
- The tool reads the real clock (`started_at`, `finished_at`, each validation's `checked_at`) and returns the receipt in its outcome; two attempts of one unit (resume) produce receipts that differ in those times. The summary's initial validations use a fixed stamp (`1970-01-01`) because a summary is pure; credit reads only satisfaction.
- The old model could read its own earlier outcomes through the decision-exchange `episode.history` lookup; that exchange is not carried. The model is shown a brief of every earlier command (`commands`) and the last one in full (`last_local_outcome`) at every decision instead; a history lookup tool is not written (the old catalogue offered `exec_command` only).
- The old `request_context` exchange text and the `pending_child_delivery` paragraph of the instructions describe actions that no longer exist and are not carried.
