# hpc_job_execution (A103, launch_hpc, below execution_job_submission): blocked, unplaced and contract misfits

## BLOCKED-ON-JOB-SERVICE

- BLOCKED-ON-JOB-SERVICE: the `job_access` service (scheduler, SSH transport, remote command execution; none wraps `TerminalExecution.execute` yet); wanted call: `await ctx.services['job_access'].exec_command(assignment, call, artifact_paths=paths, run_id=ctx.run_id, episode_id=ctx.episode_id, key=ctx.operation_key)` in `task.py exec_command`, returning the old terminal outcome (`{'facts': ..., 'native_outcome': ...}`), idempotent on `key` (a rerun of an unfinished unit must not run the command again; the old `PracticalState.begin` intent replay is gone). The episode declares `SERVICES = ('job_access',)`; a run without a factory for it fails at `link` with `LinkError('service_required:...')`. Nothing is stubbed. Whether the call is awaited is this episode's guess; the service owner decides.
- BLOCKED-ON-JOB-SERVICE: the job handoff record reader (old `job_progress_provider.targets._handoff_reader`, which decided which own practical receipts read as returnable handoffs); wanted call: `ctx.services['job_access'].handoff_refs(<own receipt refs>)`. `execution_handoff_refs` is declared in `RETURN_FORM`; `final_to_parent` raises `NotImplementedError('BLOCKED-ON-JOB-SERVICE: ...')` when it is selected.
- BLOCKED-ON-JOB-SERVICE: the job record kind (handoff, check, closure; `JOB_LEDGER` of the mechanics document): no module declares it. This episode writes only each command's receipt, as an artifact through `ctx.store.artifact`, and returns it in the tool outcome; it invents no job record kind.

## CONTRACT MISFITS

- BLOCKED-ON-JOB-SERVICE: `job_access` service; wanted call: `await ctx.services['job_access'].exec_command(assignment, call, artifact_paths=paths, run_id=ctx.run_id, episode_id=ctx.episode_id, key=ctx.operation_key)`
- BLOCKED-ON-JOB-SERVICE: job handoff reader; wanted call: `ctx.services['job_access'].handoff_refs(<own receipt refs>)`
- new field: hpc_job_execution assignment `version` (DeclaredField `practical_assignment_v1`) and `resource_kind` (DeclaredField `hpc`): the old schema fixed them by const; the parent copies them.
- new field: hpc_job_execution assignment `endpoint` is a ChoiceField (`usable_handoff`, `completed_job_outputs`) as the old schema's enum.
- new field: hpc_job_execution finding (return; the old report had none): `practical_completed`, `endpoint`, `completion_keys`, `satisfied_keys`, `receipt_count`, `failed_command_count`, optional `completion`.
- new field: hpc_job_execution settings the episode reads (`ctx.settings`): `resource` (the configured `pbs_ssh` resource), `coordinator_workspace`, `initial_information` (inventory), optional `launch_instruction_directory`, and `task_yield_profiles['launch_hpc:<request class>'] = {cutoff, parameters}` (old `cutoff` is the controller cost).
- new field: the tool arguments carry `assignment` and `context_before` added by `action` from the summary, because a tool is handed no summary.
- RecordForm field names must be lowercase identifiers: 21 old fact-source names with a dot (`execution.masking_*`, `execution.blast_utility_*`) cannot be declared under their old names (`final_to_parent.UNDECLARABLE`); "rename nothing" and the form rule conflict. They are masking/utility result families, empty for this role.
- Form types have no null: `execution_result_origin` (old `object` or `null`) is declared as a `list` (empty when no retained data); `launch_instructions` is an optional record (absent when the old value was null).
- completion credit may pass its target: it cannot. The target is the total credit of all progress requirements (`read_from_parent`), and the practical credit sums the currently satisfied requirement keys (`project_practical_credit`), so it never exceeds the target and the controller raises no `completion_credit_exceeds_target`. The old estimator verified a completion proof; the completion controller reads credit, so the controller does not stop exactly when the completion proof is verified if non-completion requirements remain unsatisfied: it then stops when its forecast falls to the cost (the proof stays in the summary, the finding and `practical_completed`).
- The old state refused any further command once the completion proof existed (`practical_assignment_already_completed`, "no further unit"). The new `action` always accepts a valid command (a decision that rejects every answer never produces a unit); after completion the controller alone ends the Episode.
- The old `begin`/`finish` intent replay and "unfinished intent requires reconciliation" are replaced by the system's attempts journal and `ctx.operation_key`; the idempotence of the command run depends on the `job_access` service (above).
- A103's `validate_form` exists but validated the old JSON-schema report form (x-source fields); the new `validate_report` checks the returned facts against the recorded facts and the receipts it names against the summary.
- Completion proof fields `run_id`, `episode_id`, `assignment_sha256` are taken from the last receipt (the old state held them itself).
