## CONTRACT MISFITS

- BLOCKED-ON-JOB-SERVICE: HPC ledger evidence record; wanted call: `reader.table(HPC_LEDGER).select({'owner': owner, 'id': identity})` (and the `kind` select and the `put`).
- BLOCKED-ON-JOB-SERVICE: HPC ledger credit record; wanted call: `reader.table(HPC_CREDITS).select({'owner': owner})`.
- BLOCKED-ON-JOB-SERVICE: job_access; wanted call: `await ctx.services['job_access'].observe_queue(configuration, key=ctx.operation_key, resumed=ctx.resumed)`.
- BLOCKED-ON-JOB-SERVICE: job_access; wanted call: `await ctx.services['job_access'].run_discovery(configuration['ssh_argv'], command, key=ctx.operation_key, resumed=ctx.resumed)`.
- BLOCKED-ON-JOB-SERVICE: estimate_table; wanted call: `ctx.services['estimate_table'].history(profile, now=now, queue_only=queue_only)` (and `latest`, `observe`, `read('as_record')`).
- validate_form_not_built:A102: the old `validate_report` called `validate_form(form, original_schema, resolver)` first; A102 has no report-form validator, so `messages/final_to_parent.py validate_report` raises `NotImplementedError('validate_form_not_built:A102')` after its fact-agreement check, and `final_to_parent` raises every time it is reached (tested). The parent-written JSON-Schema form that call validated no longer exists.
- new field: hpc_resource_prediction ledger_refs (assignment, `record_refs`; the parent-owned HPC ledger records this episode reads, passed in custody; the old ledger was a file opened by path under `<directory>/hpc/<digest(run_id, owner_episode_id)>/hpc.sqlite`).
- new field: hpc_resource_prediction yield_binding (assignment, required record `{cutoff, parameters}`; the old commission's `yield_bindings['hpc_prediction']`, which `yield_controller` cannot read from a ledger; the parent copies it from the commission).
- `commission_source_ref` of the assignment is a `record_refs` field holding exactly one reference (`read_from_parent` raises `hpc_prediction_one_commission_source_required` otherwise); the old field was a single text. `commission_id` is free text (the old `enum` came from the construction settings, which a form cannot read); exactly one of the two is required (`hpc_prediction_exactly_one_commission_required`).
- the old ownership and identity checks of the commission (`prepare_assignment`: parent role `hpc`, `owner_episode_id` equal to the parent's episode id, same commission identity; `state`: the ledger's owner record scope and commission identity equal to the assignment) are a check of a commission and are not carried; the old `scope` object does not exist (custody only), so the old scope comparison of `resolve_received_reference` is custody (`holds`).
- the tools are handed no summary, so `action` adds `owner_episode_id` (read from the summary) to the arguments of every model-selected tool call; the outcome keeps it.
- `hpc_initialize` is a new tool: the old `initialize` ran as a side effect of the first decision context and of every `execute`; `decide` cannot write, so it offers `hpc_initialize` as the first unit (no model call). Credit before that unit is zero (the formula's value: no entry row, no prediction made in this episode) and reads nothing.
- RETURN_FORM: `finding` is `FINDING_FORM` (`model_ref`, `model_quality_improvement`, `prospective_validation_credit`, `actual_job_credit_counted_here`: the old credit view and the selected model). The old fact sources `hpc_credit`, `hpc_model_ref`, `hpc_accepted_obligations`, `hpc_result_refs` are selectable (`required=False`); `hpc_model_ref` is text (a model identity is a ledger record, not a Store record); `hpc_result_refs` is `record_refs` and returns the result sources only: a parent that reads their bytes also needs each source's artifact (decision T5), which the old fact did not name (no field is added). `hpc_credit` is `completion['credit']` (the old fact was the same formula); `validate_report` compares it with the credit the summary computes from the ledger.
- the old `report_update`, `report_values` and `hpc_report_form` (the model's `x-source` report form) are not carried: every old report field was a recorded fact, now selected by the parent.
- yield: `AccumulationYieldController('hpc_resource_prediction', initial_credit, cutoff, parameters)` from `parent_input['yield_binding']` (README 7b: `HPCContinuationEstimator` has no controller of its own; the credit is a signed measured gain with no maximum or target). The controller stops the Episode only when its cost (the binding cutoff) is above zero and units stop earning. Not carried: `continuation_for_action` (the zero-continuation packet) and `practical_estimator`. Completion credit does not apply, so "completion credit may pass its target" does not arise.
- `hpc_shared_history_refs` is always in the summary (the old summary showed it only with shared memory configured, which a summary cannot read); `hpc_shared_memory` and `hpc_resource` are added by `decide` from the service read handle and the settings.
- the launch-instruction selection the old code read from `request.message['episode_assignment']['launch_instructions']` is read from `parent_input['message']['launch_instructions']`.
- the old tests of this episode bound shared old-root test classes and are retired; the new tests are structural and exercise the pure parts (form, controller, report, blocked primitives): no real-runner test is possible while the ledger and both services are blocked.
