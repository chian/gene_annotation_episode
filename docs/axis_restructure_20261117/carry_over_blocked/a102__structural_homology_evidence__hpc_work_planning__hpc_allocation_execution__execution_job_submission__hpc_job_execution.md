## CONTRACT MISFITS

- BLOCKED-ON-JOB-SERVICE: job_access; wanted call: `await ctx.services['job_access'].exec_command(assignment, command, key=ctx.operation_key, resumed=ctx.resumed)`.
- validate_form_not_built:A102: the old `validate_report` called `validate_form(form, original_schema, resolver)` first; A102 has no report-form validator, so `messages/final_to_parent.py validate_report` raises `NotImplementedError('validate_form_not_built:A102')` after its fact-agreement check, and `final_to_parent` therefore raises every time it is reached (tested). The parent-written JSON-Schema form that call validated no longer exists (the system admits the result exactly against the child's `RETURN_FORM`).
- completion target: repaired. `read_from_parent.completion_target` is the sum of the credits of all `progress_requirements` (what `credit.py` sums when every key is satisfied), so the credit reaches the target and cannot pass it. A target of zero or an initial credit at or above the target still fails the controller.
- completion credit may reach its target without a completion proof: the old completion needed every completion key satisfied and the last receipt to satisfy the endpoint predicate (`PracticalState._completion`); the controller stops at the credit target, which is reached when the keys are satisfied by any receipts. `practical_completed` can then be false in the return although the controller stopped (the finding says so).
- the completion controller stops an Episode the moment its credit reaches the target, but a requested endpoint that later loses an established fact lowers credit (signed): an episode already stopped does not see it.
- new field: hpc_job_execution completion_target (parent input, derived from `progress_requirements` by `read_from_parent`; the assignment has no such field).
- new field: hpc_job_execution task_yield_class (parent input, derived from `requested_job` and `endpoint`; the old `_request_yield_class` read the assignment in the yield estimator).
- new field: hpc_job_execution finding (return; the old episode returned the parent's requested JSON-Schema form filled from the model's report update and had fact sources only). Declared `FINDING_FORM`: `completed`, `endpoint`, `commands_run`, `commands_failed`, `satisfied_keys`, `qualification`.
- the parent's own assignment cannot be read by the child (README 5 item 14): the old admission (child choice among the parent launch's frozen HPC requests, `frozen_hpc_launch_request_missing`, the parent's `immutable_input_versions`, its protein-structure inputs, `allowed_resource_ids`/`allowed_kinds` constraints, the `launch_instructions` selection inherited from the parent launch) is not carried. The parent must copy the chosen request into this child's assignment in its `msg_to_child`; `launch_instructions` is an assignment field.
- `execution_result_origin` is `null` in the old facts when no result windows exist; a form has no null, so it is declared a `record` and returned as `{}`. The result fields (`execution_result_refs`, `execution_file_source_refs`, `execution_file_capture_outcomes`, `execution_result_origin`) are always empty: this role received no result or handoff records in the old `_received` and acquires no results.
- the old record `source` of provider `episode.practical_receipt` (identity-checked against the old runner's tables) is replaced by one artifact per receipt written by `ctx.store.artifact`; the old receipts were published at every report as well (`practical_receipt_refs` published all receipts in `facts`); now each receipt is published by its own unit.
- the old initial validations carried the wall clock of their assessment; the summary is a pure function of its view, so `internal_summary` stamps them with a fixed time (credit reads only satisfaction).
- the old `require_private_yield` switch (raising when off) has no new meaning: the profile `launch_hpc:<class>` of `settings['task_yield_profiles']` is always required.
- Settings the episode reads: `resource`, `initial_information` (optional), `coordinator_workspace`, `task_yield_profiles` (`{'launch_hpc:<class>': {'cutoff': cost, 'parameters': ...}}`), `launch_instructions_directory` (optional), `knowledge_library_directory` (optional). The `job_access` service is declared; the run's `services` collaborator needs a factory for it (a `LinkError` otherwise).
- the old own prompt renderer (`present_native_task`) required a `selected_execution_task` that this HPC copy never adds, so the old prompt was the plain JSON context; carried as `decide`'s context (see unplaced).
