## CONTRACT MISFITS

- BLOCKED-ON-JOB-SERVICE: job_access; wanted call: `ctx.services['job_access'].observe_progress(...)` (see above).
- `validate_form` is not called by `messages/final_to_parent.py validate_report`: A107 has `forms/partner_presence_evidence/communication.py validate_form(payload, schema, reference_resolver)`, but the parent writes no report schema now (README 3b C4), so there is no schema to apply; the system admits the result against `RETURN_FORM`.
- new field: execution_progress_assessment information_unit (assignment: the old monitor took it from its configuration; `credit` needs it and has no settings).
- new field: execution_progress_assessment monitoring_progress_snapshots (return, selectable: the delivered snapshots by identity, which the commissioning monitor's `credit` needs because it has no services).
- new field: execution_progress_assessment version (assignment, declared `monitor_assignment_v1`).
- new field: execution_progress_assessment committed record refs the monitor may read (assignment `record_refs`): under custody the committed records must be passed. Not added (the old assignment had no such property); the parent's `msg_to_child` cannot pass them today.
- new field: execution_progress_assessment scope: the old `observe_progress(..., scope, ...)` and `read_progress(ref, scope)` took the request's scope; the assignment has no scope property and none was added, so the wanted service calls omit it.
- the old `null` facts (`monitoring_execution_state`, `monitoring_result_available`, `monitoring_observed_at_unix_seconds` without an observation) are `record` fields holding `{'value': ...}`: a form has no null.
- tool names: old `progress.observe`, `progress.read`, `progress.log` are `progress_observe`, `progress_read`, `progress_log`. The model's child selection is `monitor_dependency` with `dependency_handle`, not a nested assignment (`known_progress_refs` of the child is always empty, its permitted types those of the parent).
- progress identities and `known_progress_refs` are provider identities, not Store records: `list` fields, no custody. `monitoring_committed_record_refs` is `record_refs`.
- direct dependencies are offered for commissioning only after an observation has returned them (old: `services.dependencies(target)` before any observation).
- `yield_estimator.py` keeps `monitor_private_yield_binding_not_enabled` and the cutoff/alpha value checks over `settings['cost']` and `settings['parameters']['uncertainty_alpha']`. Cost zero passes the old check but an accumulating controller then never stops; the run's settings must give units a cost above zero.
- the monitor's credit raises `monitor_information_credit_cannot_decrease` against the credit the controller last saw (old estimator behaviour moved into `credit.py`, README 7b); the projection is monotonic by construction, so it cannot fire today.
- the old rule "when the parent is the axis head and an annotation task is required, the parent must request `monitoring_progress_refs`" belongs to that parent's `msg_to_child`.
- the old goal text had two variants (own yield settings, or "the caller's monitoring projector and configured controller own credit and continuation"); only the first is carried.
- the old `outcome_page_size` setting is not needed (every outcome is in the view).
- the old `native_operation` argument of `progress.observe` is carried (offered only when the target description declares a `selected_observation_schema`); its translation `native_observation_options` lived in the deleted shared root, so the value is passed to the service as written.
- Tests: the old tests of this episode are scripted fakes on the old runner and are retired; the new `tests/test_binding_form.py` is real (import runs the class-definition checks; ten-file set; no import of another episode; forms; controller; commission).
