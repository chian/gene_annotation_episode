## Contract misfits

- new field: execution_job_submission handoff_unit; new field: execution_job_submission acquired_record_unit (the old code read both from its configuration; `credit` has no settings and the yield controller reads only the parent input); new field: execution_job_submission record_refs (the records the job inputs name, passed in custody); new field: execution_job_submission received_handoff_resources (the resources that already had a usable handoff: the old initial known handoff records); new field: execution_job_submission scientific_task (optional; the old `services.scientific_parent_task`). The commissioning parent (`hpc_allocation_execution`) must fill them. The old assignment's `launch_instructions` and the three old properties are kept under their names.
- `execution_handoff_refs` and `execution_completed` are required fields of `RETURN_FORM` (the old `required_return_sources` required `execution_handoff_refs` only under an annotation task parent; a conditional return source has no form). A parent therefore cannot select them (`selection_not_a_selectable_field`): they are always returned.
- `execution_result_origin` was `null` when no result window exists and a form has no null: declared as a `record`, selecting it raises `NotImplementedError('no_null_form_type:execution_result_origin')`.
- The native flux balance result fact sources (`fba_fact_sources()`, added when a native flux balance result adapter is configured) have no placed home: not declared.
- `validate_report`: the old body called the axis `validate_form(form, original_schema, resolver)`; A110 has no `validate_form`. The fact-agreement comparison runs and then `final_to_parent` raises `NotImplementedError('validate_form_not_built:biochemical_feasibility')`. Every return of this episode therefore raises until A110 gets one; it cannot return its result before that.
- Choice of controller (README 7b): the old `BoundedYieldController` becomes `BoundedQualityYieldController` (maximum = `handoff_unit` times the eligible requests without a handoff at the start, from `read_from_parent`); the intent record's suggestion of `CompletionYieldController` is not used because the old controller was a bounded quality with a maximum and the credit has no completion proof input. No "completion credit may pass its target" case: credit is `handoff_unit` times distinct resources that are permitted and not received, at most the maximum. When no eligible request remains the maximum and cost are 0 and a nonzero initial credit still raises (the old rule); the old exact-zero estimator is not carried.
- The old `PracticalYieldEstimator(verify_completion)` and the completion proof (`practical_completion_v1`) are not controller inputs (README 5 item 5) and are not carried.
- Reconstructed without the unread shared root: the resource keys shown by `execution_capabilities` (`workspace, policy, account, ssh_argv, python_executable, scheduler`, the keys of the configured transport), the profile key `launch:` + the sorted classes of the eligible requests joined by `+` (taken from the old `_launch_yield_controller`), and the child-kind slot table (the old `ROLE_KINDS`).
- The old reasoning-commit, wait and `redeliver_report` actions are not offered (the binding path is under the HPC work-planning ancestors where the old policy offered `tool, child, redeliver_report` only; the last two no longer exist). The model answers one `slot` and `resource_id`; the old selection wrapper with `report_update` is not used.
- `ctx.settings` of this episode must hold `resources` (resource id -> configuration, kinds `local` / `pbs_ssh`), `coordinator_workspace`, `task_yield_profiles` (`{'launch:<classes>': {'cutoff': cost, 'parameters': ...}}`) and optionally `initial_information`, `launch_instructions_directory`, `tool_knowledge_directory`. `decide` reads the two libraries from disk (not a recorded service read), as the child does. `settings` must give the units a cost above zero.
- The HPC child's `ASSIGNMENT_FORM` has no `record_refs` or `scientific_task` field, so `msg_to_child` does not send them to it (it cannot read the job's input records or the scientific parent task); the local child takes both. Admission of each commission by the child's real form is tested.
- `execution_capabilities` is `async def` only to match the other carried episodes; it reads settings only.
