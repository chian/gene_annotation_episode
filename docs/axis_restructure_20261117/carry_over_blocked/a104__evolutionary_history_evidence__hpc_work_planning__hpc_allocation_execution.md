## Contract misfits
- BLOCKED-ON-JOB-SERVICE: hpc_ledger.open; wanted call: `ctx.services['hpc_ledger'].open(owner_episode_id, scope, commission)` (see above): the whole episode is blocked on it.
- new field: hpc_allocation_execution scope (record): the old code read the scope from the commissioning request message, not from the assignment schema.
- new field: hpc_allocation_execution handoff_unit; new field: hpc_allocation_execution acquired_record_unit; new field: hpc_allocation_execution information_unit (numbers): the old episode took them from the configuration of the launch, results and monitor roles; the children's forms now require them in their assignments, and `msg_to_child` has only the summary.
- shape change: `commission_source_ref` (old: one reference as text) is a `record_refs` list of exactly one record (a custody field); `commission_id` stays text; exactly one of the two (the old `oneOf`) is checked in `read_from_parent`.
- Tool names: the old names (`hpc.read`, `hpc.monitor.wait`, ...) are lowercase identifiers now (`hpc_read`, `hpc_monitor_wait`, ...); the ledger keeps the old names in its own records (`LEDGER_NAMES`). New tool `hpc_state` (the initial lookup and the old `initialize`).
- Initial credit: the old controller read the ledger's credit at construction (`initial_credit`). `credit(summary, records)` has no services, so the credit before the first unit is 0.0; the first unit (`hpc_state`) brings the ledger's existing credit into the summary and the accumulation controller sees that existing credit as the first unit's gain. Wanted: either the initial credit in the assignment (a new field hpc_allocation_execution initial_credit) or a system way to price the first unit against the ledger.
- Controller kind: the intent record named completion with the remaining obligation credit as target. The credit here is the ledger credit (accepted actual results, model improvement and signed validation scores), which can pass the obligations' total, and a completion controller then raises `completion_credit_exceeds_target`; so README 7b's accumulation controller is used. Cost and parameters are `settings['cost']` and `settings['parameters']` (the old per-commission `yield_bindings['hpc_execution']` is not readable by `yield_controller`; wanted alternative: a new field hpc_allocation_execution yield_binding in the assignment).
- `message['hpc_execution_job']` (the old `initial_decision_context` the launch child received: plan id, objective, scientific manifest, scientific acceptance, supplied input file) is passed in the message of the `launch` commission; `execution_job_submission.read_from_parent` does not read its message, so it does not reach `hpc_job_execution`. Wanted: new field execution_job_submission hpc_execution_job (and the same in `hpc_job_execution`).
- A plan frozen in an earlier commission of this head has no supplied input file in this summary (`staged_inputs` come from this episode's `hpc_plan` units), so `action` refuses to launch it (`hpc_launch_requires_the_plan_frozen_by_this_episode`).
- Handoff custody: `execution_job_submission` returns `execution_handoff_refs` only; `hpc_handoff` reads the handoff record with `ctx.store.get` and passes it to `job_access.read_target`. If the target needs the handoff's artifacts, the child must return them as well (T5).
- Every tool outcome carries the full ledger decision state (`state`) because `internal_summary` and `credit` have no services; outcomes are larger than the old ones.
- The old `hpc_monitor_wait` tool sleeps in the process until the scheduled time (`MonitorCronController.wait`: `asyncio.sleep`), as before; the system has no wait (README 5 item 18).
- `hpc_report_form` and `hpc_launch_report_form` (JSON-schema forms with `x-source`) and the axis `validate_form` of the parent's form are not carried: the parent selects fields of `RETURN_FORM` (rule 5).
- `selection` to the monitor child names only the selectable facts the old head used (progress refs, target, state, availability, observation time); `monitoring_progress_snapshots` is for a commissioning monitor's credit and is not selected. `selection` to the results child is `('execution_completed',)`; selecting `execution_result_origin` raises in that child when it holds no windows.
- Outside this folder: `a104/evolutionary_history_evidence/runtime_bindings.py` (line ~386, hook-era home) still imports the deleted `hpc_work_planning.hpc_allocation_execution.binding.AllocationBinding`; it is not touched here.
