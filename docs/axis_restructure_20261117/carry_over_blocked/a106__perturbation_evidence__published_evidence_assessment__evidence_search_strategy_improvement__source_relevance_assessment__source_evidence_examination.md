## CONTRACT MISFITS

- new field: source_evidence_examination scope (assignment; the old episode took the Store scope from its request)
- new field: source_evidence_examination received_record_refs (assignment, record_refs; the old episode read context.received_record_refs). The parent must name the source, its artifact, the sources it derives from and the proposed annotation (and, for a lead, the lead's reference subject): `msg_to_child` passes exactly this list to each child.
- new field: source_evidence_examination finding (return; the old episode returned the parent-written form). The episode declares `written`, `interpretation`, `passages`, `qualification` and a `report` tool for the model's closing text. A106 is not an A105/A108 evidence episode, so no grader sheet is coupled here.
- new fields of the commission the model writes (ChildCall arguments, one per slot): `objective` (text), `message` (text), `selection` (the child's reading: table-or-window for `literature_table`, one window for `literature_ordered`, `spans` for `literature_targeted`). The old child action carried a child assignment, a sub-scope, a report contract and an initial report; the child's scope here is this episode's own scope.
- A child returns no `record_refs` (their `RETURN_FORM`s declare none). The assessment answer of an `answer_kind: assessment` task is a Store assessment: only assessments this episode wrote itself (through `reason`) are held and earn credit; assessments a child committed do not reach it. The old runner let the parent read records its children wrote in the same scope. The children would have to declare a `record_refs` field for changed assessments (`new field: <child> changed_assessment_refs`), which this episode cannot add. For `verified_source_leads` and `screening` the fact sources `literature_source_lead_dispositions` / `literature_screening_answers` carry the answers and are selected by `msg_to_child`.
- `msg_to_child` selects `literature_source_lead_dispositions` for a leads task, `literature_screening_answers` for a screening task and nothing for an assessment task (it names the children's selectable fields by their old names as literals; no check against the child).
- Tool names cannot contain dots: library names (`source.read`, ...) are carried as `source_read`, ... (`LIBRARY_NAMES` in `task.py`). Child slots keep the old role names (`literature_table`, `literature_ordered`, `literature_targeted`).
- The tool arguments are wrapped by `action` into an envelope `{'arguments', 'scope', 'page_source_ref', 'proposed_annotation_ref'}` so tools (handed no summary) can apply the page-source restriction.
- The table selection travels as one record with the fields of the other shape null (strict provider output has no optional field or union); `msg_to_child` drops the nulls (the child's form takes a field only when present).
- Settings read: `cost`, `parameters`, optional `tool_registry`, optional `knowledge_library_directory`.
- The old no-private-binding case is not carried: the controller is always built from the commissioned task (accumulation for verified_source_leads, completion otherwise).
- The base investigation text and reasoning-commit requirement are imported from the library `literature/prompts/perturbation_evidence/literature_investigation_prompt.py` instead of a private copy; GOAL imports `PERTURBATION_TASK` and the A106 sub-score `TASK` from the library (constants, not behaviour).
