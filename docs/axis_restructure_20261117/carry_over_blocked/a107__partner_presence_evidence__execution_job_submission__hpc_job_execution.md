## CONTRACT MISFITS

- BLOCKED-ON-JOB-SERVICE: job_access; wanted call: `await ctx.services['job_access'].exec_command(assignment, command, key=ctx.operation_key, resumed=ctx.resumed)`.
- the exec_command catalog (the old `operation_catalog('hpc')` of the old shared root's `library/execution_operation_information`) could not be read: the old shared root is not a source. `task.py EXEC_COMMAND` carries the text the carried `exec_command` catalogs of the sibling job episodes (A102) share; the old a107 `terminal_execution.py` names the tool `exec_command` with arguments `cmd`, `workdir`, `env`, `target`, which `TerminalExecution.validate_action` checks and the schema matches.
- the old fact sources of the role came from `fact_sources(role)` of the old shared root (`library/received_execution_information`), unreadable. `RETURN_FORM` declares what `terminal_execution.py` and `to_parent._live_facts` name: `practical_completed`, `practical_receipt_digests`, `practical_receipt_refs`, `execution_handoff_refs`, `execution_blast_hsps`, `execution_result_refs`, `execution_file_source_refs`, `execution_file_capture_outcomes`, `execution_result_origin`, `execution_completed`, and the three HMMER row families (`execution_hmmer_domain_rows`, `execution_nhmmer_locus_rows`, `execution_hmmalign_sequence_rows`). Not declared: the masking (`execution.masking_*`, 7) and BLAST utility (`execution.blast_utility_*`, 14) sources, because their names contain a dot and a form's field names are `[a-z][a-z0-9_]*` ("rename nothing" cannot hold); and the families the old code returned only when an adapter was configured (RNA structure comparison and structure results, expression NMF, Infernal and Infernal preparation, standard and native BLAST database, HMMER preparation, pairwise BLAST result refs and rows, `bvbrc_appservice_support_refs`): a form is fixed at class definition and cannot depend on configuration.
- validate_report: the old first step `validate_form(form, original_schema, resolver)` validated the parent-written JSON-Schema form with `x-source` fields; that form no longer exists (the system admits the result exactly against `RETURN_FORM`, and a parent writes no form). It is not called (the axis has `forms/partner_presence_evidence/communication.validate_form`, but it needs a schema nobody supplies). Only the fact-agreement body is carried (`execution_report_disagrees_with_recorded_facts`). The adapter `validate_received_report` calls belong to result acquisition.
- completion credit may pass its target: the target is the credit the completion keys earn (`read_from_parent.completion_target`, new: the old code had a completion proof and no number), but the old credit counts every satisfied requirement key, including ones outside `completion_keys`; when such a key is satisfied as well the credit exceeds the target and the controller raises `ValueError('completion_credit_exceeds_target')`. A target of zero or an initial credit at or above the target also fails the controller.
- completion credit may reach its target without a completion proof: the old completion needed every completion key satisfied and the last receipt to satisfy the endpoint predicate; the controller stops at the credit target, which is reached when the keys are satisfied by any receipts. `practical_completed` can then be false in the return although the controller stopped (the finding says so).
- the completion controller stops an Episode the moment its credit reaches the target, but a requested endpoint that later loses an established fact lowers credit (signed): an episode already stopped does not see it.
- new field: hpc_job_execution completion_target (parent input, derived from `progress_requirements` and `completion_keys` by `read_from_parent`; the assignment has no such field).
- new field: hpc_job_execution task_yield_class (parent input, derived from `requested_job` and `endpoint`; the old `_request_yield_class` read the assignment in the yield estimator).
- new field: hpc_job_execution finding (return; the old episode returned the parent's requested JSON-Schema form filled from the model's report update and had fact sources only). Declared `FINDING_FORM`: `completed`, `endpoint`, `commands_run`, `commands_failed`, `satisfied_keys`, `qualification`.
- the parent's own assignment cannot be read by the child (README 5 item 14): the old admission (the child's choice among the parent launch's frozen HPC requests, `frozen_hpc_launch_request_missing`, the parent's `immutable_input_versions`, `allowed_resource_ids`/`allowed_kinds`, the native input checks) is not carried. The parent must copy the chosen request into this child's assignment in its `msg_to_child`; `launch_instructions` and `scientific_manifest` are optional assignment fields.
- `execution_result_origin` is `null` in the old facts when no result windows exist; a form has no null, so it is a `record` returned as `{}`. The result fields are always empty: this role received no result or handoff records in the old `_received` and acquires no results.
- the old record `source` of provider `episode.practical_receipt` is replaced by one artifact per receipt written by `ctx.store.artifact`; the old receipts were also published at every report; now each receipt is published by its own unit.
- the old initial validations carried the wall clock of their assessment; the summary is a pure function of its view, so `internal_summary` stamps them with a fixed time (credit reads only satisfaction).
- the old `require_private_yield` switch has no new meaning: the profile `launch_hpc:<class>` of `settings['task_yield_profiles']` is always required.
- Settings the episode reads: `resource`, `initial_information` (optional), `coordinator_workspace`, `task_yield_profiles` (`{'launch_hpc:<class>': {'cutoff': cost, 'parameters': ...}}`), `launch_instructions_directory` (optional), `knowledge_library_directory` (optional). The `job_access` service is declared; the run's `services` collaborator needs a factory for it (`LinkError` otherwise).
- the old files of this folder carry traces of the a110 copy (`presentation.py` docstring "Complete A110 native presentation", imports of `root.a110...` in `presentation.py`, `task_report.py`, `task_state.py`, `waiting.py`, `received_execution_information.py`); they were machinery or unplaced either way.
- the git history was read from `/home/chia/repos/gene_annotation_episode_disk` (the working copy under `/home/chia/repos/gene_annotation_episode` has no `.git`). The folder held a hook-era `runtime.py` (deleted in step 2); the head `a107/partner_presence_evidence/episode.py` and other folders still import it (`HpcJobExecutionRuntime`), which now fails: for their agents.
