## CONTRACT MISFITS

- BLOCKED-ON-JOB-SERVICE: job ledger handoff record; wanted call: `ctx.store.table(JOB_LEDGER).get(handoff_ref)`.
- BLOCKED-ON-JOB-SERVICE: job_access; wanted call: `await ctx.services['job_access'].observe_target(target, key=ctx.operation_key, resumed=ctx.resumed)`.
- BLOCKED-ON-JOB-SERVICE: job_access; wanted call: `await ctx.services['job_access'].read_file(target, path=..., offset=..., limit=..., key=key, resumed=ctx.resumed)`.
- validate_form_not_built:A102: the old `validate_report` called `validate_form(form, original_schema, resolver)` first; A102 has no report-form validator, so `messages/final_to_parent.py validate_report` raises `NotImplementedError('validate_form_not_built:A102')` after its fact-agreement check, and `final_to_parent` raises every time it is reached (tested). The parent-written JSON-Schema form that call validated no longer exists (the system admits the result exactly against the child's `RETURN_FORM`).
- new field: execution_result_acquisition acquired_record_unit (assignment; the old configuration value of that name, which `credit(summary, records)` cannot read from settings; the parent copies it into the commission).
- new field: execution_result_acquisition known_result_refs (assignment, optional `record_refs`; the result records the parent already holds, which the old binding context knew as its initial known records and whose bytes earn nothing).
- `handoff_ref` is a `record_refs` field holding exactly one reference (a form has no single-reference type; `read_from_parent` raises `execution_results_one_handoff_required` otherwise). The old field was a single text.
- `version` of the assignment is a `DeclaredField` (`execution_results_assignment_v1`), as the old schema's `const`.
- tool names: the old `execution.results.status`, `.collect`, `.read` are `execution_results_status`, `execution_results_collect`, `execution_results_read` (a tool name is `[a-z][a-z0-9_]*`). The result body version is `execution_result_information_v3` (the old `scope` field is gone: there is no scope object, only custody).
- finding (return, new): `FINDING_FORM` of `final_to_parent.py`: `completed`, `requested_paths`, `results_acquired`, `windows_acquired`, `acquisition_failures`, `uncovered_paths`, `qualification`. The old episode had fact sources only. Not an A105/A108 evidence episode, so no investigation finding.
- RETURN_FORM fact sources: all selectable (`required=False`). The old `required_return_sources` required `execution_result_refs` only when the parent was the axis head `structural_homology_evidence` and its services said an annotation task was required (a run-time condition of the head, which a return form cannot state); this episode's parent is that head, which selects `execution_result_refs` in its commission. `execution_result_origin` is the empty record where the old value was `null`; the file-source and protein-structure facts are declared and always empty.
- the old maximum of the finite-selector bounded controller, `acquired_record_unit x (1 - fraction already received)`, needs the known results read; `yield_controller` is handed no records. The maximum is `acquired_record_unit` (the credit of a wholly new selector). When known bytes exist the maximum is not reached and the controller stops when units stop earning (its cost, from `settings`, above zero). The old exact-zero forecast and the practical endpoint estimate on a verified completion proof are not carried.
- the old estimators of the API and typed targets (`PracticalYieldEstimator` with a completion proof) would map to completion (README 7b); no completion controller is built because those selectors are not carried. "completion credit may pass its target" therefore does not arise.
- the settings keys read by `yield_estimator.py` keep the old profile names with the kind taken from the commission's `resource_kind` (`local` or `hpc`): `settings['results_yield_profiles']['native_unbounded_<kind>']` and `settings['task_yield_profiles']['results:native_finite_<kind>']`, each `{'cutoff': cost > 0, 'parameters': {...}}`. Other settings read: `log_window_bytes` (required by the tools), `resource` and `initial_information` (optional, shown to the model), `launch_instructions_directory`, `knowledge_library_directory` (optional).
- the old refusal of a result action after a verified completion (`execution_results_assignment_already_completed`) is a stop rule and is deleted: only the controller ends the Episode. After the requested bytes are covered, credit reaches the controller's maximum (when no bytes were known) and it stops; `execution_completed` in the return is `false` when the covered bytes were not observed from a successful (completed, return code 0) attempt although the controller stopped.
- `execution_handoff_refs` is the assignment's handoff once a unit has read its target (the old code asked the provider whether the handoff is returnable); the target is shown to the model from the first acquired result (the old summary showed it from the first decision), because reading it is blocked.
- the old immutable intent / observation / window / receipt files, saved-action row check and the recorded-commission restoration are machinery: the system journals the unit and a rerun is idempotent on `ctx.operation_key` (the service must keep the observation and each window read idempotent on its key).
- credit.py is real code (not a stub); the `min`/`max` calls in it measure byte intervals (old code) and do not limit the credit.
- new field: execution_result_acquisition resource_kind (assignment, `ChoiceField` local or hpc; the old continuation read the target's `resource_kind` through the handoff, which is BLOCKED-ON-JOB-SERVICE, and `yield_controller` is handed only the parent input; the parent copies the kind of the job it handed off). The API kind is not carried (its selectors are listed above).
