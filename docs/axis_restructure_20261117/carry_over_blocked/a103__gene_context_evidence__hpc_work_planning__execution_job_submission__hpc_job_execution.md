# hpc_job_execution (A103, launch_hpc): blocked, unplaced and contract misfits

## BLOCKED-ON-JOB-SERVICE

- BLOCKED-ON-JOB-SERVICE: the `job_access` service (scheduler, SSH transport, remote command execution; none wraps `TerminalExecution.execute` yet); wanted call: `await ctx.services['job_access'].exec_command(assignment, call, artifact_paths=paths, run_id=ctx.run_id, episode_id=ctx.episode_id, key=ctx.operation_key)` in `task.py exec_command`, returning the old terminal outcome (`{'facts': ..., 'native_outcome': ...}`), idempotent on `key` (a rerun of an unfinished unit must not run the command again; the old `PracticalState.begin` intent replay is gone). The episode declares `SERVICES = ('job_access',)`; a run without a factory for it fails at `link` with `LinkError('service_required:...')`. Nothing is stubbed. Whether the service call is sync or awaited is a guess of this episode (`await`); the service owner decides.
- BLOCKED-ON-JOB-SERVICE: the job handoff record reader (old `job_progress_provider.targets._handoff_reader`, which decided which own practical receipts "read as returnable handoffs"); wanted call: `ctx.services['job_access'].handoff_refs(<own receipt refs>)`. `execution_handoff_refs` is declared in `RETURN_FORM`; `final_to_parent` raises `NotImplementedError('BLOCKED-ON-JOB-SERVICE: ...')` when it is selected.
- BLOCKED-ON-JOB-SERVICE: the job record kind (handoff, check, closure; `JOB_LEDGER` of the mechanics document): no module declares it. This episode writes only each command's receipt, as an artifact through `ctx.store.artifact`, and returns it in the tool outcome; it invents no job record kind.

- function = `gene_annotation_episode/episodic_workflow/episode_support/records/practical_receipt_information.py::PracticalReceiptInformation` (`publish`, `read`, `resolve`), pattern = "library not carried". Old call -> intended call: `PracticalReceiptInformation(store, run_id).publish(context, receipt)` (takes the old `BindingContext`, reads `store.db` (`records`, `sqlite_master`), `runtime_actions` and `runtime_episodes`, and `store.put('source', ...)`) -> a custody `ctx.store.put('source', payload, origin='tool')` after `ctx.store.artifact(...)`. Not called by the episode: only `TerminalExecution.validate_action` (pure) is called, from `action`; the execution is the `job_access` service's.

- `contracts.py launch_operation_catalog`, `native_result_operation_catalog`, `internal_summary.py NativeSummary._resource_information`, `capabilities`, `resource_tool_contracts`: catalogues and capability listings of the launch parent and the results role, not operations of launch_hpc; the only tool of this role is `exec_command`.
- `decision_presentation.py present_native_task` renderer text (`render_hpc_prompt`, `is_hpc_context`, `render_selected_execution_prompt`): lived in the old shared root (`library.hpc_prompt`), which is not read or restored; the model request carries its context as a mapping and the instruction text of this role is in `task.py INSTRUCTIONS`.
- `from_parent.py` checks of the commission against the parent (parent launch re-validation, masking and utility inputs, immutable input versions, native BLAST database input validation): checks of a commission; a wrong commission fails.
- API-service fact sources that depend on the old configuration (`uniprot_fact_sources`, `_appservice_sources`, `minhash_fact_sources`, `execution_file_source_refs`, `execution_file_capture_outcomes` of role `results`): not declared for launch_hpc (conditional on `api_execution`, or results-role only). The old `empty_facts()` of the native BLAST database result modules is not in the library: object-typed sources return `{}`.

## CONTRACT MISFITS

- BLOCKED-ON-JOB-SERVICE: `job_access` service; wanted call: `await ctx.services['job_access'].exec_command(assignment, call, artifact_paths=paths, run_id=ctx.run_id, episode_id=ctx.episode_id, key=ctx.operation_key)`
- BLOCKED-ON-JOB-SERVICE: job handoff reader; wanted call: `ctx.services['job_access'].handoff_refs(<own receipt refs>)`
- new field: hpc_job_execution assignment `version` (DeclaredField `practical_assignment_v1`) and `resource_kind` (DeclaredField `hpc`): the old schema fixed them by const; the parent copies them.
- new field: hpc_job_execution assignment `endpoint` is a ChoiceField (`usable_handoff`, `completed_job_outputs`) as the old schema's enum.
- new field: hpc_job_execution finding (return; the old report had none): `practical_completed`, `endpoint`, `completion_keys`, `satisfied_keys`, `receipt_count`, `failed_command_count`, optional `completion`.
- new field: hpc_job_execution settings the episode reads (`ctx.settings`): `resource` (the configured `pbs_ssh` resource), `coordinator_workspace`, `initial_information` (inventory), optional `launch_instruction_directory`, and `task_yield_profiles['launch_hpc:<request class>'] = {cutoff, parameters}` (old `cutoff` is the controller cost).
- new field: the tool arguments carry `assignment` and `context_before` added by `action` from the summary, because a tool is handed no summary.
- RecordForm field names must be lowercase identifiers: 21 old fact-source names with a dot (`execution.masking_status`, `execution.masking_artifacts`, `execution.masking_quantities`, `execution.masking_checks`, `execution.masking_statistics`, `execution.masking_failures`, `execution.masking_saved_data`, `execution.blast_utility_status`, `execution.blast_utility_sequences`, `execution.blast_utility_database_fields`, `execution.blast_utility_integrity`, `execution.blast_utility_preparation`, `execution.blast_utility_prepared_database`, `execution.blast_utility_checks`, `execution.blast_utility_failures`, `execution.blast_utility_missing`, `execution.blast_utility_artifacts`, `execution.blast_utility_saved_data`, `execution.blast_utility_paths`, `execution.blast_utility_path_sections`, `execution.blast_utility_vdb_context`) cannot be declared under their old names (`final_to_parent.UNDECLARABLE`); "rename nothing" and the form rule conflict. They are masking/utility result families, empty for this role.
- Form types have no null: `execution_result_origin` (old `object` or `null`) is declared as a `list` (empty when no retained data); `launch_instructions` is an optional record (absent when the old value was null).
- Completion target: the old estimator verified a completion proof; the completion controller reads credit. The target is the total credit of all progress requirements (`read_from_parent`), which the practical credit cannot pass (it sums satisfied requirement keys), so the controller will not raise `completion_credit_exceeds_target`. Consequence: the controller does not stop exactly when the completion proof is verified if non-completion requirements remain unsatisfied; it then stops when its forecast falls to the cost (the completion proof is still in the summary, the finding and `practical_completed`).
- The old `begin`/`finish` intent replay and "unfinished intent requires reconciliation" are replaced by the system's attempts journal and `ctx.operation_key`; the idempotence of the submission depends on the `job_access` service (above).
- A103's `validate_form` exists but validated the old JSON-schema report form; the new `validate_report` checks the returned facts against the recorded facts and the receipts it names against the summary.
