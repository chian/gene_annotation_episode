## CONTRACT MISFITS

- BLOCKED-ON-JOB-SERVICE: job_access; wanted calls as above (read `target`, `target_description`; `observe_target`, `read_file`).
- BLOCKED-ON-JOB-SERVICE: JOB_LEDGER handoff and closure records, `estimate_table.add`.
- new field: execution_result_acquisition resource_kind (the kind of the handed-off resource, which the old code read from the handoff target).
- new field: execution_result_acquisition workspace (the workspace the requested paths are confined to; the old code read it from the handoff target).
- new field: execution_result_acquisition acquired_record_unit (the old configuration value; `credit.py` reads it from the parent input through the summary, `yield_estimator.py` uses it as the bounded-quality maximum).
- new field: execution_result_acquisition initial_result_refs and initial_result_artifact_refs (the old `initial_known_record_refs`; a passed record does not bring the records it names, so the parent names each result source and its artifact).
- `handoff_ref` is a `record_refs` field holding exactly one reference; the old value was text. Custody needs a record reference; `read_from_parent` raises `execution_results_one_handoff_required` otherwise.
- Tool names: the old operations `execution.results.status|collect|read` contain dots; tool names are `[a-z][a-z0-9_]*`, so the tools are `execution_results_status`, `execution_results_collect`, `execution_results_read`. Fact sources with a dot (`execution.masking_*`, `execution.blast_utility_*`) become fields with an underscore in its place. "Rename nothing" cannot hold for them.
- Yield profiles: the old profile tables were keyed by resource kind and task (`results_yield_profiles['native_unbounded_<kind>']`, `task_yield_profiles['results:native_finite_<kind>']`), with `cutoff` as the controller cost. They are carried as keys of this episode's settings entry (`settings['results_yield_profiles']`, `settings['task_yield_profiles']`, each profile `{'cutoff', 'parameters'}`; the cutoff is passed as the controller cost); the resource kind comes from the new assignment field.
- The finite-selector controller is bounded quality with maximum `acquired_record_unit`; the old maximum was `acquired_record_unit * (1 - fraction already known)`, which needs the held earlier results, and `yield_controller` receives only the parent input. The credit never exceeds the unit, so the controller's maximum is not a clamp. Old exact-zero forecast when nothing remains uncredited: not carried (only the controller stops the Episode).
- The old `PracticalYieldEstimator` completion-proof endpoint (verified completion -> zero further gain) has no replacement: the completion proof is not a controller input (README 5 item 5). Completion is the `completed` flag of the summary and the `execution_completed` field of the result.
- The old type of `execution_result_origin` is a record or `None`; a form has no null. When no window was retained the field is not returned and selecting it raises `a_generic_native_acquisition_has_no_value_for:execution_result_origin`.
- `validate_report`: the old first step `validate_form(form, original_schema, resolver)` over the parent-written JSON-Schema form, the adapter `validate_received_report` calls and the frozen-facts branch of UniProt are not carried (that form no longer exists; the system admits the result against `RETURN_FORM`). Only the facts-agreement body is carried (`final_to_parent.validate_report`).
- Where the axis has no `validate_form` call this episode needs: none (the episode calls none).
- Completion credit may pass its target: not applicable (accumulation or bounded quality, no completion target). The bounded-quality maximum is the unit and credit is `unit * mean newly covered fraction`, at most `unit`.
- The wait action of an API target is not carried (no wait in the system); API targets raise in `read_from_parent`.
- The settings keys `log_window_bytes`, `results_yield_profiles`, `task_yield_profiles` (and optional `knowledge_library_directory`) are read from this binding's entry of `continuation`; `parameters` of a profile is the controller's `settings` argument.
