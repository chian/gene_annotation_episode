# resource_work_submission (A101): blocked, unplaced and contract misfits

Episode: `gene_annotation_episode/episodic_workflow/root/a101/sequence_homology_evidence/resource_work_submission`. Old role `launch`; commissions the three resource children (slots `launch_api`, `launch_hpc`, `launch_local`, the old role names). Its pieces: resource tools (capabilities, inspect, check handoff), a typed reasoning commit, two library lookups, and the child commissions. Controller: accumulation.

- Handoff record kind: the adapters wrote handoff records straight into the old Store (`check_record_refs`, `handoff_receipt`). The episode returns what the children returned in custody (`execution_handoff_refs`); no handoff record library exists.
- Linking a run of this episode raises `LinkError('service_required:...')` until the run supplies a factory for `resource_adapters`.

## CONTRACT MISFITS

- new field: resource_work_submission scope (assignment; the old request scope: the API and local children are commissioned within it and the reasoning commit names it)
- new field: resource_work_submission scope_refs (assignment, `record_refs`; the records the scope names, passed on to the API child)
- new field: resource_work_submission input_refs (assignment, `record_refs`; the records of the immutable input versions, passed on to the API and HPC children)
- new field: resource_work_submission completion_target (assignment; the credit one usable execution handoff earns: the API child's own `completion_target`, and the unit of this episode's credit)
- new field: resource_work_submission finding (return; the old episode returned the parent's requested JSON-Schema form). `FINDING_FORM`: `commissions`, `usable_handoffs`, `unavailable_checks`, `resource_availability`, `qualification`.
- new field: resource_work_submission adapter_facts (return, selectable; the adapters' own fact sources, whose names are not known at class definition) and execution_handoff_refs (return, selectable `record_refs`; the handoff records the children returned in custody).
- The old HPC rule ("an HPC return form must contain `execution_handoff_refs`") is met by the HPC child's required `handoff_refs`: the HPC child declares no `execution_handoff_refs` (the API child does) and `handoff_refs` cannot be selected, so the parent cannot ask for the old name from the HPC child.
- The three children declare their handoff facts in different shapes: the API and HPC children `execution_handoff` as a record (`{}` for none), the local child as a list of zero or one. `read_from_child` therefore reads only `execution_handoffs`, which all three declare.
- The local child declares no `record_refs` field in its assignment and none in its return: the parent cannot pass it the input or scope records (it receives `scope` in the message, as the child reads it there) and receives no handoff records from it. Its handoffs are values only.
- The adapter's tool catalogue and the three fixed tools: tool names cannot contain a dot, so the model-facing names (`resource.capabilities`, `resource.inspect`, `resource.check_handoff`) map in `action` to the tools `resource_capabilities`, `resource_inspect`, `resource_check_handoff`.
- Assumption about the adapter reply: a handoff is `result['execution_handoff']` of the `resource_check_handoff` reply (an `execution_handoff_v1` record), as in the sibling resource episodes; the old code did not show where the adapter put it.
- Controller choice: accumulation (README 7b; the old file named none). Credit is `completion_target` times the number of distinct usable handoffs; the commission fixes no total, so completion has no target (a target of one handoff could be passed by a child returning several, and the controller would raise `completion_credit_exceeds_target`). Settings the episode reads: `cost` (above zero, or the controller never stops), `parameters`, optional `tool_knowledge_directory` and `launch_instructions_directory`. The old credit was `services.bound_role_credit` (the adapters' `credit_view`), defined outside this folder; the new credit is the count of usable handoffs the tools and children returned (an owner decision to confirm).
- The old `reason` action is carried (`reason` tool over `ctx.store.commit_reasoning`), though a resource launch has little to reason about: the old `permitted_common_actions` listed it. `evidence_processing.kind = no_applicable_evidence` is kept as the exception to the empty-commit rejection, as in the sibling resource episodes.
- The model's answer to a commission is `kind: episode_child` with `role` (a slot) and `assignment` holding only `resource_selection` and `launch_instructions`; the other assignment fields are copied from the commission in `msg_to_child` (the old answer carried the whole assignment). The model-facing `kind` keeps the old name `episode_child`, which the A101 transport recognises.
- The checks of the model's choice (`check_child_selection`) validate the model's answer in `action`; they are not a check of a commission. A parent whose own assignment pins launch instructions must have the model copy them: no fallback fills them in.
- Process note: one text edit of `task.py` and the map for the carry-over table were made with `python3`/`awk` outside the launcher (no model, no run, no remote contact); every test and import check ran through the launcher.
