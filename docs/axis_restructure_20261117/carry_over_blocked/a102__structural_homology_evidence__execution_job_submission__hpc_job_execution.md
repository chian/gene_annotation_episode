## CONTRACT MISFITS

- BLOCKED-ON-JOB-SERVICE: job_access; wanted call: `await ctx.services['job_access'].exec_command(configuration, coordinator_workspace, assignment, command, run_id, episode_id, key)` (see above).
- BLOCKED-ON-JOB-SERVICE: job records (handoff); see above.
- validate_form_not_built:structural_homology_evidence: the old `validate_report` called the axis `validate_form(form, original_schema, resolver)` on the parent-written report form. A102 has none; `final_to_parent.validate_report` raises `NotImplementedError('validate_form_not_built:structural_homology_evidence')` where that call was, so `final_to_parent` raises on every run until a validator exists (the new form has no parent-written JSON-schema form to validate).
- completion credit may pass its target: it cannot pass it (target = sum of the credits of all `progress_requirements`, the credit is the sum of the satisfied ones), but it may stay below it when the completion is verified: completion needs only the `completion_keys` and the endpoint predicate. The old `PracticalYieldEstimator` gave an exact zero forecast once the proof verified; the completion controller keeps the Episode running until its forecast falls to the cost. Conversely the old `PracticalState` admitted no command after completion (`practical_assignment_already_completed`), and `decide`/`action` cannot stop offering `exec_command`; in the new form that refusal is the job service's. Initial credit equal to the target (all requirements satisfied initially) is refused by the controller. Nothing is bounded or added.
- new field: hpc_job_execution (none). The assignment form has one field per property of the old schema (`practical_assignment_v1`, hpc, with `resource_id` required and `launch_instructions` optional). `requested_job` has alternatives in the old schema (generic argv/environment or native structure jobs): one `record` field. The old schema's `launch_instructions` was `required=False` here because the old schema did not require it.
- The baseline validations of the initial context (`initial_validations` in the parent input) use a fixed `checked_at` (`1970-01-01T00:00:00+00:00`): the parent input is compared on resume, and the old one carried the wall-clock time of the first opening.
- `execution_result_origin` was null in the old facts when no result windows existed, and a form field has no null: it is a selectable `record` field and `final_to_parent` raises `ValueError('execution_result_origin_not_available...')` when selected (an hpc launch acquires no result bytes). `execution_result_refs` is always empty here (it came from the results role's records).
- `execution_handoff_refs`: the old returnable-handoff test came from the removed `job_progress_provider.targets._handoff_reader`. `final_to_parent.facts` takes the receipts in which a validation of the requirement kind `requested_job_handoff` is satisfied. This reading is an assumption of this carry-over.
- The parent's immutable input versions, its protein-structure inputs and its frozen hpc request enum were checked by the child through the parent's recorded request (README 5 item 14); the child cannot read its parent's assignment. The parent's own `msg_to_child` must supply a valid practical assignment; `read_from_parent` runs the practical assignment contract (`validate_assignment`) and fails on a wrong one.
- Settings the episode reads (`continuation['structural_homology_evidence/execution_job_submission/hpc_job_execution']`): `resource` (the pbs_ssh configuration), `coordinator_workspace`, `task_yield_profiles` (`'launch_hpc:<class>'` -> `{'cutoff', 'parameters'}`), optional `launch_instructions_directory`. The old `require_private_yield` flag and the results, handoff/acquired-unit and log-window configuration belong to the other roles of the old configuration and are not read.
- The `ASSIGNMENT_FORM` has no `record_refs` field: the old assignment named no records. A record the exec commands read (inputs) would be named by the launching parent; none is declared here.
- `messages/internal_summary.py` makes `controller` `None` when `view.controller_state` is `None`: the system builds the summary before any unit with no controller yet (`episode_type.build_controller`), where `yield_table` raises `TypeError` for a non-state. Not a fallback: the state does not exist at that point.
- Shared per-kind class deleted: the earlier hook-era port's `runtime.py` of this folder (`HpcJobExecutionRuntime`, `HpcJobTools`, `construct`) was deleted with the other hook-era files. It is still imported by `root/a102/structural_homology_evidence/resource_work_submission/hpc_resource_work_execution/episode.py` (`HpcJobExecutionRuntime`), by `root/a102/structural_homology_evidence/contract_binding.py` (`construct`, lines 328 and 341) and by `resource_work_submission/tests/test_resource_work_link.py`; those imports now fail and belong to the carry-over of those folders. (The working tree at /tmp/ramrepo is a copy; nothing was changed in the git repository.)
