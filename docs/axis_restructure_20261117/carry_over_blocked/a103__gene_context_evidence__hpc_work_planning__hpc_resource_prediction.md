# hpc_resource_prediction (A103): blocked, unplaced and contract misfits

Episode: `gene_annotation_episode/episodic_workflow/root/a103/gene_context_evidence/hpc_work_planning/hpc_resource_prediction`. Job episode (the prediction sister of the HPC execution episode; childless; tool-only; operational credit; accumulation controller).

## BLOCKED-ON-JOB-SERVICE

- BLOCKED-ON-JOB-SERVICE: `hpc_ledger` (the job record kind of the commissioning HPC parent's ledger and its declared work table: model, model_choice, model_entry, candidate, queue, comparison, shared_history, plan, measured, closed, monitor, monitor_controller, result, tool_request, discovery evidence, and the credits table); wanted call: `ledger = HPCLedger.open_existing(ctx.store, owner_episode_id)`, an object over the parent's held ledger rows with `commission`, `read(id)`, `records(kind)`, `put(kind, body, identity=None)`, `once(identity, kind, calculate)`, `model_credit(model_ref, improvement)` and `credit_view()['contributions']`. `task.py open_ledger` raises `NotImplementedError('BLOCKED-ON-JOB-SERVICE: hpc_ledger; wanted call: ...')`, and every tool (`hpc_initialize`, `hpc_read`, `hpc_compare`, `hpc_history_refresh`, `hpc_discovery_run`, `hpc_candidate_propose`, `hpc_queue_observe`, `hpc_model_fit`) opens it first, so every unit raises where it is reached. The old ledger is a sqlite file outside the Store (`jobs/hpc/gene_context_evidence/hpc_ledger.py`), shared by the prediction and execution sisters; in the design of `LAUNCH_MONITOR_EXTRACT_MECHANICS.md` section 6 it travels as work-table rows in custody (the parent passes them in a `record_refs` field, the child returns what it wrote in one). No such table is declared in `episode_support/`.
- BLOCKED-ON-JOB-SERVICE: `job_access` (declared in `task.py` `SERVICES`); wanted calls: `ctx.services['job_access'].run_discovery(configuration, command, key=ctx.operation_key)` returning `{'command', 'returncode', 'stdout', 'stderr', 'observed_at', ...}` for one lightweight remote inspection through the resource's `ssh_argv` (old `subprocess.run([*ssh_argv, command], timeout=90)` with the output truncated to 65536/8192 bytes: neither the timeout nor the truncation is carried), and `ctx.services['job_access'].observe_queue(configuration, key=ctx.operation_key)` returning the old `hpc_queue.observe(configuration)` value (`{'snapshot': {...}, 'acquisition': [...]}`). The library has the queue observation as `jobs/hpc/hpc_queue.py::observe`; no service wraps it.
- BLOCKED-ON-JOB-SERVICE: `estimate_table` (declared in `task.py` `SERVICES`; the old `ExecutionMemory` of `records/gene_context_evidence/execution_memory.py`, a sqlite file of its own); wanted calls in tools: `history(query, now=now, queue_only=True)`, `latest(key, kind)`, `observe(key, kind, value, observed_at=..., provenance=[...])`, `as_record()`; wanted call in `decide`: `ctx.services['estimate_table'].read('execution_expectations', 'hpc_prediction')` (the old binding's execution expectations, resource and native estimates and native event targets, a workflow collaborator of the old runner), used only when the setting `execution_expectations` is present. No module of `episode_support/` is the service.

## BLOCKED-ON-STORE-ACCESS

- function = `gene_annotation_episode/episodic_workflow/episode_support/jobs/hpc/gene_context_evidence/hpc_ledger.py::HPCLedger`, pattern = "library not carried". It keeps its evidence, actions, credits and forecast-slot tables in a sqlite file (`sqlite3.connect`, `INSERT OR REPLACE`) outside custody. The episode does not import it. - the `[:2000]` cap in the old `_shared_history` is a count cutoff and is not carried; the library `ExecutionMemory.history(..., limit=2000)` has the same default, to be dropped when the service is built.
- `episode_support/jobs/hpc/gene_context_evidence/hpc_campaign.py::validate_commission`, `hpc_prediction.py` (`prior_model`, `fit`, `predict`, `quality`, `compare`), `hpc_resource_prediction.py::physical_attempt_key`, `jobs/hpc/hpc_queue.py` (`digest`, `features`) and `instructions/gene_context_evidence/execution_guidance.py::resource_identity` are pure value functions and are called as written. `instructions/launch_instructions.py::LaunchInstructions` and `tools/tool_knowledge.py::ToolKnowledge` read a frozen library folder of the disk, not the Store; `decide` calls them as written with directories from settings.

In the final form the system admits the result and the parent holds what is returned; whether the model identity belongs to the owner's ledger is a read of the ledger rows the parent holds (BLOCKED-ON-JOB-SERVICE: hpc_ledger).

- `decision_inputs.py PredictionDecisionInputs.decision_inputs`, the parts that came from workflow collaborators of the old runner and have no service or library today: `resource_tool_estimates` (`resource_estimator.estimate_context`), `native_execution_expectations` (`native_estimation_context`), `native_event_targets` (`native_event_information.read`), `job_execution_options` (`job_episodes.prospective_*`), `completed_action_reports`, `requested_action_history` as the old HPC-context report, `pending_work`. - `render_hpc_prompt`, `is_hpc_context` (the old `library/hpc_prompt`, decision prompt renderer of the old binding): the old shared root; there is no module of that name in `episode_support/`. `decide` sends the structured context as the model request's context and renders nothing.
- `to_parent.py PredictionReport.validate_report`: the `validate_form(form, original_schema, resolver)` of the JSON-schema report form is not carried (the form is replaced by `RETURN_FORM`, which the system admits exactly); the equality of each field with the recorded fact is carried in `final_to_parent.validate_report`.

## CONTRACT MISFITS

- new field: hpc_resource_prediction ledger_refs (assignment, `record_refs`): the parent's ledger rows the child reads must be passed in custody (a pass carries only the records named). Not added to `ASSIGNMENT_FORM`, because the job record kind is not defined (BLOCKED-ON-JOB-SERVICE: hpc_ledger).
- new field: hpc_resource_prediction hpc_ledger_refs (return, `record_refs`): the ledger rows this episode writes (model, model_choice, comparison, candidate, queue, shared_history evidence) must be returned in custody for the execution sister and the parent. Not added, same reason.
- The tool names `hpc.read`, `hpc.compare`, `hpc.history.refresh`, `hpc.discovery.run`, `hpc.candidate.propose`, `hpc.queue.observe`, `hpc.model.fit` could not stay: tool names are `[a-z][a-z0-9_]*`. They are `hpc_read`, `hpc_compare`, `hpc_history_refresh`, `hpc_discovery_run`, `hpc_candidate_propose`, `hpc_queue_observe`, `hpc_model_fit`.
- new tool: hpc_resource_prediction `hpc_initialize` (the old `PredictionState.initialize`, run on first use inside `decision_context`/`execute`). `decide` and `internal_summary` cannot write, so opening the ledger is the episode's first unit, offered without the model; it earns credit zero.
- new field: hpc_resource_prediction `commission_source_ref` is a `record_refs` field holding exactly one reference (it was one string of format reference) so that the record is passed in custody; `read_from_parent` raises unless exactly one reference is given.
- The old assignment schema's `oneOf` (exactly one of `commission_id` and `commission_source_ref`) cannot be written in a `RecordForm`; both fields are `required=False` and `read_from_parent` raises when not exactly one is present.
- The old `prepare_assignment` checks (the parent has role `hpc`, `owner_episode_id` equals the parent's episode id, the commission identity equals the parent's own, the yield binding is present) are the child's check of its own commission: not carried (owner's rule 1). The same for the ledger-owner scope and identity equality of `PredictionState.state` and the scope check of `resolve_received_reference` (the assignment has no scope; custody holds the Source).
- Settings the episode reads (the old `PredictionConfiguration` arguments): `settings['resources']` (resource configurations by id), `settings['commissions']` (configured commissions by id, with `yield_bindings['hpc_prediction']` `cutoff` and `parameters`), `settings['shared_execution_memory']` (present when shared memory is on), `settings['execution_expectations']` (optional), `settings['launch_instructions_directory']`, `settings['tool_knowledge_directory']`. The caller's `continuation` entry must hold them.
- The message of the commission may carry `launch_instructions` (the old `episode_assignment.launch_instructions` selection); `read_from_parent` reads it with `message.get`, as an optional value.
- `hpc_credit` (a selectable field) is the same value as `credit`; it is kept because the parent's old fact source had that name; it is `completion['credit']`, not a second computation.
- Continuation: the old estimator was accumulation with the commission's cutoff and parameters plus `HPCContinuationEstimator`; only accumulation is carried (README 7b). The cutoff (now the controller's cost) must be above zero or the accumulating controller never stops. The old `continuation_for_action` zero-forecast packet (no held-out cases, all trained, all candidates compared, fresh queue) is deleted: nothing but the controller stops the Episode.
- The goal text ends with "Return when further model improvement is less useful than running the next worthwhile portfolio"; the Episode cannot return by its own choice, so `INSTRUCTIONS` adds one sentence saying so. The old goal's text is the instruction text, so it lives in `task.py`; `goal.py` holds the short goal, unit and result of the old working-tree binding.
- The parent folder holds `hpc_runtime.py` (hook-era `HPCRuntime`, which the old `episode.py` here imported). It is the parent's file and was not touched; this episode no longer imports it.
- No real runner test is possible: the first unit raises at the blocked ledger. The tests cover the class definition checks (by import), the folder, imports, the form, `read_from_parent`, the credit, the controller, the report and the blocked raise.
