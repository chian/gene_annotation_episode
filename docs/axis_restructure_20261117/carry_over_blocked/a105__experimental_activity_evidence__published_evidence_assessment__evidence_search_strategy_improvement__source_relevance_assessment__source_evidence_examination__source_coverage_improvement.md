## CONTRACT MISFITS

- **`final_to_parent` raises on every close.** The old `validate_report` called `validate_form`; A105 has none, so the brief says the call raises `NotImplementedError('validate_form_not_built:a105')`. `validate_report` does that after the assignment-agreement checks, and `final_to_parent` always calls it: no Episode of this binding can return its result until an A105 `validate_form` exists. The checks written after the raise (`validate_received_report`) are the old ones over the summary and become reachable then.
- new field: source_coverage_improvement scope (assignment; the old episode took the Store scope from its request)
- new field: source_coverage_improvement record_refs (assignment, `record_refs`; the old episode read `context.received_record_refs`). The parent must name every record the episode reads: the source, its artifact, the sources it derives from (`parent_source_refs`), the question context records, the hypothesis the task answers and the subjects of the scope, since a pass carries only the records named. `page` and `literature_task` hold references as text because the old schema typed them so.
- new field: source_coverage_improvement finding (return; the old report was the parent's typed form filled from the model's report update). The episode declares its own typed finding (`processing`, `assessments` with source claim and qualification, `no_applicable_evidence`, `source_leads`, `grading_sheet_refs`, `unresolved`), read from the committed assessment records (`investigation_finding`), never written as prose; there is no report tool, so the old `report_update` prose is not returned.
- new field: source_coverage_improvement finding_refs (return, required `record_refs`: the assessments, their observations, hypotheses, sources and the sources' artifacts, held ones only, so that the parent can read what the finding names).
- new field: source_coverage_improvement sheet_refs (return, selectable `record_refs`: the saved sheets behind the selected cells and the grading sheets).
- completion target: the old `remaining_commissioned_credit` capacity (`credit_unit` x experiments, otherwise `credit_unit`) is `read_from_parent`'s `completion_target`; no new field. The completion credit cannot pass its target by construction: `credit_view` counts at most one answer per requested item (assessment, screening, measurement and assembly at most one; experiments one per distinct requested experiment, duplicates being refused by `validate_commission`).
- `internal_summary`, `credit` and `final_to_parent` are handed no settings, but the old binding configuration decided the population flags, the evidence origins and the implementation descriptors of ratio-source, controlled-response and gel. The flags are `task.py`'s choice of tools (`ctx.settings`); the summary and credit read a family only when a saved sheet of its provider is held, and build the repositories of those three families with the old defaults (`evidence_origin='reported_source'`, no expected descriptor). The old constructor checks of the descriptor and the origin are not carried.
- `final_to_parent` is handed no records; the old `validate_received_report` checks that need the Store (`validate_fact_values`, `validate_empty_return_family`, the requested-subset comparison and the worksheet links) are made in `internal_summary` (`check_family`, `validate_a105_worksheet_links`) over the same rows and raise the old codes as `ContractError`: a failing check fails the run in the unit that computes the summary (the old code returned them to the model as delivery feedback).
- The old credit read `runtime_actions` for the episode's own reasoning results; they are read from `view.outcomes` through the summary (`source_leads`, `no_applicable_witnesses`). The old lead reader also read admitted child forms; this episode has no child.
- Checks of a commission in the old credit and assignment code are not carried (rule 1): the credit's commission-mismatch, scope and target-annotation checks, and the assignment's proposed-annotation-equals-parent and within-parent-page checks (`_parent_page_schema`, `_validate_parent_page`).
- Tool names cannot contain dots: the library names (`source.read`, `literature.rate.populate`, ...) are carried as `source_read`, `literature_rate_populate`, ... (`LIBRARY_NAMES` and `credit.py::POPULATION_TOOLS`). The offered access tools are the old `_ACCESS_TOOLS` that the A105 registry implements; `source.sequence.scan`, `image.view`, `source.xlsx.sheets`, `source.xlsx.rows` and `execution.estimate` are not in that registry (the old catalog filtered them out).
- `action` wraps the model's arguments into an envelope `{'arguments', 'scope', 'page_source_ref', 'proposed_annotation_ref', 'context'}` so that the tool, which is handed no summary, can apply the old source restriction, build the library context and still return an `invalid` outcome that enters the iterator.
- Settings the episode reads: `cost` and `parameters` (yield controller), `tool_registry` (`pdfinfo_executable`, `pdftotext_executable`, `pdftoppm_executable`, `job_limits`; required by the access tools), the population flags (`rate_population`, `assay_grading_population`, `ratio_source_population`, `controlled_response_population`, `gel_population`, `completion_time_population`, `product_partition_population`, `active_site_population`, `parent_depletion_population`, `stoichiometric_balance_population`, `compiled_assay_population`, `channel_population`, `ion_discrimination_population`), optional `knowledge_library_directory`, optional `launch_instruction_directory`.
- The old estimator kinds are `accumulation` (verified_source_leads) and `remaining_commissioned_credit` (every other task): README 7b maps them to `AccumulationYieldController` and `CompletionYieldController` (target `completion_target`). The old `validate_yield_bindings` check of the configured declarations is not carried.
- `credit` computes the answers from the records, and `internal_summary` computes them again for the model (`credit_view`): the system calls both at every unit.
- The assay grading runs inside the original `reason` action (`literature_required_grading.execute`) as the AGENTS.md rule for A105 requires: the grader selection and the saved sheet are coupled, a no-applicable-evidence finding is the only processing that omits grading, and a returned `invalid` or `failed` outcome enters the iterator like any other unit outcome. Whether the library's `execute` keeps this under custody depends on the library carry.
- The instruction text of the old prompt about `redeliver_report` and `episode.history` (one adjacent span) is replaced by one sentence about `own_literature_outcomes`; the rest of the shared A105 prompt (which also describes the parent's child commissions) is kept as the library states it.
- No old tests exist for this episode (its folder held no `tests/`), so the retired-tests file has only its header.
- The outcome page of `internal_summary` lists only the read tools this episode offers.
