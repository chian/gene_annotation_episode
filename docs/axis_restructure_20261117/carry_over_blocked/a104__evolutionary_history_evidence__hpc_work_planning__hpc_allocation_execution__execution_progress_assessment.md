- BLOCKED-ON-JOB-SERVICE: `job_access`; wanted call (a recorded decision read): `ctx.services['job_access'].read('describe_progress_target', summary['target_handle'])` in `task.py decide` (old `services.describe_progress_target`). Called as written; a run without the service fails at link (`LinkError('service_required:...')`).
- BLOCKED-ON-JOB-SERVICE: progress snapshot record for an assignment's `known_progress_refs`; wanted call: `ctx.services['job_access'].read('read_progress', reference, scope)`. `credit` has no services and the commission passes no snapshot record (the refs are provider identities, not Store records), so `credit.py _SummaryProgress.read_progress` raises `NotImplementedError('BLOCKED-ON-JOB-SERVICE: progress snapshot record for ...')` as soon as the baseline is not empty. ## BLOCKED-ON-STORE-ACCESS

- function = `gene_annotation_episode/episodic_workflow/episode_support/tools/evolutionary_history_evidence/tools.py::source.read` (the registry operation the old `progress.log` called), pattern = "library not carried" (raw Store registry). Old call `tools.execute_async('source.read', {source_ref, representation, offset, limit}, scope=..., operation_key=..., permitted_record_refs=[source_ref])` -> intended call `ctx.store.open_artifact(window['artifact_ref'])` with a seek and an exact byte read, after `ctx.store.get(window['source_ref'])` (the old representation/artifact match). `task.py progress_log` does this itself (own few lines, not a copy of the library function); it needs the source and its artifact held (the commission must name both), else `CustodyError`.
- function = `gene_annotation_episode/episodic_workflow/episode_support/grading/evolutionary_history_evidence/progress_information_credit.py::ProgressInformationCredit`, pattern = none: it takes a reader with `read_progress(reference, scope)` and touches no Store; `credit.py` hands it a reader over the summary's snapshots.
- committed records: old `store.get(reference)['record_type'] in permitted` over the committed record refs of a snapshot -> intended `ctx.store.get(ref)['record_type']` (tools) and `view.records.get(ref)['record_type']` (`internal_summary`). The refs are records the job owner publishes; the episode does not hold them unless the commission names them, so the read raises `CustodyError` for an unheld one. The commissioning parent's `msg_to_child` must pass every committed record the target can expose in a `record_refs` field and the assignment form has no such field (see "new field").

## CONTRACT MISFITS

- BLOCKED-ON-JOB-SERVICE: job_access; wanted call: `ctx.services['job_access'].observe_progress(...)` (see above).
- `to_parent.py validate_report` first called `validate_form(form, original_schema, resolver)` of the parent's JSON-schema report form (A104 has `forms/evolutionary_history_evidence/communication.py validate_form`). In the new form the parent writes no return form and the report is admitted against the child's `RecordForm`, so there is no JSON-schema form to validate and the call is not carried; the rest of `validate_report` (facts equal the recorded ones, progress refs received, committed records delivered and permitted) is in `messages/final_to_parent.py` and runs before `final_to_parent` returns.
- new field: execution_progress_assessment information_unit (assignment: the old monitor took it from its configuration; `credit` needs it and has no settings).
- new field: execution_progress_assessment monitoring_progress_snapshots (return, selectable: the delivered snapshots by identity, which the commissioning monitor's `credit` needs because it has no services; the old parent read them through the shared progress provider).
- new field: execution_progress_assessment version (assignment, declared `monitor_assignment_v1`: the old schema's `version` property; the parent copies it).
- new field: execution_progress_assessment committed record refs the monitor may read (assignment `record_refs`): the old monitor read committed records of any permitted type from the shared Store; under custody they must be passed. Not added to the form (the old assignment had no such property); the parent's `msg_to_child` cannot pass them today.
- the old `null` facts (`monitoring_execution_state`, `monitoring_result_available`, `monitoring_observed_at_unix_seconds` without an observation) are `record` fields holding `{'value': ...}`: a form has no null.
- tool names: the old `progress.observe`, `progress.read`, `progress.log` are `progress_observe`, `progress_read`, `progress_log` (a tool name matches `[a-z][a-z0-9_]*`). The model's commission selection `monitor_dependency` carries `dependency_handle`.
- progress observation identities and `known_progress_refs` are provider identities, not Store records: they travel in `list` fields, not `record_refs`, and are not custody. `monitoring_committed_record_refs` is `record_refs` (a read by the monitor already needs them held).
- `monitor_private_yield_binding_not_enabled` and the cutoff value check are kept in `yield_estimator.py` over `settings['cost']` and `settings['parameters']['uncertainty_alpha']`. Cost zero passes the old check but an accumulating controller then never stops; the run's settings must give units a cost above zero.
- the monitor's credit raises `monitor_information_credit_cannot_decrease` against the credit the controller last saw (old estimator behaviour moved into `credit.py`, README 7b); the projection is monotonic by construction, so it cannot fire today.
- the old rule "when the parent is the axis head and an annotation task is required, the parent must request `monitoring_progress_refs`" belongs to that parent's `msg_to_child`.
- the old goal text had two variants (own yield settings, or "the caller's monitoring projector and configured controller own credit and continuation"); only the first is carried: this episode always builds its own accumulation controller from its settings (an entry without them raises).
- the old `outcome_page_size` setting is not needed: every outcome is in the view.
- the old `required_return_sources` / `redeliver_report` / `wait` permitted actions: the wait and redelivery actions are machinery and not carried.
