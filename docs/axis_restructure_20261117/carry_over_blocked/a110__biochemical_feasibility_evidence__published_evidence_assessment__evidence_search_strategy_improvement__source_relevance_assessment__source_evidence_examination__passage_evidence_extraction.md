## CONTRACT MISFITS

- new field: passage_evidence_extraction scope (assignment; the old episode took the Store scope from its request)
- new field: passage_evidence_extraction received_record_refs (assignment, `record_refs`; the old episode read `context.received_record_refs`). The parent must name the page's source, its artifact, the sources it derives from (`parent_source_refs`) and the records that give the question its context, because a pass carries only the records named.
- new field: passage_evidence_extraction finding_unit (assignment; the unit of the old `services.scientific_credit`, which lived in the old shared root and is not read). `credit.py` multiplies the count of distinct retained findings by it (`FindingProgressPolicy(finding_unit)`), as the library projection requires an explicit positive unit.
- new field: passage_evidence_extraction finding (return; the old episode returned the parent's requested form filled from the model's report update and had no finding). The episode declares its own finding form (`written`, `interpretation`, `passages`, `qualification`) and a `report` tool for the model's closing text. The old `report_update` of every model answer is the `report` tool. This is the A110 finding; the AGENTS.md "Required literature evidence processing" section applies to A105 and A108 and is not claimed here.
- The old assignment properties from `literature_component_binding.assignment_schema_fields()` and the old fact sources from `fact_sources()` cannot be named: the module is not in the library. `ASSIGNMENT_FORM` and `RETURN_FORM` therefore lack them (the "one field per old property" rule cannot be met for them).
- A110 has no `validate_form` (README 5 item 11: `forms/biochemical_feasibility_evidence/communication.py` has `plain` only). The old `validate_report` call `validate_form(form, schema, resolver)` is not borrowed; the call would raise `NotImplementedError('validate_form_not_built:biochemical_feasibility')` and is replaced by the episode's own `FINDING_FORM.admit` in `validate_report`, because the finding has no old report schema.
- The old episode named no yield estimator (`yield_controller` -> None; the old generic controller). The accumulation controller is chosen (README 7b: credit that accumulates); `settings['cost']` and `settings['parameters']` are read from the episode's `continuation` settings.
- completion credit may pass its target: not applicable, the controller is accumulation.
- Tool names cannot contain dots: the library names (`source.read`, ...) are carried as `source_read`, ... (`LIBRARY_NAMES` in `task.py`).
- The tool arguments the model fills are wrapped by `action` into an envelope `{'arguments', 'scope', 'page_source_ref'}` so that tools, which are handed no summary, can apply the old page-source restriction and still return an `invalid` outcome that enters the iterator, as the old `execute` did.
- Settings the episode reads: `cost` and `parameters` (yield controller), optional `tool_registry` (keyword arguments of `ToolRegistry`; `native_statistics` makes `execution_estimate` available), optional `knowledge_library_directory`.
- `decide` shows the model the tool catalog built from `task.py` constants (`DESCRIPTIONS`, `INPUT_SCHEMAS`) instead of the old `services.tool_catalog(scope)`; the descriptions are a private copy of the tool library's text.
- Test coverage: the folder had no tests; `tests/test_binding.py` has real checks only. A real runner test (link, RunJournal, Store, yield_control) is not written: the first unit would call the not-carried `ToolRegistry` and the first credit the not-carried `project_finding_progress`, and no real model is available without `model_run`.
