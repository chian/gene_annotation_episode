## CONTRACT MISFITS

- BLOCKED-ON-JOB-SERVICE: handoff record kind (job ledger); wanted call: `records.table(JOB_LEDGER).select({'event': 'handoff', 'job': handle})`.
- validate_form_not_built:A102: the old `validate_report` called `validate_form(form, original_schema, resolver)`; A102 has no report-form validator, so `messages/final_to_parent.py validate_report` raises `NotImplementedError('validate_form_not_built:A102')` after its fact-agreement check, and `final_to_parent` raises every time it is reached (tested).
- GOAL.md: the brief names `docs/axis_restructure_20261117/GOAL.md`; the file does not exist. Not read.
- the old continuation was a `BoundedYieldController` capped at the uncredited requests (the intent record says "completion with a target"; README 7b maps the old bounded controller to bounded quality). Chosen: `BoundedQualityYieldController` with `maximum_credit = remaining_credit` from the commission and `cost` = the profile's cutoff. Credit cannot pass that maximum: only resources the commissioner made eligible can be commissioned, and each counts once.
- the old exact-zero estimator for "no uncredited request" is not carried (README 7b); `yield_controller` raises `ValueError('launch_no_uncredited_original_request')` when `remaining_credit` is not positive, and `ValueError('execution_original_task_yield_profile_required:<key>')` when the settings have no profile (as the old code did).
- new field: execution_job_submission scope (assignment; the old request message carried it and the API child reads it).
- new field: execution_job_submission input_refs (assignment, `record_refs`; the old `initial_references`: the records the requests name; the children read them).
- new field: execution_job_submission handoff_unit (assignment; the old `configuration.handoff_unit`, which `credit(summary, records)` cannot read from settings).
- new field: execution_job_submission already_handed_off_resource_ids (assignment, optional; the old `initial_known_record_refs` of usable handoffs, which `credit` and the continuation exclude).
- new field: execution_job_submission scientific_task (assignment, optional; the old `services.scientific_parent_task` of a native protein-structure job, passed to the `launch_local` child).
- new field: execution_job_submission finding (return; the old episode returned the parent's JSON-Schema form; declared `FINDING_FORM`: `commissions`, `handoff_resource_ids`, `new_handoff_count`, `qualification`).
- new field: execution_job_submission eligible_resource_ids, request_kinds, task_yield_key, remaining_credit (parent input derived by `read_from_parent`; the old yield estimator read the assignment).
- api_job_execution declares `immutable_input_versions` as a `record`, and the old value is an array: `msg_to_child` sends `{'versions': [...]}` for it. The `launch_api` child form is otherwise built from the request (`version`, `service`, optional `algorithm`/`database`, `resource_id`, `request`) plus `scope`, `input_refs`, `launch_instructions` and `completion_target` (= `handoff_unit`, the credit one handoff earns).
- the children's return forms: `execution_handoff_refs` and `execution_completed` are declared selectable by all three and are what this episode selects; `execution_result_origin` is declared as text by `api_job_execution` and as a record by the other two (the old value was null), so the parent never selects it. The parent's own `execution_result_origin` is the empty record (a form has no null).
- a handoff is taken as usable when the child returned handoff references that the episode holds, and its resource id is the one the parent commissioned (the hpc and local findings do not carry the resource id): the old code re-read each handoff record to check its target and usability (job-service item above).
- `launch_instructions`: the old envelope materialised the selected request's own selection. The commissioner's pinned selection (the old goal: preserve pinned instructions) is given to a child whose request has none.
- `decide` shows the capabilities and the inventory at every decision (the old `initial_decision_context`) and also offers the `execution_capabilities` tool, as the old catalog did. The tool earns nothing; the bounded controller needs a cost above zero in the settings profile to stop an episode that only reads it.
- `decide` raises `NotImplementedError('a102_api_service_execution_not_in_library:capabilities')` when the settings configure an API resource.
- the scratchpad directory that the harness named for this session already held another agent's `numbers.py` (it shadows the standard library when a script is run from there); one-off checks were run with `exec(open(...).read())` from the repository root, and the repository path is a symlink to a RAM copy without a `.git` (old code was read with `git --git-dir=/home/chia/repos/gene_annotation_episode_disk/.git show 97308b94c:<path>`).
