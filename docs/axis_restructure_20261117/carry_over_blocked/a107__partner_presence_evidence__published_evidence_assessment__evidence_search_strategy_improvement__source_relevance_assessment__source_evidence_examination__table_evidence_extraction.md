## CONTRACT MISFITS

- new field: table_evidence_extraction scope (assignment; the old episode took the Store scope from its request)
- new field: table_evidence_extraction received_record_refs (assignment, `record_refs`; the old episode read `context.received_record_refs`). The parent must name the source, its artifact and the sources it derives from, since a pass carries only the records named.
- new field: table_evidence_extraction finding_unit (assignment, number; the credit is `ScientificFindingProgress(FindingProgressPolicy(finding_unit))`, whose unit the old runner's `scientific_credit` service supplied; its value is not in any readable old file).
- new field: table_evidence_extraction finding (return; the old episode returned the parent's requested form filled from the model's report update). Own typed finding form (`source_claim`, `source_subject`, `qualification`, `target_correspondence`, `readings`) and a `report` tool for the model's finding. A107 is not an A105/A108 episode, so no saved subscoring sheet applies.
- The old `scientific_credit(context, receiver_selection)` body lived in the old shared root and was not read. The credit is the A107 finding progress (the axis head's projector `task_projector.original_task_projector` -> `finding_progress()`); this leaf has no reasoning commit and writes no assessment, so the assessments it holds are only those the parent passed in `received_record_refs` (its credit is 0 when none are in scope). If the old service gave a leaf credit for its own readings, that is not recoverable from the readable files.
- The old assignment `selection` was `anyOf` a table selection or a byte window; forms have no union and no null. `selection` is one open `record` field, admitted by `read_from_parent` against TABLE_FORM or WINDOW_FORM (a `sheet_key` selects the table form); a null `header_row`, `where` or `where.column` is the field omitted.
- Tool names cannot contain dots: library names (`source.read`, ...) are carried as `source_read`, ... (`ACCESS` in `task.py`). `tool_catalog` is a new first lookup tool (the old services tool catalogue).
- `action` wraps the model's arguments into an envelope `{'arguments', 'scope', 'source_ref', 'sheet_key'}` so that the tool, which is handed no summary, can apply the source restriction and the sheet guard and still return an `invalid` outcome that enters the iterator.
- `final_to_parent` raises `a107_table_evidence_finding_not_reported` when the controller stops the Episode before any finding was reported (no fallback value).
- Settings the episode reads: `cost` and `parameters` (yield controller), optional `tool_registry`, `knowledge_library_directory`, `launch_instruction_directory`.
- Controller: the old file chose none (old default). `AccumulationYieldController` is chosen because `ScientificFindingProgress.yield_method` is `'accumulation'` (README 7b). No completion target, so no "completion credit may pass its target" item.
- A107 has no `validate_form` obstacle here: the old `validate_report` called `validate_form` against the parent-written JSON-schema form; there is no such schema in the new form, so the finding is checked by its own `FINDING_FORM` and the held-source check.
- Old tests: this episode had none at 97308b94c and the working tree held none, so the retired-tests file has only its header.
