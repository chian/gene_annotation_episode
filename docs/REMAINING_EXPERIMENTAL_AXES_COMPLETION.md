## What was connected

Existing readers, numerical calculators, source custody and typed parent delivery already supplied most of the required functionality. The identified additions were explicit reusable assessment types and stable experiment identity across assessment revisions. Numerical formulas were not changed.

An optional `experiment_assessment` accompanies an existing population request. It contains a received, source-backed assay reference, experiment type, stable question key, scientific question, conclusion, limitations and, for corrections, the predecessor sheet and revision reason. The population operation checks identity authorization and the latest predecessor inside its publication transaction. A second representation cannot publish a second current assessment for the same experiment/question key without explicitly revising the existing one.

Original measurements, controls, source witnesses, uncertainty, interpretation and numerical results remain in immutable saved sheets. Parent numerical rows carry the canonical experiment reference. `current_assessments()` returns the latest assessment for each experiment/question; `assessment_history(sheet_ref)` reconstructs its saved revision chain. Several questions can concern one experiment, so the number of assessments is not an independent-experiment count. Historical numerical rows remain explicitly addressable.

Legacy raw sheets remain readable without invented experiment identities. Their original APIs are preserved; the current-assessment inventory includes explicitly linked assessments. An unresolved identity must be established from source evidence before an assessment is linked. The investigation prompts describe this distinction.
