## Ported from other arms, and how `port_twins.sh` decides
21 files were taken from another arm's already-purged copy (a106 RIA contracts/profiles, a107
`episode_receipts.py`/`numerical.py`, a110 `task_state.py`, a105/a104 tests). I will not run the script again;
propagation is left to the coordinator. Script and map:
`/tmp/claude-1000/-home-chia-repos-gene-annotation-episode/6505138e-b5fa-4641-9b42-c1589dca8429/scratchpad/pa108/port_twins.sh`, `twin_map.tsv` (same directory).
- Twin test (built once into `twin_map.tsv`, non-test `.py` files tracked at HEAD under a108): arm X's file at the
  SAME relative path is a twin when `git show HEAD:<X file>` with every `aXXX` replaced by `a108` and `AXXX` by
  `A108` has the same sha256 as `git show HEAD:<a108 file>`. Arms are tried in the order a106, a105, a101, a107,
  a110, a104, a103, a102. Only the arm's own name is substituted; root-level files are never twins.
- Which content wins, per a108 file: the first twin in that order whose working file differs from the HEAD base
  is "theirs" (renamed the same way). If the a108 working file still equals HEAD, theirs replaces it. If a108 was
  also edited, `git merge-file` merges a108-working / a108-HEAD / theirs; a clean merge is written, a conflict
  leaves a108 untouched and is logged `CONFLICT`. A twin that no longer exists is only logged (`twin_deleted`,
  which also lists paths the arm never had); nothing is deleted. Log: `port_log.tsv`.
- Limits: 253 of 284 RIA files and 93 of 142 top-level modules have twins; the map is HEAD-based, so files I
  edited by hand are still merged from twins; a twin edit can break an a108-only caller (it did once:
  `numerical.py` from a107 needed `runtime.py` lines 106 and 3492 aligned by hand).
