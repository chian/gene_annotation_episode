## 3. Left in place, and why

1. **Runtime-computed binding identity**: `implementation_record()` / `binding_record.py` / `SOURCE_PATHS` and the
   `definition_inputs.py` rosters, `implementation_sha256` in binding descriptors, compared when a saved run is reopened.
   It hashes implementation files, but holds no pinned value and is the durable-restart identity in every axis's runtime.
   I treated "pin mechanism" as hard-coded expected digests plus the receipts built on them. If the owner wants this gone
   too it is a separate, much wider change (every axis's `runtime.py`, `episode_composition.py`, all homes'
   `binding_record.py`). `SEE/implementation_sources.py` and `R/a106/literature_implementation_sources.py` stay because
   that code reads through them.
2. **Pins on third-party scientific source**: `SOURCE_FILE_SHA256`, `SOURCE_FUNCTION_SHA256`, `SOURCE_SHA256`,
   `CALLABLE_SHA256`, `source_file_sha256` in native-tool contracts (about 96 product files across all axes and
   `R/library`, e.g. `R/a105/protease_kinetics_measurements.py:23,240`). They pin the external tool module a native job
   executes, not this codebase. Not touched; needs an owner decision.
3. Native worker `implementation_files` lists (`esm_worker_implementation_files`, `_molecular_implementation_files`): same
   kind as item 1.
4. `lexical_dependency` in active-site and completion-time extractions: a plain parser-version string, no digest.
5. Older-record branches next to the removed pins that belong to the area agents: `LEGACY_VERSION` paths in
   `literature_kinetic_storage.py` (a104, a105, a106), `original_keys | {'projection_version'}` in product coupling,
   the `scientific_process_episodes_v5..v10` version set in `R/a103/episode_composition.py`.
6. Unused imports that were already unused before this work (`Path` in most storage modules). Only imports my removals
   orphaned were deleted.
