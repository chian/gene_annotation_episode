# h3: retained plan / sealed bundle replays and the fixtures that carry `policy.wall_seconds`

Scope: decision 3 ("Retire those replays") under decision 4 and the widened instruction of 15 November ("any test
that loads a plan, capture, receipt, bundle or output saved by an earlier code state is deleted outright ... delete,
do not repair"). Whole repository. No product file was edited. Paths below are relative to
`gene_annotation_episode/episodic_workflow/root/` unless they start with `tests/` at the repository top (marked "top").

## Rule applied (measurable)
1. A fixture file is an old-form record when it is a record written by this program (plan, handle, owner file,
   bundle, receipt, intent, request, worked-record set, run manifest) whose `policy` / `job_limits` /
   `allocation` block carries `wall_seconds`. 1,815 such files existed at the start (found by regex over every file
   under `*/fixtures/`).
2. A test is deleted when it reads such a file, directly or through a helper or a helper imported from another test
   module (computed with a static reach analysis over module-level names and pytest fixture arguments, seeds checked
   by eye per file), or when it replays a retained sealed attempt bundle / saved handle (`bundle.json`,
   `original_handle.json`) even without the key.
3. A test that reads only native tool output stored beside those records (`.cm`, `.tbl`, `.paf`, BLAST `report.json`,
   Rfam `response.body` / `snapshot.json`, `.hic`) stays. A test that builds a current plan and injects `wall_seconds`
   to check the refusal stays.
4. After the tests: the old-form files are deleted; a fixture directory is deleted whole when no Python file outside
   `fixtures/` names it any more (grep with `--exclude-dir=fixtures`).
