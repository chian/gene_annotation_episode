# Scientific evidence credit and its runtime binding

## Progress and annotation support

The runtime now accepts an optional caller-owned `project_annotation_score`
alongside its existing progress callbacks. Scientific decisions receive
`annotation_score`, `annotation_evidence_vector` and `annotation_score_binding`.
The parent may request a numeric form field with `x-source: annotation_score`;
closure freezes its actual value, including for later redelivery. Job roles do
not acquire this scientific report channel. The optional policy and effective
definition are recorded and checked on recovery. Without that binding, old
runs retain their original absent fields and scoring. Annotation support
creates no numerical observations and does not set continuation.

The production investigation-progress contribution rule is not yet bound.
An explicit typed-finding projection and receipt-aware runtime adapter now exist;
the caller supplies the numerical unit and initial known references. The
`received_findings` case-policy mode selects it for both scientific levels and
retains annotation support separately. Runtime receipt, frozen inheritance and
selected-read integration passed the 25-check receipt/policy/case group.
A fresh configured-model verification run, investigation_004, now uses this
binding with explicit provisional finding unit 1. The first reasoning action
scored two findings and the next decision received progress 2 separately from
annotation support 0; full scientific and lifecycle verification remains open. See
[INVESTIGATION_FINDINGS.md](INVESTIGATION_FINDINGS.md) for implemented semantics
and the remaining state/communication/credit work.
Source downloads, new IDs, account copies or toggled interpretations are not
adequate substitutes for new useful scientific information. Existing IDs do
not establish semantic independence of differently quoted passages. Progress
identity, inherited information, actual parent receipt and correction semantics
must be defined together; no activity-counting formula has been installed.

Scientific episodes can inspect annotation operands through the optional
`episode.annotation_score` tool when this separate projector declares a detail
reader. It uses the same bound projection and explicit paging arguments as the
context score. Its scalar is named `annotation_score`, and the original binding
and policy accompany actual operands. The shared detail-reader implementation
also continues to serve `episode.credit`; there is no fallback policy, separate
summarizing model call or progress award for the read. Eight affected checks
passed in 26.09 seconds after this addition, including a real hypervolume
decline followed by an ordinary annotation-operand read with zero new progress.
Independent source review of the reader found no concrete defect. Failure,
missing-reader and job-catalog exclusion behavior were source-inspected; they
were not all separately executed in the new separation test file. Existing
credit-reader failure checks did execute through the shared implementation.

## Explicit annotation-support arithmetic

`scientific_credit.AnnotationSupportScore` supplies the separate annotation
channel with the existing evidence operands, policy and hypervolume. Its
binding explicitly selects `equal_component_integer_mass_v1`. Equal winning
component vectors accumulate exact integer position mass in the temporary
SQLite spool before floating multiplication and streamed summation. Adding a
losing account cannot change the score just by splitting an unchanged winner
into additional integration cells. Summary, detailed operands and binding all
identify this value as annotation support, not investigation progress.

This addresses an observed numerical artifact in investigation_003 child
decision 50: identical winning scientific contributions scored
2.5471927539599757 before the added local account and 2.5471927539599752 after
it. The independent read-only reconstruction produces exactly

contributions. The artifact is separate from the genuine earlier decrease
caused by the added localization qualification.

The original `ScientificEvidenceCredit`, `ScientificInvestigationCredit` and
public projector default retain their saved arithmetic and binding records.
No saved observations, controller parameters or running process have been
rewritten. The new adapter has not yet been selected by a production case
run; the explicit new case-policy mode is available and undergoing verification.

## Historical hypervolume credit binding

`credit.project_credit` implements the current scientific evidence projection.
`scientific_credit.ScientificEvidenceCredit` binds an explicitly supplied
`CreditPolicy` to the shared runtime's task and scientific-child interfaces. It
does not introduce another formula or select numerical continuation settings.

The five axes are empirical, comparative, mechanistic, biological context and
discrimination between interpretations. For normalized axis values `a_i`, axis
weights `w_i` and softening `epsilon`, the existing normalized volume is:

```
V = (product((epsilon + (1-epsilon)*a_i)**w_i)
     - epsilon**sum(w_i)) / (1 - epsilon**sum(w_i))
```

The scalar is the configured scale times this volume, integrated over the fixed
original-input scope. Missing evidence on one axis therefore does not veto all
other evidence. This is a progress proxy, not a probability of biological truth.

Axis operands come from current source-linked assessments in explicitly recorded
coherent annotation accounts. Accounts can retain unresolved alternatives; they
do not have to select a specific function. Measurements, inferred attribution,
source organisms, actual intervals and conditions keep their recorded identities.
Raw database labels, source downloads, hit counts and tool completion alone are
not scientific credit. Correcting a current contribution can reduce credit;
historical-best clamping does not hide that loss.

The existing within-axis rule uses the strongest supporting contribution divided
by one plus the strongest opposing contribution. It prevents copied evidence
from accumulating credit but also ignores additional equally strong independent
corroboration. No additional accumulation formula is supplied by this binding.

The adapter requires an explicit `CreditPolicy` and exposes its full parameters
and formula/projection versions in its binding definition. Summary and ordinary
`episode.credit` detail reads use that same policy and fixed scope. A child's
supplied assignment must agree with that scope. Reading credit changes no state.

If a caller uses this same adapter for scientific children, the runtime records
the child's inherited current scoped credit before its work, then observes raw
changes from that baseline. The parent projects the actual shared scientific
state after the child's action. It does not add child scalar scores to its own.
Requested forms can return current credit and actual changed scientific refs;
closed forms retain their completion-time values after later corrections.

This binding does not separately score an assessment-only investigation that
has not recorded an annotation account. That limitation remains explicit. A
different local contribution scheme requires its own defined meaning; the
adapter does not infer one from a child's name, prose, or report field count.

## Provisional local interpretation accounts

`ScientificInvestigationCredit` admits `interpretation_account` records into
the same cell integration and softened hypervolume as `ScientificEvidenceCredit`.
Existing annotation accounts remain inherited operands. Whole coherent accounts
compete by the existing maximum; separate accounts are neither summed nor
automatically fused. The root binding remains annotation-only. A nested
scientific parent uses its own configured projection, so inner account progress
can affect its local score before root annotation integration.

The optional `interpretation_accounts` reasoning section records subjects,
footprints, coherent hypothesis/disposition/assessment sets, contexts,
alternatives and expected revision. It does not replace the parent annotation.
The runtime supplies owner identity and immutable assigned scope; the model
cannot supply ownership. The current lineage includes that owner, scope,
subject and context domain. Internal owner identities stay outside the public
record, whose actual kind remains `interpretation_account` in state, projection
details and typed report references.

Inherited current scoped accounts establish the baseline, so copying an existing
account earns no gain. A real assessment revision can invalidate its exact old
reference in all copied accounts. Revising one episode's account alone does not
retire another episode's current account. Closed accounts are durable scientific
state; closed logging/controller/provider histories retain their archive/release
path. No historical-best score clamp or additional observation is introduced.

Parents can request `changed_interpretation_account_refs`, with reference format
and namespace `interpretation_account`, through their existing closed form.
Those actual recorded refs, separately requested assessments and local credit
need no composer. The parent integrates their evidence in its own subsequent
reasoning action; child scalars are not added to its score.

Assessment-only work still needs an explicit coherent account to enter this
projection. Weaker corroboration and nonwinning accounts can leave its maximum
unchanged. Scope is commissioned original material, not a question inferred
from prose. This prototype adds no new numerical strengths or goal-specific
relevance rule to conceal those limitations.

0.9614173228346456 to 0.8182275087954431. Read-only inspection of the recorded

score per hypothesis. Neither replacement has been approved or installed.
Historical scores, the child's completion-time form and the active run's
settings remain unchanged.

Scientific credit remains separate from monitoring information credit and from
execution-duration expectations. Timing statistics and local job preparation do
not become supporting evidence for a molecular function through this adapter.

The existing numerical applicability strengths, unresolved multiplier, softening
and scale are explicit provisional settings for the first configured-model run;
their presence does not mean that each value was user-approved.
The historical case bound the existing scientific implementation through a
saved policy source. The live central policy module was later removed in favor
of episode-owned bindings. That historical case did not install the subsequently suggested
accumulation formula, remove the unresolved multiplier or add another local
scientific score.
