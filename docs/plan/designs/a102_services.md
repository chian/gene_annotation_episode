## 1a. UniProt REST (https://rest.uniprot.org; files `uniprot/`)

- UniParc by MD5: `GET https://rest.uniprot.org/uniparc/search?query=checksum:40785A8282413070FE126DFD41E458FF&format=json&size=3` -> HTTP 200, 0.79 s, 63.8 kB (`uniparc_md5.json`). One result, keys `uniParcId` (`UPI000003FF29`), `crossReferenceCount` (319313), `commonTaxons`, `uniProtKBAccessions` (4750 entries with `.1` version suffix, includes `P0A9X9`; the list is not sorted by reviewed status), `sequence` (`length`, `md5`, `crc64`, `value`), `sequenceFeatures`. RecA: same query shape with `format=tsv&fields=upi,accession,organism,length,checksum` -> HTTP 200, 0.80 s, 53 kB (`uniparc_reca_md5.tsv`); the TSV has the columns Entry, UniProtKB (all accessions joined by `; `), Organisms, Length, Checksum. No protein names come back from UniParc; one UniParc entry holds every identical sequence of every organism.
- UniProtKB by CRC64: `GET https://rest.uniprot.org/uniprotkb/search?query=checksum:CED47F00BF18A49B&format=tsv&fields=accession,id,protein_name,organism_name,length,reviewed,annotation_score` -> HTTP 200, 0.75 s (CspA, `uniprotkb_crc64.tsv`, 25 rows, all 70 aa, P0A9X9 first, then 7 reviewed orthologs with identical sequence, then unreviewed). RecA with `&size=5`: P0A7G6 first, then reviewed E. coli strains, all 353 aa (`uniprotkb_reca_crc64.tsv`). A CRC64 can in principle collide, so length (and ideally the sequence) must be compared.
- UniProtKB with an MD5 value in `checksum:` (`uniprotkb_reca_md5_attempt.txt`): HTTP 200, 20 B, only the header `Entry` and no rows. UniProtKB `checksum` is CRC64 only; MD5 works in UniParc.
- Both work without key or email. Documentation: https://www.uniprot.org/help/api (not re-read for limits; no 429 was seen). Result rows are ranked by UniProt, not by closeness; all returned rows here are identical sequences.
- Requests used: uniparc/search 3, uniprotkb/search 5 (+1 in section 4).

  `{"query":{"type":"terminal","service":"sequence","parameters":{"evalue_cutoff":1,"identity_cutoff":0.3,"sequence_type":"protein","value":"<sequence>"}},"return_type":"polymer_entity","request_options":{"paginate":{"start":0,"rows":10},"scoring_strategy":"sequence"}}`

CspA hits: 2L15_1 and 30IB_1 identity 1.0 evalue 8.9e-42; 1MJC_1 (69 aa) identity 1.0.
- Entity: `GET https://data.rcsb.org/rest/v1/core/polymer_entity/1U94/1` -> 200, 0.23 s, 30.8 kB. Useful fields: `rcsb_polymer_entity.pdbx_description` (`RecA protein`), `rcsb_polymer_entity.rcsb_polymer_name_combined.names`, `rcsb_entity_source_organism[].scientific_name`/`ncbi_taxonomy_id`, `entity_poly.pdbx_seq_one_letter_code_can`, `rcsb_polymer_entity_container_identifiers.uniprot_ids` (`P0A7G6`) and `reference_sequence_identifiers` (SIFTS, coverage), `rcsb_polymer_entity_align`, `rcsb_polymer_entity_annotation`.

## 3. Structure search (Foldseek web server https://search.foldseek.com; files `foldseek/`)

- Databases: `GET /api/databases` -> 200, 0.84 s, 7 kB. List of `{name, version, path, default, order, taxonomy, complex, motif, rna, ...status}`. Used: `pdb100` (PDB100, version 20240101), `afdb-swissprot` (AlphaFold/Swiss-Prot v6), `cath50` (CATH50 4.3.0). Also listed: `afdb50` (AlphaFold/UniProt50 v6), `afdb-proteome` (v6), `pdb_folddisco`, `bfvd_v3`, `bfmd`, `mgnify_esm30`, `gmgcl_id`, `pdb_interface`, `humanppi_interface`, `afdb_homodimer_interface`, `rnadb`, `esm30_folddisco`, all status COMPLETE.
- Submit: `curl -X POST https://search.foldseek.com/api/ticket -F "q=@AF-P0A9X9-F1-model_v6.pdb" -F "mode=3diaa" -F "database[]=pdb100" -F "database[]=afdb-swissprot" -F "database[]=cath50"` -> HTTP 200, 1.4 s, `{"id":"<ticket>","status":"PENDING"}`. Poll `GET /api/ticket/{id}` -> `{"id","status"}` with PENDING, RUNNING, COMPLETE or ERROR (documentation https://search.mmseqs.com/docs/). First poll at 6 s after submit already said COMPLETE (9 s from submit to a COMPLETE answer, 3 databases).
- Result: `GET /api/result/{id}/0` -> 200, 3.6 s, 12.06 MB (`result_0.json`). Top level `type` (`structuresearch`), `mode` (`3diaa`), `queries[]` (`header`, `sequence`), `results[]` per database: `db`, `alignments` (a list holding one list of hits), `taxonomyreports` (per-hit-set taxon tree: proportion, clade_reads, taxon_reads, rank, depth, taxon_id, name). Per hit keys (all hits the same): `query`, `target` (id + description: pdb100 `1mjc-assembly1.cif.gz_A CRYSTAL STRUCTURE OF CSPA, THE MAJOR COLD SHOCK PROTEIN OF ESCHERICHIA COLI`; afdb-swissprot `AF-P0A9Y0-F1-model_v6 Cold shock protein CspA`; cath50 `5o6fA00` or `af_Q94C69_1_75_2.40.50.140`, the last field being the CATH superfamily 2.40.50.140), `seqId` (percent), `alnLength`, `missmatches`, `gapsopened`, `qStartPos`, `qEndPos`, `dbStartPos`, `dbEndPos`, `prob`, `eval`, `score`, `qLen`, `dbLen`, `qAln`, `dbAln` (aligned strings with `-`), `tCa` (comma list of the target's aligned C-alpha x,y,z in the TARGET's own frame, not superposed on the query), `tSeq`, `taxId`, `taxName`. There is no TM-score field, no RMSD and no rotation/translation in either mode. Hits returned: afdb-swissprot 982, cath50 481, pdb100 549 (CspA query). Examples: pdb100 hit 1 `1mjc` seqId 100 score 521 eval 4.3e-13 prob 1; hit 2 `3i2z` (CspE, Salmonella) seqId 71.2 score 433 eval 9.5e-11; `8h1i` seqId 68.5 (an endolysin, so structural hits include other functions).
- Download: `GET /api/result/download/{id}` -> a tar.gz of tab files `alis_<db>.m8` and `alis_<db>_report.m8` (taxonomy); columns of `.m8`: query, target, seqId, alnLength, mismatches, gapOpen, qStart, qEnd, tStart, tEnd, prob, evalue, score, qLen, tLen, qAln, tAln, tCa, tSeq, taxId, taxName. 11.2 MB unpacked (`foldseek/dl/`).
- `mode=tmalign` (one database pdb100; ticket 2): COMPLETE at the first poll after 7 s; result 200, 2.8 s, 3.46 MB, 548 hits, same keys, `mode` `tmalign`. Foldseek README (https://github.com/steineggerlab/foldseek) says that with TM-align alignment the score is the query-normalised TM-score x 100 and the e-value field is the mean of the query and target TM-scores; the first hit of this answer has score 90 and eval 0.9246, consistent with that. The fields are still named `score`/`eval`/`prob`; there is no separate TM-score key. (Not further verified by recomputing.)
- Sequence input: `-F "q=@cspa.fasta"` (one FASTA record, `mode=3diaa`, `pdb100`) -> ticket created (HTTP 200, 0.87 s), then status ERROR at the first poll (6 s). The web API did not accept a sequence for a structure search; no `predict` / ProstT5 option appeared in the documented API (https://search.mmseqs.com/docs/: parameters q, database[], mode all|summary, email) or the database list. Local Foldseek can do ProstT5 3Di from FASTA (README: `foldseek createdb db.fasta db --prostt5-model weights`), which gives 3Di only, no C-alpha, no TM-score.
- Limits: no usage limit text found (README and the API docs say none; the README states the webserver exists for "seconds" searches). Tickets used: 3, ticket polls about 9, result 2 + download 1. Foldseek's own tool needs the query as a structure file (PDB/mmCIF).
- RCSB `service: structure` with a model URL works (section 1c) and returns embedding scores only.

## 4. Function names for hits (files `uniprot/`, `rcsb/`)

- UniProt, one accession or several: `GET https://rest.uniprot.org/uniprotkb/search?query=accession:P0A7G6+OR+accession:P0A9X9&format=tsv&fields=accession,id,protein_name,gene_names,ec,go_id,go,annotation_score,reviewed,organism_name,xref_pdb` -> 200, 0.60 s, 2.1 kB (`function_fields.tsv`). Columns: Entry, Entry Name, Protein names, Gene Names, EC number, Gene Ontology IDs (`;`-separated), Gene Ontology (GO) (names with ids), Annotation (score 1-5), Reviewed (`reviewed`/`unreviewed`), Organism, PDB. CspA: GO:0003677 DNA binding, GO:0003723 RNA binding, GO:0009409 response to cold, annotation 5.0; EC empty. RecA: protein name `Protein RecA (Recombinase A)`, EC empty (UniProt gives none), 18 GO ids incl. GO:0003697, GO:0004520, GO:0140664, annotation 5.0. An enzyme example, `accession:P00350&fields=accession,protein_name,ec,annotation_score,reviewed` -> EC `1.1.1.44` (`ec_example_P00350.tsv`).
- JSON form: `GET https://rest.uniprot.org/uniprotkb/P0A7G6.json?fields=accession,protein_name,ec,go,annotation_score,reviewed` -> 200, 0.51 s: keys `entryType` (`UniProtKB reviewed (Swiss-Prot)`), `primaryAccession`, `annotationScore`, `proteinDescription` (recommendedName/alternativeNames with evidence codes), `uniProtKBCrossReferences` (GO).
- PDB entity -> UniProt: RCSB `polymer_entity/{entry}/{entity}` (section 1c) gives `uniprot_ids` and the SIFTS coverage; PDBe SIFTS: `GET https://www.ebi.ac.uk/pdbe/api/mappings/uniprot/1u94` -> 200, 0.69 s: `{"1u94":{"UniProt":{"P0A7G6":{"name":"RECA_ECOLI","mappings":[{"entity_id":1,"chain_id":"A","unp_start":2,"unp_end":353,"start":{"residue_number":5},"end":{"residue_number":356},"identity":1.0,"coverage":0.997}]}}}}`. PDBe names: `GET .../pdbe/api/pdb/entry/molecules/1u94` -> 200, 0.53 s, `molecule_name`, `synonym`, `length`, `in_chains`, `source`.
- A Foldseek AFDB hit already carries the UniProt accession in `target` (`AF-P0A9Y0-F1-model_v6 Cold shock protein CspA`); a pdb100 hit carries PDB id, assembly and chain (`1mjc-assembly1.cif.gz_A`) plus the PDB title.
