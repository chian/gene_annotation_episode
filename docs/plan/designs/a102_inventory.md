Names: LIB = `gene_annotation_episode/episodic_workflow/episode_support`; A102HEAD = `gene_annotation_episode/episodic_workflow/root/a102/structural_homology_evidence`; A101HEAD = `gene_annotation_episode/episodic_workflow/root/a101/sequence_homology_evidence`.

"Live importer" means: imported by something that a run imports today (A102HEAD, another axis, `episode_runtime`, `method_loop`). Method: `git grep` of the module path outside tests. Note that A102HEAD does not import today (section 5), so "imported only by other A102 library files or by A102HEAD" means no running episode uses it.

### 1.2 Outside endpoints (exact URLs), request, and what is kept

All structure acquisition is plain HTTPS GET with no query parameters (`self._http(service, url, {}, media_type, max_bytes=..., follow_redirects=False)` through `_bounded_provider_get`). No authentication, no token, no POST. Each call has a caller-set `max_bytes` bound; the response bytes are read up to that bound and the request arguments are attached to the snapshot as `request`.

| Service | Operation (A102 tool name in `task.py`) | URL | Request | What it keeps |
|---|---|---|---|---|
| RCSB PDB | entry metadata (`public_rcsb_entry`) | `https://data.rcsb.org/rest/v1/core/entry/<entry_id>` (`entry_id` matches `[A-Za-z0-9_]+`, URL-quoted) | GET, media type `application/json`; arguments `entry_id`, `fields` (list), `max_bytes` | `SourceSnapshot` (service `rcsb_pdb`, url, retrieved_at, content bytes, request), the receipt, and a source record with artifact |
| RCSB PDB | structure file (`public_rcsb_file`) | `https://files.rcsb.org/download/<entry_id>.pdb` (format `pdb_3x_text`) or `.cif` (format `pdbx_mmcif_text`) | GET, `application/octet-stream`; arguments `entry_id`, `file_format`, `max_bytes` | same |
| AlphaFold DB | prediction metadata (`public_alphafold_prediction`) | `https://alphafold.ebi.ac.uk/api/prediction/<identifier>` (identifier is a UniProt-style accession, URL-quoted) | GET, `application/json` | snapshot, receipt, source; the decoded metadata is the authority for the next call |
| AlphaFold DB | structure file (`public_alphafold_file`) | not built by code: the URL the metadata advertises, selected by a JSON pointer (`url_pointer`) into the retained metadata, accepted only if scheme https, host `alphafold.ebi.ac.uk` or `www.alphafold.ebi.ac.uk`, port 443 or none, no credentials or fragment, path `/files/<name>.pdb|.cif` | GET, `application/octet-stream`; arguments `metadata_source_ref`, `url_pointer`, `file_format`, `max_bytes` | snapshot; file association record (metadata source ref, metadata artifact ref, advertised URL) |
| EMDB | entry metadata (`public_emdb_entry`) | `https://www.ebi.ac.uk/emdb/api/entry/<EMD-nnnn>` (id matches `EMD-[0-9]+`) | GET, `application/json` | snapshot, receipt (no density map is fetched) |

Neighbouring (not structure) endpoints in the same client: UniProt `https://rest.uniprot.org/uniprotkb/search`, NCBI BLAST `https://blast.ncbi.nlm.nih.gov/Blast.cgi`, EBI HMMER `https://www.ebi.ac.uk/Tools/hmmer/api/v1/...`, Europe PMC `https://www.ebi.ac.uk/europepmc/webservices/rest/...`, NCBI Entrez `https://eutils.ncbi.nlm.nih.gov/entrez/eutils/*.fcgi`.

No code in the tree takes a protein sequence and looks up a structure by sequence (no PDB sequence search, no UniProt-to-AlphaFold mapping call): each tool takes an explicit entry id / accession. (Searching only the files listed in the brief and `git grep` for `rcsb|alphafold` in LIB; I did not read every line of `acquisition.py`.) Predicting a new structure is not implemented: `knowledge/structural_homology_evidence/native-structural-homology.md` says novel-sequence folding is "a separate explicitly configured remote/API/HPC job" and `structure.model_request` "publishes the missing-model need to the shared parent".

### 1.3 How A102HEAD reaches them

`A102HEAD/task.py` defines `public_rcsb_entry`, `public_rcsb_file`, `public_emdb_entry`, `public_alphafold_prediction`, `public_alphafold_file` as tools. Each calls `run_tool(name, ...)`, which builds `ToolRegistry(ctx.store, **ctx.settings.get('tool_registry', {}))` (old class, `LIB/tools/structural_homology_evidence/tools.py`) and `registry.execute_async(name, arguments, scope=..., operation_key=ctx.operation_key, permitted_record_refs=...)`. The `task.py` module docstring itself says "The library tools themselves call ToolRegistry over ctx.store: library not carried" and names `BLOCKED-ON-TOOL-CATALOG-SERVICE`. So the custody store is handed to an old registry that expects the old Store API.

(a) **Pure-Python CA superposition** (no external program): `calculations/protein_structure_calculations.py` (section 2), run inside a "protein structure" worker by `jobs/protein_structure/*` and `tools/protein_structure/native_protein_structure_*`. ### 4.1 The native index B

Computed in **`grading/structural_homology_evidence/scoring.py`, function `geometry(distances, target_length, reference_length)`**:

- `n = len(distances)` (paired CA positions), `rmsd = sqrt(fsum(d^2)/n)` computed by this function from the list of paired CA distances (not the program's printed RMSD), `coverage = 2n/(target_length + reference_length)`, `kernel = 1/(1 + (rmsd/2)^2)`, `B = coverage * kernel` (0.0 when `n = 0`). Output keys: `profile, n_pairs, target_length, reference_length, target_coverage, reference_coverage, symmetric_coverage, rmsd_A, rmsd_kernel, global_scale_A (2.0), B, status`. Profile string `VERSION = 'a102_rmsd_2A_features_1A_v1'`.
- Fields it is computed from, taken from the native record built by `native_worker._native` (schema `a102_native_alignment_v1`): `distances_A` (distance after the program's transform, recomputed by code from the staged 0.001 A CA coordinates), `target_scope` (two integers; the target length used is `scope[1] - scope[0]`), `reference_length`, `supplied_length`. Optional `distance_rounding_bounds_A` gives low/high `B` (`B_rounding_interval`).
- `grade_comparison(native)` wraps it: requires schema, a unique injective pairing, `atom_selection == 'CA'`, model origin in `{experimental, predicted, supplied_unknown}`, identity fields `target_ref, reference_ref, comparison_group, variant_ref`, boolean `primary`; marks self-copies ineligible (`self_structure_copy`, `self_coordinate_copy`); returns schema `a102_comparison_grade_v1` with `components`, `eligible`, `exclusion`, `interpretation`, `function_specific {status 'not_assessed', F, E}`, `native_input_sha256`.
- `compile_native_sheet(grades, *, target_ref, supplied_length, regions, evidence_regions)` builds the target sheet `a102_native_sheet_v1`: per required region the maximum `B` over the single primary variant of each comparison group (recomputed on the positions inside the region), then the geometric mean over regions; keys `schema, version, axis 'A102', value, profile, scope, regions[{start,end,value,comparisons[]}], excluded, comparison_count, status ('derived'|'not_observed'), interpretation, function_specific_index, full_target_index`.
- `feature_sheet(grade, definition)` (schema `a102_feature_sheet_v1`, F = mean `1/(1+(d/1 A)^2)`, `E = B * F`; feature states `measured | established_absent | established_incompatible | unresolved`, unresolved gives bounds `[0, 1]`) and `contrast_panel(...)` (`a102_contrast_sheet_v1`, best supporting E minus best witnessed incompatible E) are in the same file.
- Other grades named in `docs/axis_restructure_20261117/INVESTIGATION_FINDING_FEATURES_a102.md` (the owner-review proposal of finding features): attachment sheets `reference_fold_native_map_and_local_distance_v1`, `feature_geometry_local_scaffold_v1`, `contrast_from_qualified_local_features_v1`, `local_trait_<kind>_v1`. I read the headings only.
