## Recurring bases and scientific inserts

Child scientific literature decisions retain the complete existing
EXPERIMENTAL_TASK, not a new eight-paragraph common replacement. The parent
retains the complete existing REFERENCE_PARENT_TASK and its actual caller job.
Both retain applicable ordinary SAVED_NUMERICAL_RETURN_TASK and the original
typed contracts. Complete scientific inserts are selected using actual task/
information evidence below; they are never shortened because STEERING is curt.

Proposed pure helper:

```
selected_literature_task_sections(state, lookup_results=())
    -> tuple[(aspect_code, complete_task_text)]
```

It reads only actual assignment, original requested-form meanings, authenticated
host-owned-work metadata, actual outcomes/admitted rows and explicitly returned
lookup/history information. It does not choose operations, read papers, load
private sheets, score evidence, call models, write state or add observations.
It does not infer scientific relevance from words in a paper title, source
inventories, a capability flag or mere registry membership.

Supplemental kinetic log-model TASK belongs to an actual requested
literature_kinetic_model_cells/kinetic-model operation or actual corresponding
work/evidence. It is not the default native-parameter TASK. Constructor format
support and TASK selection support are separate: existing other families remain
available to their existing workflow; adding them to a TASK trace does not add
them to the seven-family worksheet constructor.

Select a scientific aspect if any of the following inputs positively identifies
it. Form/assignment choices affect instructional scope, not source truth or
permission to populate unrequested cells:

1. The parent explicitly selected its finite assignment roster (the exact
   seven assignment keys are in mapping002), or the original requested form
   contains the exact registered source field/explicit selected alias. A family
   with an empty roster can still have requested interpretation meaning; the
   full relevant instructions do not require a populate action or invent cells.
2. Actual owned selected work is known from original run/episode-bound output
   metadata, including a completed useful partial result. See the metadata
   contract below. An attempted failed action is handled separately; it is not
   represented as completed owned work.
3. An actual admitted row from an ordinary child form, owned selected outcome
   or current typed report update identifies the family/version. The current
   scope/version and requested side/population remain intact. The mere existence
   of a source/receipt ID or a source in the global store is insufficient.
4. The episode explicitly requested the operation/return contract information
   or history information described below, or supplied an explicit selected
   scientific process whose full instructions already define that aspect.

Ordering is presentation only: preserve explicit requested section order, then
first occurrence of actual returned/lookup aspects, with each full insert once.
It is not an experimental itinerary or action priority. Explicit caller scope,
constraints and substantive selected process guidance are never stripped while
deduplicating identical inserts.

## Capability-only markers are not actual work

Current `LiteratureEpisodes.initial_decision_context` and `decision_context`
set these solely from enabled booleans:

| Current marker | Current sole flag condition | Why insufficient |
|---|---|---|
| literature_completion_time_work | completion_time_population | An installed capability is not a selected completion-time question or result. |
| literature_active_site_work | active_site_population | Available titration reading is not an actual active-site investigation. |
| literature_product_partition_work | product_partition_population | Enabled product-partition arithmetic is not selected evidence. |

The current prompt `_task` appends all three TASKs from these markers, and the
reference-parent `_task` does likewise. That is a concrete construction defect.
Any other flag-only markers (for example an enabled ratio-source or gel path)
must be audited by the same criterion, not presumed evidence from their names.

Current compiled/summary/product work markers have more qualified producers
(assignment rosters or repository work). Those can reflect actual owned or
received information. The selector must use their audited producer meaning,
not declare every `*_work` spelling trustworthy. In particular the compiled
v1/v2 marker cannot select v3 merely because both share the same operation.

The minimal later host change is a read-only helper in LiteratureEpisodes:

```
_owned_population_task_sources(context) -> tuple[registered_source_code]
```

This is host context metadata, not a new report fact or durable table. It
enumerates only enabled, installed existing operation tables; filters original
rows by exact context.run_id/context.episode_id; selects only the successful
original result's sheet_ref/status metadata; verifies the corresponding source
provider/record version and scope/receipt possession already known to that
episode; and returns the mapped family code. It reads no numeric cell bodies,
private source artifacts, model conversations or provider logs. Discovery creates
no tables. Unavailable/malformed metadata is not positive evidence of owned work.

Use existing repository metadata conventions, without assuming that all legacy
repositories implement `has_work` or `owned_sheet_refs`: completion-time,
active-site and product-partition currently inherit their common repository
but do NOT expose the newer has_work helpers. Do not add calls to nonexistent
methods. Their actual selected operation tables and provider/version metadata
already exist and can supply this bounded read-only classification.

| Existing legacy work | Actual original operation table | Provider/version classification |
|---|---|---|
| Completion time | literature_completion_time_operations | literature.a105.completion_time_population / literature_completion_time_record_v1 |
| Active site | literature_active_site_operations | literature.a105.active_site_population / literature_active_site_record_v1 |
| Product partition | literature_product_partition_operations | literature.a105.product_partition_population / literature_product_partition_population_record_v1 |

The seven supported family routes use their existing provider/version/operation
metadata. Compiled v2 and v3 share an operation table/provider and are separated
by the actual source record version, never the generic capability flag. Native
kinetic and summary share a public operation name but have distinct selected
operation tables and source versions.

For new contexts, remove the three unconditional marker emissions and feed
the pure selector the authenticated host family-code list using the proposed
context key `literature_owned_population_sources`. This is the exact proposed
representation. The pure selector ignores the three old bare flag-only markers,
including when an original saved context contains them. Other legacy work
markers cannot act as standalone positive inputs either: assignment, actual
family-code metadata or admitted result evidence must independently support them.
The list stays outside displayed STEERING and supplies no numerical observation.
Received evidence comes from its admitted rows, not from an ownership label.

## Exact boundary and event traces

| Event/input | Selector input used | Full TASK behavior | STEERING/accounting |
|---|---|---|---|
| Initial child commission | Original scoped child assignment, requested form/aliases, explicit scientific guidance | Child EXPERIMENTAL_TASK plus exactly selected full aspects; do not import parent's private TASK/history | Initial supplied facts only; no fabricated prior yield or completed work. |
| Initial reference-evidence parent | Its caller question/material/scope and own requested form; actual owned metadata if any | Parent REFERENCE_PARENT_TASK; capability catalogue alone appends no experimental aspects | Available operations remain discoverable; no source row becomes knowledge merely by catalogue presence. |
| Requested seven-family field | Exact registered source plus matching finite roster | Corresponding complete mapping above, even when current result is a valid unknown | Necessary units, status and source/scenario qualifications only. |
| Completed owned operation | Original operation name/version + actually owned result source classification | Exact branch's full TASK recurs on later decisions; completed partials qualify | Its actual numerical result/failure meanings; one ordinary observation for the selected completed own action. |
| Child return to parent | Only requested admitted exact row families and constrained interpretation context | Parent retains its own full job; relevant scientific aspect guidance can remain full, never a substitute child job/history | Terse received numbers and qualifications; one original returning child contribution observation, not one per section. |
| Nested forwarding | Desired-order admitted family intersection plus narrowed relationship selectors | Forwarding episode retains its own assignment and full relevant guidance | No extra private upstream cell hydration, orphan positive link or independent-evidence count. |
| Operation contract lookup | Actual completed explicitly requested operation-contract result | Complete task(s) for its real branch alternatives, labelled distinctly as alternatives | Contract information is instructions, not experimental evidence or completed action. |
| Return contract lookup | Actual completed requested exact source-family declaration | Only that family's complete TASK | No numerical sheet/provenance dump or observation. |
| Explicit history lookup of own action | Original selected tool/version and requested admitted outcome subset | Exact relevant branch's full TASK recurs; no task inferred from arbitrary source wording | Show requested recorded attempts/outcomes/qualifications, not entire recipes/private history. |
| Failure/repair | Concrete selected attempted tool/version from actual selected action/history, if available | Keep the attempted aspect's full instructions for meaningful repair even with no completed numerical output | State actual failure and necessary repair information; no successful-work claim or extra observation. If branch unknown, keep common instructions without guessing one. |
| Reconstruction/next iteration | Original assignment/form plus original admitted/owned/lookup information | Same full relevant instructions; do not depend on transient conversation history | Original facts/conditions/expectations survive; no source reacquisition, re-grading or history rewrite. |

The failure trace does not retain every past attempted method forever. It keeps
the most recent/relevant attempted aspect while that repair affects the next
decision, or an explicitly selected earlier history item. Previously acquired
aspects continue through actual available results/returns and the ongoing task.
Repeated navigation and obsolete failures do not expand STEERING without bound.

the branch for ongoing work. Both actual lookup information and selected branch
remain distinguishable in the retained decision inputs.
