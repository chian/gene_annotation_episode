# Proposed FBA projection examples and verification boundary

No tests, application imports, native solver, model call or projection prototype
were run for this source-only audit. All cases below are future meaningful tests
against the proposed interface. The numerical examples explicitly distinguish
retained earlier calculations from synthetic missing-data examples.

## 2. Explicit synthetic partial-row examples

These are deliberately synthetic expected behaviors, not authentic native
measurements and not executed tests.

**Sparse effective model.** Expected reaction population 3; retained native

**CSV without a model.** Retain source_row_indices [0,2], with row 2's actual
token "6.0", value 6, state present, precision unknown and float_hex null.

model_association, filter flux minimum 10, window offset 0 limit 3. Numeric row 2

filter_match=unknown, existence=unknown, source_row_not_retained and null selected
values. expected_count=null, retained_count=2, selected_row_count=3,
matched_row_count=0, filter_unknown_row_count=2, filtered_row_count=2,
returned_row_count=2 and has_more=false. The result asserts neither a 3-row CSV
nor a 100-row CSV. Without the filter, row 2's actual qualified flux returns.

**Native/CSV disagreement.** Use an explicitly synthetic sheet and calculator
fixture whose native reaction flux is 6 and CSV flux is 5, and whose retained
calculation says csv_minus_flux=-1 and csv_flux_comparison=conflicts under a known
precision/tolerance. The projection copies those three values. A separate case
has the same numbers but precision unknown and comparison unknown; projection
must not change unknown to conflicts by repeating the arithmetic. A later saved
recalculation may change the comparison only through the existing calculator.

**Incomplete sparse constraint.** A calculator fixture has expected_term_count
null, available_term_count=2, activity missing with term_population_incomplete.
Return those values unchanged. Do not substitute retained term-array length 2
for expected count, and do not compute a partial activity from surviving terms.

## 4. Inspected consumer seams and limits

The four complete analogous NMF modules were read: expression_nmf_result_views,
expression_nmf_result_contracts, expression_nmf_return_views and
expression_nmf_returns. Its whole native_expression_nmf_results and
expression_nmf_result_worker modules were also read. Additional complete relevant
functions were read from result receipts, execution_episodes, runtime,
communication and scientific_process_prompt; exact coverage is in INSPECTION_001.

The NMF facts/return modules demonstrate an appropriate **separation**: a pure
projection, exact registered facts, separate saved File references, and a host
returns class that authenticates original immediate-child deliveries. They do
not justify copying NMF's scientific-completion predicate into FBA. The NMF worker
and publication path use fit eligibility/success predicates that FBA must not
adopt as a requirement for returning infeasible or partial original results.

Relevant future consumers:

* The bounded FBA result worker invokes the existing parser/sheet/calculator and
  project_fba_result, then saves sheet, calculations, projection and diagnostics
  separately. Saved mode invokes no native producer or acquisition.
* Its result host validates immutable output and exact selection before factual
  publication. Host paths, receipt identities and acquisition/closure evidence
  are stored alongside the projection, not injected into it.
* communication._compile_closed_schema registers the exact FBA top-level fact
  schemas. execution_episodes.fact_sources and received_report_sources expose
  only actual bound capabilities; received_report_facts uses the FBA returns
  adapter at closure. runtime.report_sources/facts merge those requested sources.
* The separate FBA returns class follows actual received forms, preserves frozen
  forwarding witnesses and admission order, and grants only explicitly received
  saved-sheet references. It must not recursively expand native provenance.
* scientific_process_prompt._steering currently generically flattens admitted
  child reports. FBA needs its own later reviewed selection/rendering boundary;
  no current NMF handling proves FBA presentation is settled.
