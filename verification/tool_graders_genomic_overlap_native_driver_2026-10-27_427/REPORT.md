## Implemented behavior and ownership

`prepare_local_genomic_overlap` requires the actual durable pending
`practical.job.start` intent, original assignment and allocation, and exact
derived action directory. It freezes the plan/invoke records and calls only
the existing `native_lifecycle.prepare_job`. Preparation stages no scientific
input, probes no software and starts no service. `local_genomic_overlap_plan`
authenticates the original request bytes, handle tuple, assignment, policy and
safe paths without dispatch, status collection or scientific reads. Existing
host lifecycle dispatch remains the owner of starting/resuming a reservation.

`run_genomic_overlap_driver` verifies the selected interpreter and code pins,
retains original input bytes, calls the unchanged G1 `parse_region_set`, retains
the full parsed occurrence map, and writes canonical BED4 with G1 tokens. It
executes the explicitly bound `bedtools intersect -a A -b B -wo -sorted` once
per selected eligible pair. The version probe runs once only when native work
is needed. Native bytes go directly to complete files. Independent pair seals
precede the batch seal. `main` accepts the original plan path and returns 0 only
for a complete batch.

Missing inputs, rejected mismatched bytes, invalid input, analytic empty input,
present zero-byte successful output, unavailable software and actual native
failure remain distinct. Implementation mismatch preserves independently
verified originals but invokes no unqualified G1 parser. Sealed replay validates
original bytes without native execution; an unsealed attempt cannot resume a
suffix. Original publication/log failures can leave an explicitly unsealed
attempt with retained bytes. No scientific calculator, resource selection,
retry policy, cancellation policy or observation/credit writer was added to
the driver.
