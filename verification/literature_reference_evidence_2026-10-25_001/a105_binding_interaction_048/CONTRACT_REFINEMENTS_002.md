# Additive contract refinements after parent review

The parent released only the new calculator, its new tests, and this directory. These refinements supersede conflicting details of PROPOSAL.md before coding.

1. Input adds `comparison_scope`: `reported_protocols` or `common_conditions`. Common-condition relationship status is `matched`, `not_matched`, `unknown`, or `conflicting`. Common-condition comparisons require `matched`; actual reported-protocol arithmetic can survive other statuses with explicit qualifications. No protein-input-ratio correction is made.
2. Each operand retains exact literal `context` labels and separately source-assigned `canonical_ids`. Within each subject pair, known canonical subject, construct, state, parameter definition, readout and normalization IDs must match and be supported by the pair relationship. Unknown required IDs withhold that pair; differing IDs conflict. Canonical reference ligand IDs must match across the reference-ligand roles, likewise test ligand IDs; the two ligand IDs must differ. All parameter-definition IDs must match for the full interaction. Cross-subject readout/normalization differences remain actual-protocol qualifications rather than silently asserting equality. Preparation and experiment IDs are retained; unknown preparations establish neither sameness nor independence. Physical fits, source token locators and exact estimate keys remain distinct identities.
3. All source witnesses use a closed union naming source/artifact plus one of: UTF-8 byte span `[start,end)`, image pixel region `[x0,y0,x1,y1]`, or table cell (table ID, zero-based row, column). Numeric operands additionally retain source expression. Thus a Methods paragraph or footnote can directly support a relationship without posing as a numeric parameter row. Source custody/byte and image extents remain outside this pure calculator.
4. Confidence intervals require two ordered endpoints and a source confidence level, not symmetric SD; unreported spread cannot carry a number. Exact counts must be at least a source minimum count. No count or spread is promoted into covariance.
5. A model with variance status `unknown` may retain a validated full covariance or null, but cannot use it to populate V/S/B. Known/estimated models require the full matrix and all four supplied physical owners. Exact model estimate keys hash the complete operand record, parameter kind and nM unit; physical IDs remain separately visible. Model reporting-event status is `unknown` or `source_defined`, with a source witness required for the latter. Censored likelihood is unimplemented even with a source-defined reporting event; that is distinct from not knowing the reporting event.
6. Log differences and standard uncertainties use `dimensionless`; V uses `dimensionless_squared`. Each dependent cell preserves its earliest specific unavailable cause. Source thresholds have a separate threshold field, never a point value; range failures affect only representations that fail. S/B require uncensored points, known covariance, normal log-estimate model and positive V.

The complete module docstring and synthetic fixtures will show the exact closed structures. No existing storage, reader, prompt, catalog, runtime, annotation-credit aggregation or shared kinetic integration is changed.
