# Bounded A105 common compilation audit 214

The next concrete repair is component-scoped uncertainty in the existing source-assay compiler. It already returns `q/E` and `q/(kE)` means but cannot receive their own smaller joint covariance. This blocks a numerical precision contribution even when the relevant uncertainty is supplied. It does not justify adding more reader namespaces or declaring A105 complete.

This is an engineering audit of a bounded implemented subset, not a new literature review or a claim of coverage of all 142 case groups. No paper or retained paper-specific scientific packet was inspected. All executions here use explicitly synthetic fixtures. No existing repository file, goal, amendment, production code or production test was changed. Exactly ten evidence axes remain the larger system; this audit concerns A105 only.

## Reproduced gap

`diagnostic_003.py` uses a hash-verified copy of the frozen 209 baseline, not the concurrently changing checkout. It runs the actual `LiteratureEpisodes.execute` operation `literature.assay.components.populate`, then obtains saved facts, builds the exact registered compiled form and calls `validate_report`.

The upstream optical reader/calculator/storage and active-site reader/calculator/storage are populated by the existing synthetic 185 setup. Only the actual q and E selectors remain selected. g, k, u and v are absent, their correction stages unknown; they are never padded with zeros or ones. Result: q≈1.8 uM/min, E=2 uM, q/E≈0.9 per_min. Corrected activity and its variance remain unavailable, as they should.

A separately stipulated **synthetic**, owned covariance for q and E is then supplied: `[[0.04,0.005],[0.005,0.01]]` in the corresponding canonical mixed units. Exact owners, units and dependency lists come from the actual retained extraction. This is not uncertainty reported by a paper, nor a claim that the setup's optical source already supplied covariance: its saved covariance is explicitly null. The diagnostic distinguishes lack of source uncertainty from lack of support for receiving a two-owner covariance when one is supplied.

The two selected attempts return:

1. Actual order `[q,E]`: `compiled_covariance_order_or_version_mismatch:covariance`.
2. Six role names with only the two actual owners, without fabricated owner records: `complete_covariance_owners_required:covariance`.

For the partial statistic a=q/E, the independently computed Jacobian is `(1/E,-q/E²)`≈`(0.5,-0.45)`. The full signed expression is `Var(a)=Var(q)/E² + q² Var(E)/E⁴ - 2q Cov(q,E)/E³`≈0.009775 per_min²; standard uncertainty≈0.0988685997 per_min. This quantity requires neither the four missing corrections nor a residual variance for a different fully corrected estimand. Every returned compiled row instead carries `partial_uncertainty_status=unimplemented`. The implementation also expressly lists `partial_normalization_uncertainty_unimplemented`.

The input reader's `_covariance` requires exactly six roles and six present owners. The calculator's `_matrix` requires 6×6. `populate_compiled_assay` calculates q/E and q/(kE) separately, but calls the six-operand activity calculator for all uncertainty outputs. Storage's schema fixes partial uncertainty to `unimplemented`; the renderer repeats that limit. Thus this is a complete selected-path limitation, not just an absent helper function.

Earlier diagnostic attempts are retained honestly. Attempt 001 failed an overly exact oracle comparison against decimal 1.8 while the upstream retained floating result is near 1.8. Attempt 002 reached a preceding model-witness requirement, not the target covariance boundary. Attempt 003 supplies the existing fixture's explicit synthetic covariance/model stipulation as a witness, keeps the observation model `none` and variance status `estimated`, and asserts the exact two target failure codes. Only attempt 003 supports the covariance conclusion.

## Exact proposed repair interface — same compiler, explicit compatibility

This is an implementation proposal for root review, not a goal amendment or adopted policy.

1. Keep the v1 request variant, frozen v1 record versions, v1 projected row schema and all saved values readable exactly. Do not silently change `partial_uncertainty_status` in existing v1 records, reinterpret saved scientific values, or recalculate cold saved records.
2. Add an explicitly versioned v2 request variant to the **same selected compiler operation**. Suggested marker: `population_version: a105_compiled_assay_population_v2`, with the existing source/assay/operand/relationship/stage fields and an ordered list `covariance_source_refs`. Legacy requests without the marker remain the original closed v1 variant; no implicit migration. Each selected source uses `version: a105_compiled_assay_covariance_v2`, the existing fields `primitive_order`, `operand_keys`, `primitive_units`, `dependency_keys`, `covariance`, `origin`, `basis`, plus explicit `variance_status` known/estimated/unknown. `primitive_order` is a nonempty unique subset of the six named roles. All parallel arrays have N entries and the matrix is N×N. Every listed role must be a selected, possessed, numerically eligible operand with its exact canonical quantity owner, units and dependency keys. No entries or owners are invented for omitted roles.
3. Validate finite/symmetric/PSD covariance and repeated-owner constraints just as rigorously as v1. The declared order need not match the formula order: select the exact principal submatrix by named roles. A larger actually owned joint block may supply a marginal component's uncertainty. Two blocks that overlap must not supply contradictory entries/owners; either require exact agreement or return a specific unsupported ambiguity. Never complete missing cross terms by zero, assume independence from different labels, or assemble several unrelated marginal blocks into a joint block.
4. V2 adds distinct components to the **same compiled sheet**, for example `measured_endpoint_per_selected_amount_propagated_variance` and `_propagated_standard_uncertainty`, plus the corresponding q/(kE) components. Each carries `estimand_component`, selected covariance source/ref/order, exact operand keys/dependencies, variance status, propagation order/model and unavailable reason. q/E uses J=(1/E,−q/E²); q/(kE) uses J=(1/(kE),−q/(k²E),−q/(kE²)) on named q,k,E. Do not require unrelated g/u/v owners or a distinct fully corrected residual. Missing source covariance yields `component_covariance_unreported`; a block that does not cover required owned operands yields `component_joint_covariance_not_supplied`; unknown status remains unknown. Estimated covariance permits explicitly estimated first-order propagated variance, not known-normal inference.
5. Keep existing `effect_variance` meaning unchanged: it is the full corrected activity's propagated plus supported distinct residual variance. A new `corrected_activity_propagated_variance` can expose known JΣJᵀ separately when all required actual operands/covariance are available, while total variance stays unavailable if a required distinct residual is unknown. Do not relabel partial q/E uncertainty as full corrected-activity uncertainty. Bypassed-stage and native normalized covariance remain explicit unimplemented scope until specifically implemented; no fake algebraic-identity measurement owners are inserted.
6. Prefer a versioned registered fact source `literature_compiled_assay_cells_v2` and `requested_compiled_assay_components_v2`, backed by the same compiler/repository with version-dispatched saved reads. Preserve `literature_compiled_assay_cells` and its exact registered v1 schema. This is transport compatibility, not a new assay, reader family or scientific contribution. `communication.py` currently compares the entire registered schema for equality; simply expanding its component enum or replacing it with an ad-hoc union would break old contracts. Register/validate v2 explicitly, preserve v1, and trace assignment, catalog/203 contract-information lookup, episode operation dispatch, facts, exact report admission, received-form refs, parent forwarding and durable reconstruction for both versions.
7. Extend the full recurring compiled TASK with component uncertainty meanings; keep it substantive on every iteration. Update controlled numerical STEERING and contract-information/203 compaction to recognize both versions and render only requested values. Old saved v1 forms must retain their exact original schema and semantics; current model-facing guidance must accurately distinguish historical v1 limitations and available v2 operations. Tests should prove a useful owned two-input result, nonzero signed covariance, missing/unknown covariance, incompatible owners/units, repeated quantities, mixed v1/v2 saved replay and exact scoped typed return, including no hidden numerical expansion.

This repair is one concrete step toward common A105 scoring, not a declaration of scientific adequacy or a replacement for root's validity/product-relevance work. After it, a coordinated common-sheet implementation still needs explicit links among assay/result/measurement population/functional assertion and dependent/complementary/contradictory evidence. Validity CV or relative loss must not be blindly inserted into the uncertainty of k or counted as independent support. Physical endpoint coupling alone must not stand in for that common scientific structure. W05 target transfer/final annotation credit remains excluded.
