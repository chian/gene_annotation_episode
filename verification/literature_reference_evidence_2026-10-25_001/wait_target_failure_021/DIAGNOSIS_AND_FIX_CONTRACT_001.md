The latter calls `validate_wait_selection` before creating a new action leaf, except an already completed exact wait replay. `validate_wait_selection` checks exact condition structure and, when bound, calls `NativeEventInformation.validate_wait`; without that binding it only rejects native-prefix targets. Ordinary source IDs and unknown IDs therefore pass.
3. `NativeEventInformation._authenticate/_saved/_assigned/_job/_selection/_legacy_assignment/_actual_target/_received/_wait_cursors/_read` authenticate original episode request/scope, assigned or actually received native target, original registry/resource/reservation, and original received cursor. `validate_wait` allows visible native targets only for `state_changed`, rejects unreceived native-prefix targets, and probes native registration for nonstandard names. ## Proposed minimum correction; coordinator review required before editing

One fresh integration owner, after coordinator review, may own ONLY:

- `method_loop/durable.py`: declare a narrow ValueError-family event-target failure carrying constrained `code` and exact `affected_refs`; provide side-effect-free target validation and use the same missing-identity/unsupported-native-event check in backend dispatch. Do not change generic `_row` behavior for unrelated consumers. Do not catch arbitrary KeyErrors or expose execution tokens/private child content.
- `gene_annotation_episode/runtime.py`: preserve native custody checks and apply backend target validation for genuinely new selections before wait/action dispatch. Handle the declared target failure as specific wait feedback in `apply_response`. For already selected incomplete/reconstructed waits, execute/record an ordinary failed action result through the existing ActionFailure path; preserve original condition, decision identity, recorded attempted duration and estimate. Do not preselection-reject such an existing unfinished action outside the ordinary feedback path. Catch only declared wait-target errors, never broad unrelated backend bugs. Completed exact replays must bypass new validation and reuse their existing result/context.
- `gene_annotation_episode/native_event_information.py` ONLY if needed to attach precise affected references to its already existing not-visible/unsupported-event rejection. Preserve original authentication/received-custody logic and error meaning. The new error should remain a ValueError subclass so existing semantic callers remain compatible. No new owner policy.
- A NEW focused test file, e.g. `tests/test_wait_target_failures.py`, with isolated fixtures; leave historical tests unchanged unless separately reviewed.

The intended failure feedback is a small structured record: `status=invalid` or `failed` according to whether dispatch was selected, `category=wait_target`, a declared code such as `unknown_wait_target`, `unsupported_wait_event`, or the already bound native-visibility failure, and the exact offending `affected_refs`. Include selected event/cursor when necessary for repair. State that the reference does not identify an available event target; let the episode choose its next action. Do not supply a substitute target, new timeout, retry action, cancellation, polling cadence or scheduler decision. Storage failures must remain distinct from unknown identities.

Existing ownership is the limit: native assigned/received targets follow current scope/custody; ordinary target resolution currently authenticates durable existence. This investigation found no basis for a new immediate-parent-only rule. Valid exposed descendants/native targets cannot be rejected merely because another episode originally owns them. Where an existing binding forbids a foreign target, preserve that binding's specific rejection and attach affected refs. A claim that every cross-owner ordinary commission is invalid would require a separate authority/contract and is not proposed here.

Required checks for the integration owner:

1. Existing synthetic source and arbitrary unknown event IDs, alone and mixed with valid targets, produce precise repairable feedback and zero action-completion observations/credit/slots; selected timer is never silently used as fallback. A valid first member cannot hide an invalid later member.
2. A subsequent separately selected valid action succeeds in the ordinary loop; failed selection adds no yield sample. The same holds for persisted incomplete invalid wait/reconstruction and subsequent replay; no repeated execution or new model calls are introduced by recovery itself.
3. Native nonvisible/unsupported events keep existing authority semantics and precise offending refs; ordinary valid targets and legitimately received descendant/native targets remain available.
4. Valid execution/native events preserve selected identities, cursors, event provenance, native receipt bytes, original deadline and statistical snapshot; actual successful wait supplies exactly one ordinary observation with zero passing-time gain. Exact completed replay performs no backend revalidation/resampling or new observation.
5. Reconsideration-only waits, race-free selected-set notifications, interrupted wait measurement/recovery and cancellation-safe descendant survival retain behavior. Invalid requests create no backend events, native publication, scientific record, child admission or new work.
6. Failed action feedback remains visible in the next literature parent/child STEERING without shortening TASK, adding a report composer, or exposing private histories. Original605-file pin/run is never modified or restarted.
