## Delivered path

The existing `rate_population` capability now exposes the selected ordinary
operation `literature.measurement_validation.populate`. There is no new feature
flag, episode type, loop, model composer, controller rule or credit binding.
The operation binds the released pure205 reader/calculator to new durable storage
and scientific rendering. Pure205 inputs, calculations and five-paragraph TASK
remain byte-identical to their released hashes.

The new exact recorded source is `literature_measurement_validation_cells`;
`requested_measurement_validation_components` defaults to an empty list. Each
requested component returns every retained applicable measurement instance, in
original measurement order. Row identity is
`(sheet_ref, measurement_key, component)`, preserving within/between precision
bases and repeated components. A raw-control placeholder has a null measurement
key and an explicit unimplemented meaning. Multiple rows do not establish
independent experiments. Repeated bias/loss/RMS views retain their actual shared
dependency/contribution identities.

Population authorizes each source through the owning episode's actual scoped
received references. Recovery and relative-bias operands come only through the
existing recovery repository's `fact_cells` possession boundary. A globally known
sheet does not grant its numerical cells. Original request, selection,
extraction, sheet, received operand snapshots, source metadata and implementation
receipt are retained. The pure205 implementation is attested prospectively only.

Saved reads authenticate content-addressed artifacts, original operation/request,
source/role/selection relationships and exact projected outcomes. They do not
reacquire scientific source bytes, parse the scientific numbers again, recalculate
statistics, invoke a model or compare current scientific code hashes with the
original receipt. The exact new host return is available under the existing
legacy-None alias and explicit contract-information profile. Runtime203 and
episode_contract_information are unchanged.

Scientific TASK remains separate from numerical sheets and curt factual STEERING.
Own results, admitted returns, current forms, requested history and operation or
return lookups use the reviewed scientific insert and typed numerical renderer.
Interpreted and conditional values display in distinct columns. Existing parent
questions and their constrained interpretation fields remain intact.

Source-support quotes mask nominated CV/Z numeric spans by content-addressed
artifact and byte coordinates, including original/text aliases of identical
bytes. When broad table/statistic context contains additional numerical operands
without known spans, projection retains a specific
`unrequested_numerical_scope_unresolved` limitation instead of expanding the
table. The original witness remains saved. Independently selected concise numeric
conditions remain available. Upstream recovery literals have no invented source
anchors and are not automatically expanded. This is a bounded table/statistic
context guard, not arbitrary prose/PDF/OCR numerical-scope recognition.
