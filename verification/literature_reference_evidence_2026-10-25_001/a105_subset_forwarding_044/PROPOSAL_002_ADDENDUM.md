# Original and revised admission contract authentication

Additive update to001 after parent ownership release and full runtime redelivery
consumer inspection. Ownership remains the same two production files and two
new tests; no runtime, optical, numerical schema or TASK changes.

The common base authenticator is named `_runtime_delivery_cells`, distinct from
optical004's `_original_delivery_cells`. Optical retains that entire original
specialization unchanged and additionally calls the common superclass check.
Thus foreign runtime-shaped keys cannot bypass common validation by entering
optical's historically trusted-manual-key branch. Existing optical table names
and `optical_admitted_cells` digest identity remain exactly compatible.

The suffix index must be canonical ASCII integer text in SQLite's representable
nonnegative signed64-bit range. Malformed/foreign/oversized keys and missing
original attempt/episode tables produce structured ContractError; no arbitrary
workflow count or continuation limit is introduced.

For original admission, the successful runtime_report_attempts form/contract
is located by exact run, receiver episode and decision index. Its original
child identity must resolve to runtime_episodes, and the child request's frozen
report_contract must equal the attempt contract. Only fields with this exact
view's x-source are copied. Exact cells are compared canonically to the incoming
or reopened received subset, even when a forged digest also matches changed cells.

A later actual selected `redeliver_report` can legitimately revise the schema
or purpose while reusing the original saved child facts. In that case the base
requires the attempt's actual runtime_actions selection at the same receiver
and decision index to be that repair, its selected purpose/schema to match the
admission contract exactly, and an earlier original delivery_ref belonging to
that same receiving parent and original child. The current attempt's delivery_ref
must also equal that exact selected delivery, and the earliest prior contract
must equal the original frozen child's contract. A generic schema subset/superset
relationship is never authority. The runtime already constructs repair values
from the child's saved facts and permitted unchanged original interpretations;
this repair does not recreate or reinterpret those facts or add a model call.

Pre044 original nonoptical runtime receipts can reopen using that original
form/contract proof alone. The read path and an explicit repeated receive leave
such rows without a newly synthesized binding, preserving exact SQL/history.
Old manual receipts without binding return `literature_delivery_binding_unavailable`.
New manual receives remain explicitly trusted API calls, not proof of runtime
commissioning. A digest alone does not authenticate original runtime admission.

The new tests cover actual synthetic populations across all16 namespaces and
partner's retained/native/defined-unit input variants. The separate nested
shared-loop test exercises scripted real Episode accounting. A two-boundary
C4 test controls immutable synthetic commissions, validates original closed
facts, exercises transactional interruption/repeated admission and read-only
reopen, and rejects receipt-plus-digest expansion. That controlled C4 fixture
does not claim detached process execution or model science. A revised-contract
fixture authenticates the actual repair selection and rejects changed purpose,
current delivery identity or original frozen contract.
Existing optical revised-redelivery/shared-loop tests provide the full existing
runtime repair consumer regression in the affected bounded group.
