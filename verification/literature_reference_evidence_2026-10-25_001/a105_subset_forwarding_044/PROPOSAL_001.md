## Proposed uniform interface

`fact_cells(context, sheet_refs, *, components)` belongs in the base repository.
All16 typed views inherit it except optical, which retains its existing override.
It validates run/view, requested component selection and saved selected sheet.
Actual own sheets use original request episode plus matching selected operation
association; they may project their own requested saved cells. Other-owned
sheets supply only exact `(sheet_ref,component,typed_view)` rows actually admitted
to this episode, filtered by requested components. Global record custody, a
shared run or source ancestry alone does not supply numerical knowledge.
Wrong legacy/native rate views remain rejected, including empty wrong-view
admission behavior already implemented.

`validate_fact_values(context, cells)` will first validate exact saved-cell values,
then require each row to equal that episode's context-aware fact projection.
C7's uniform `_rate_facts` invokes `fact_cells` for every namespace. C7's
`validate_received_report` uses `validate_fact_values` after its existing refresh
of only the reporting child's durable received references; this prevents a
hand-authored expanded outgoing form from bypassing fact generation. It does
not run a possession check on the receiver before the incoming receipt exists.
`received_form_references` continues recording the incoming already-admitted
subset; `received_report_facts` copies only admitted rows.

## Per-view receipt authentication and compatibility

Base `receive_cells`/`received_cells` will bind/revalidate receipts in a per-view
`<family>_delivery_bindings` table, keyed by run/episode/operation, with the exact
cell digest. The existing received table identity fixes provider/view; selected
sheet validation enforces provider and record version. This keeps ratev1 and
rate_source_v2 distinct despite their common operations table. Partner's two
input routes retain their common namespace.

Table names derive from the fixed repository received-table property, replacing
`_received` with `_delivery_bindings`. Digest kinds derive by dropping the fixed
`literature_` prefix and `_received` suffix, then appending `_admitted_cells`.
Consequently optical uses its ALREADY EXISTING
`literature_optical_delivery_bindings` and `optical_admitted_cells` digest, so
pre044 optical receipts do not need a new binding or migration. Its overrides
continue doing their original stronger checks before calling the base, and its
existing `_original_delivery_cells` authentication remains dynamically selected.
All other families gain actual per-view bindings upon an explicit receive call.

Runtime `run:receiver:index:typed_form` keys authenticate their exact cells
against the original successful runtime_report_attempts form and contract,
including original child contract identity where available. Runtime-shaped keys
with another run/receiver or malformed index must not become manual receipts.
Arbitrary standalone keys remain an explicitly trusted manual repository API;
their digest proves preserved receipt identity, not runtime commissioning.
Existing old nonoptical manual receipts without a new binding must return a
structured missing-binding limitation, never receive invented provenance.
Original nonoptical runtime receipts can be validated against the existing exact
successful form/contract without synthesizing a new admission or rewriting
history; final implementation will document whether that read-only compatibility
path is supported or a structured missing-binding limitation is returned.

No source artifact, reader, calculator, model, observation, original expectation
or credit history is touched by forwarding or saved reconstruction. Repeated
admission remains idempotent; valid partial/null/qualified cells retain meaning.
