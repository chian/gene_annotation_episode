# Exact experimental-cell possession and forwarding repair

The confirmed041 failure is repaired: a child returning a rate difference does
not give its literature parent the child's unreturned reference/test rates or
ratio merely because the parent holds the sheet reference. The reporting parent
also cannot bypass that restriction with a hand-authored valid saved row.

## Final implementation

Only two existing production files changed:

* `literature_rate_storage.py`: uniform context-aware owned/admitted fact cells,
  outgoing possession validation, authenticated per-view delivery binding and
  original-runtime form/contract reconstruction.
* `literature_episodes.py`: uniform fact projection and outgoing reporting-episode
  possession validation after only that child's existing durable-ref refresh.

Actual own selected sheets retain appropriate projection. Other-owned sheets
forward the exact admitted `(sheet_ref, component, typed view)` subset. Legacy
and native rate views stay distinct; partner input variants retain one view.
Units, null reasons, censor qualifications, formulas, source meaning and existing
dependency references are unchanged. No additional scientific instructions,
numerical cells, selection router, episode kind, controller rule, model call or
annotation-credit policy was introduced.

Incoming parent receipt is separate from outgoing child validation. Runtime
typed-form keys authenticate the exact successful original form/contract and
original child. A selected repair additionally authenticates its purpose/schema,
current/original delivery identity and original frozen child contract. Actual
repair runs before action publication, so the narrow public decision projection
`response -> '$.selection'` at the exact run/receiver/index, purpose='decision',
supplies that missing selected-action record. Complete provider request/response,
private history and reasoning are neither selected nor loaded. Conflicting
action/decision records fail rather than choosing a convenient one.

New delivery-table DDL belongs only to the incoming receive transaction. Older
authentic runtime receipts reopen from their existing original form/contract
without creating a new binding table or inventing receipt provenance. Old manual
receipts lacking a binding return `literature_delivery_binding_unavailable`;
their original data remain intact. Arbitrary manual receipt keys remain an
explicitly trusted repository API, not evidence of runtime commissioning.

Optical004's entire source remains SHA07128e71f1976f03eb966d09b26ca0b53d285bb1b3ae1946cfa9d7f27ae806ac.
Its existing stronger override checks and old digest/table representation remain.
The new base uses the same representation instead of requiring another binding

## Limits and continuation

These are synthetic engineering and scripted shared-loop checks, with a separate
controlled C4 commission fixture. They do not establish detached worker execution,
model-backed scientific interpretation, primary-source numerical validity, a
completed experiment grader or a completed axis sheet. The older-runtime proof
assumes the same already-established current bound view/operation/receive tables;
older different capability sets retain their own preserved pins.

This repairs communication ownership for existing components. It adds no grader
coverage and leaves the full literature goal active. Case-grounded kinetic,
binding, transport, validity/isolation and compilation work remains with the
parent, as do later appropriate literature axes and W05 handoff. Exactly ten
top-level axes remain; no extra sheet was introduced.

Exploratory failures are preserved in numbered logs/receipts.003 exposed real
redelivery's pre-action publication boundary;004's actual existing consumers
then passed, while three new fixture mutations hit NOT NULL before their
negative assertion.005 corrected those explicit adversarial fixture UPDATEs
and strengthened genuine missing-table read-only reconstruction. No production
authentication was weakened to obtain passing tests.
