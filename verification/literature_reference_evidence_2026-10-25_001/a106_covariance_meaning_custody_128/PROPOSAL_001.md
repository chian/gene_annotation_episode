# A106 covariance meaning custody proposal128

This is an implementation proposal for the fixed literature task, not a goal,
governing amendment, new scoring formula or runtime gate. No primary paper was
read. The constructed122 counterexample and complete affected input, arithmetic,
storage, typed-form, receipt and presentation paths were inspected.

## Meaning currently lost

The supplied covariance, a zero-covariance assumption, and covariance estimated
from paired raw units can yield the same derived variance. Existing typed rows
do not preserve that distinction. Unknown covariance already remains unknown;
its enclosure arithmetic and all other numerical calculations stay unchanged.

## Small input and saved-output extension

Each retained covariance entry may add optional `interpretation_basis`, with
exactly the existing four meanings: source_reported, source_supported_inference,
conditional_assumption, unresolved. Its existing witnessed support remains
optional; missing support adds no calculation gate. The selected kind and
assumptions remain the interpreting episode's responsibility.

Only an input that explicitly supplies this new qualifier triggers a new saved
covariance-descriptor snapshot. Inputs and saved sheets without it retain their
original byte/content shapes. The new snapshot records the three actual arm
pairs and preserves an absent basis as null, never inferred or backfilled.
Explicitly unknown covariance and absent covariance selection remain qualified.

Seven existing statistical components can carry optional
`covariance_interpretations`: perturbation variance/its two bounds use W,K;
restoration variance/its two bounds use K,R; shared contrast covariance uses
W,K and W,R and K,R. Other point/statistic cells acquire no covariance metadata.
Each pair qualifier contains first/second arm, actual covariance kind, nullable
interpretation basis, effective selected variance status, a component-use code,
and anchored support references. It contains no raw numerical covariance or
other unrequested arm measurement. A component that is unavailable retains its
existing reason; its selected covariance is not falsely presented as applied.

## Source support and presentation

A narrow publication hunk creates actual anchored `reference` records for
newly captured covariance witnesses and includes them in the original selected
operation outcome. Labels are fixed nonnumeric scientific-role descriptions.
Full anchors remain durable and exact. Saved metadata validation reconstructs
the expected support identities from retained witnesses without opening source
bytes or recalculating statistics.

A support witness may contain unrequested raw covariance/other-arm values.
Therefore its anchor is not automatically expanded into the parent's prompt.
A narrow A106 presentation mask preserves its received identity and support
handle while omitting that excerpt. The covariance table shows selected kind,
basis, variance status and use qualification, resolving only actually received
support records. Explicit source reads retain their normal behavior.

The same concise table appears after the selected population result and beside
actual admitted A106 rows. No Store lookup, source read, model call or report
composer is added by rendering.

## Compatibility and ownership

Five existing files are the complete planned production scope:

- literature_perturbation_summary.py: optional input qualifier and new-only
  covariance descriptors; no arithmetic/eligibility changes.
- literature_perturbation_summary_storage.py: publication/validation helpers,
  optional component-scoped closed schema and saved projection.
- literature_perturbation_storage.py: the narrow transactional publication hook
  and original outcome references.
- communication.py: retain exact registered55/56 contracts and recognize the
  new optional covariance-qualified contract; no generic grammar changes.
- literature_experimental_prompt.py: A106 covariance table and source-support
  excerpt mask only. Other owners' A108/A110/partner edits remain untouched.

No new module, operation, namespace, sheet, axis or observation is needed.
`perturbation_summary_cells_schema(include_interpretation_basis=False)` remains
the exact original55-field schema. A new explicit keyword disables covariance
metadata to recover the exact56-field schema; both remain accepted as complete
registered schemas. Old payloads and typed receipts are not upgraded. New rows
cannot drop or mutate their captured qualifiers because exact saved-value and
receipt checks still apply.
