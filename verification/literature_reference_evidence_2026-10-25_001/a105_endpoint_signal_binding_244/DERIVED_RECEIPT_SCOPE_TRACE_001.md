The evidence supports three different conclusions:

* Automatic typed return/hydration: the new endpoint implementation MUST keep
  saved private input/sheet/matrix data out of normal parent returns, alias
  hydration, current updates, own-child return envelopes, history, lookup and
  cold reconstruction. Its exact component admission rules and scoped renderer
  are part of244's proposed ownership. This fixture does not prove that future
  endpoint path is installed or verified.
* Explicit new original-source reading: the literature episode may select a new
  authorized reading action on actual original public evidence. The original
  fixture read succeeded and remains allowed. A narrow earlier numerical return
  does not prohibit an independent source investigation under the parent's job.
* Explicit derived-receipt reading: the derived fixture's implementation JSON
  contains more than a nominally admitted component. The generic read does not
  distinguish that custody document from original scientific text. Root must
  decide the exact authorization boundary for new endpoint saved records after
  this trace. No blanket read prohibition or broad runtime gate follows.

No additional production path has been edited or silently claimed as owned.
Within existing244 paths a literature-specific endpoint saved-source check is
possible; a generic nonliterature parent or lower-level material operation has
a different owner. Before any wider hook is authorized it must be tied to an
actual demonstrated endpoint typed-data expansion, preserve original-source
reading, and maintain the existing selected-action/outcome/receipt semantics.
