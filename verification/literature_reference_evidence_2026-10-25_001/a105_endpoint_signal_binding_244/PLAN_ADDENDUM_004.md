# Exact constant-based type check and fresh-cache cold proof

This clarifies the implementation of003's exact registered endpoint type
exception. The scientific schema/request/TASK/paired examples do not change.
Root accepted this approach within the existing newstorage/communication file
ownership. No production file is edited by this plan addendum.

The new storage module will contain a detached immutable-v1 schema definition
`ENDPOINT_SIGNAL_CELLS_SCHEMA_V1`, matching EXACT_SCHEMAS002.return_schema. Its
public `endpoint_signal_cells_schema()` returns a detached copy for ordinary
new contract discovery. The definition is a finite metadata literal/bounded
construction from local fixed declarations, with no scientific reader,
calculator, interpretation, source IO or imported current schema factory.

communication's source-specific depth1 exception compares the submitted whole
endpoint fact node with this exact constant through canonical finite JSON. It
DOES NOT call endpoint_signal_cells_schema(), registered_schema(), a241schema
factory or any scientific validator. The constant check only establishes that
this particular recorded v1 type is allowed; generic authored schemas retain
their existing restrictions. The new binding's endpoint report-source metadata
can copy the same detached constant instead of invoking a factory. Existing
generic grammar, shared runtime and other sources are unchanged.

Saved numerical reads and projections use their ORIGINAL saved schemas,
request, extraction/sheet/row/outcome and identity relationships. They never
regenerate a saved row type or scientific meaning using current factory output.
Original pending alias expansion uses the authenticated saved declaration/map
and its exact original type. The constant equality check does not replace or
upgrade that original snapshot. Future schema changes require a distinct
versioned type; current changed code is not claimed able to reproduce an old
runtime descriptor fingerprint. Historical descriptors still require their
original immutable code pins.

The cold checks must use a fresh interpreter, or explicitly clear
communication._compiled_schema_content BEFORE the FIRST read-only composer and
before any schema-validation warmup. A warm cache cannot stand in for this
proof. The controlled fixture will first preserve the original saved form,
schema, declaration, descriptor, pending request, rows and file hashes, then:

1. Open the FIRST reconstructed Store read-only. Before composition, forbid
   original source/image/recipe bytes and artifact-file reads;241reader,
   detached scientific validator, interpretation/parser, calculator and
   covariance propagation; provider calls; new receipt/admission writes; and
   current selected-operation implementation attestation.
2. Also forbid current registered_schema, endpoint_signal_cells_schema and
   current Workflow report_sources/catalog/action_schema generation for the
   original pending alias-expansion test. Reading the static registered v1
   metadata constant/membership remains allowed; no current schema factory
   function runs. Saved-schema validators continue using saved schema trees.
3. Compose the binding using its original same-pin descriptor. Read/copy exact
   saved rows and validate the original pending alias/literal declaration with
   the cache empty. Assert a real compiler visit occurred through the exact
   constant exception, with no factory calls, scientific work, receipt writes
   or hidden validation warmup.
4. Compare original complete expanded schema/declaration, pending request bytes,
   typed rows, descriptor and file hashes exactly; DB total_changes remains0,
   and operation/receipt/action/observation counts remain unchanged. Absent new
   tables are still absent. No validation result is manufactured by warming a
   cache in the hot fixture first.

This proof supplements the original cold-source/scientific-work blockers; it
does not weaken literal schema/form validation or admit arbitrary snapshots.
All004generic-probe limitations and the narrow owned literature custody rule
in003 remain. No production release or scientific completion is claimed here.
