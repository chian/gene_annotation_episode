# Independent original-result verification method

This workload owns only the two new integration/acquisition test modules and
this evidence directory. It makes no production edits, changes no goal or
accounting record, and does not touch the excluded pending NCBI RID.

## Actual native and Workflow path

`test_native_hmmer_results_integration.py` uses the real Store, shared Workflow,
ExecutionServiceFactory, launch/resource/results bindings, receipt admission,
operational-credit projection, practical completion verifier, native lifecycle,
installed HMMER, original-bundle capture, bounded deterministic worker,
numerical sheets/calculators and observation publication. The parent explicitly
commissions launch and then results; the resource child selects
`practical.job.start` and results selects collect/status. Test synchronization
waits for its tiny launched job before the scripted parent commissions results.
It does not add production polling or an extra controller observation.

Each native request starts from a retained 064 exact program/mode request and
explicitly sets optional metadata to an empty object. Legacy supplied metadata
in those earlier retained requests contains length/alphabet conflicts. The new
request instead uses actual input bytes and validated original biological
sequence bindings. Retained 064 evidence is unchanged. The test subjects come
from those same input FASTA records in one Store problem; an explicit wrong-
sequence test changes one Store residue while preserving the native input.

The numerical comparisons use saved B003 scores. They join actual identities,
occurrences, intervals, axes and origins before comparing every available
closed-family scalar; they never zip independently sorted rows. B003 hmmscan's
larger query population is not mistaken for the 064 single-query request.
New correctly parsed metadata can make previously unavailable values available;
old B003 artifacts remain unchanged. Every successful main case recalculates
the saved sheet with network sockets, process launch and built-in file opening
prohibited, and requires exact score equality and an unchanged input sheet.

All fresh scientific and bounded grading commands use the existing local
lifecycle with 20 GiB RAM, 4 GiB scratch and no wall limit. Main Workflow tests
check the actual lifecycle policy and verified cgroup memory, swap and runtime
properties. Full native files, sheets and scores remain in Store artifacts;
returned forms contain only requested bounded numerical fields and explicit
unavailable values.

## Fixture limits

Decisions are scripted, not LLM-generated scientific choices. The annotation
parent uses an explicit finite verification horizon and an engineering
projection counting only its actually received observation receipts. This is
not W05 or a gene-annotation-confidence formula. Successful execution/results
roles use the production operational projector and practical estimator. Final
actual gain is preserved and verified completion immediately yields expected
future gain zero through the ordinary controller, without a zero-gain turn.

Deliberately incomplete fault cases replace only the test binding's base
estimate with a disclosed finite verification horizon, retaining the real
practical proof checker and operational credit. They verify partial results and
absence of completion proof; they do not claim production completion or
continuation for unfinished assignments. The callback is confined to the test
instance and its use appears in each retained CASE.json.

The capture-only companion copies all 12 retained producer modes, rebases the
realized temporary paths, and supplies a frozen-plan boundary stub. It verifies
complete bytes and failure custody, not launch ownership. Original launch
qualification is exercised independently by the actual Workflow tests.
Malformed manifests, digest/size failures, symlinks, wrong identities, omitted
outputs, wrong biological binding, missing row keys and altered journals are
explicit synthetic faults applied to otherwise actual retained or fresh data.

No API, HPC, authentication, literature, database BLAST, annotation aggregation,
or model-service invocation is claimed. This is the six-program B004 local
result path, not proof that every operation in the immutable goal is complete.
