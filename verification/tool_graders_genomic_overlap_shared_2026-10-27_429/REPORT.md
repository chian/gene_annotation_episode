# Shared genomic-overlap integration verification

This packet verifies selected-operation registration, input authority, native
preparation/observation hooks and fixed execution records. It does not establish
complete results-worker custody or delivery through a full Workflow.

## Implemented boundaries

- `ExecutionEpisodes` exposes the real four-field tool information and exact
  requested-job schema only for a configured local genomic-overlap binding.
  An absent binding does not expose the operation. API and HPC declarations
  cannot claim this local deployment.
- Scientific-parent commissioning, launch initialization, resource-child
  commissioning and resource initialization call the same input-authority port.
  Actual received-source/artifact joins, exact selected paths and protected
  reference checks are required. No native work occurs during commissioning.
  This validates permission to use the supplied dataset; it does not invent
  a biological association between that dataset and the annotation target.
- Shared practical execution prepares the explicitly selected native operation,
  retains the selected attempt, observes actual native status and reads bounded
  windows of declared files. It does not add a monitoring model, retry loop or
  alternate resource selection.
- The fixed pair-manifest validator can validate an independently retained
  original pair seal without inventing missing batch/set records. The existing
  batch-aware validator additionally checks the supplied original set outputs.
- Analytic empty-input completion requires successful canonical publication of
  both inputs. An empty input does not conceal failure to publish its partner.

The commissioning test uses actual Store objects, BindingContext objects and
received-reference records through both launch and local-resource initialization.
It also verifies rejection of a newly substituted unreceived source. This is a
shared-boundary integration test, not a complete method_loop Workflow run.
