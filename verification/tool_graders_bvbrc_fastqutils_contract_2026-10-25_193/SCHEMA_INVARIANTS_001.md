# Closed-schema semantics and compatibility notes

`SCHEMAS_001.json` is a schema asset, not a production implementation or another scoring language. `build_contract_assets.py` generates it reproducibly and a numerical oracle only. Ordinary calculator functions specified in CONTRACT001 own formulas. The schema declares62 native measurement names,17 calculated component names and32 object types. No arbitrary scalar metric names or arbitrary evaluator expressions are accepted.

JSON Schema validation is necessary but insufficient. The production contract validator must reject nonfinite JSON recursively, Python bool as a numerical count, duplicate object keys, noncanonical reference identities, missing/dangling/cross-task references, duplicate IDs, malformed field relationships, inconsistent native counts and mismatched metric/units/axis/meaning. The rule table in CONTRACT001 §5 fixes meaning; parser version chooses interpretation. Preserve negative Phred deviations and signed differences. Native invalid negative counts remain raw tokens with null numeric value and an explicit issue.

Numeric measurement values must be nonnegative integers for actual record/base/pair counts and exact histogram counts. Native GC-smoothed count, scaled counts, percentages and estimates retain their distinct units and meanings. Native rounded/truncated values cannot become exact-count denominators. Metadata indices/ordinals/byte offsets are locators, not scientific scores. Native option values are configuration. Numeric tags with unknown scientific semantics remain typed native tag values and never become generic numerical evidence.

`Cell.state=available` has a finite number; `partial` has a finite number describing only the validated scope; all other states have null value. The lexical token survives malformed/nonfinite native values. Complete empty modules have no rows and a complete raw block; absent modules have requirements. Native status categories remain separate. Zero, N/A, NaN, empty table, missing artifact and upstream failure are different states. A partial document may contain independently available complete cells, provided their populations/locators make scope clear.

A complete acquisition requires both transferred-byte integrity and complete native parsing; a matching SHA of a partial transfer does not prove complete native data. Gzip CRC/ISIZE must validate; plain FASTQ at a `.gz` name is permitted with a mismatch diagnostic. BAM BGZF EOF absence is a warning plus completeness qualification, not automatic evidence that every earlier record is unusable. ZIP member names and raw block ordinals prevent independent native reports from being merged by basename. No HTML graph image is a numerical table.

Source IDs in examples are synthetic tokens. Production IDs must encode or bind original analysis identity + saved object pointer so equality/custody checks can resolve them. One canonical production encoding is `bvbrc_fastqutils_<kind>:<percent-encoded-analysis-id>/<percent-encoded-JSON-pointer>` using strict UTF-8 and canonical percent encoding. The broad local ID grammar in the schema asset must be specialized by C's exact encoder/decoder validator when references are published; it must never be treated as sufficient custody. Raw source filenames/titles can contain characters outside that grammar and remain in native artifacts/records, not silently rewritten.

The corresponding communication identifier namespaces are `bvbrc_fastqutils_measurement`, `component`, `population`, `association`, `stage`, `library`, `artifact`, `category`, `native_label`, `requirement`, and `field` (with the prefix on every name). Native IDs and source labels can be returned only as actual authenticated original tokens. Model prose cannot create a source token. Stored fact records supply `source_ref` in namespace `execution_result`, `field`, and finite `value`; these use the existing original-publication validation/admission path.

`RequestedForm` in the schema is a convenience input document for reviewing selections. It is not the `ResultSelector.requested_schema`. The actual provider's `requested_form_schema(selections)` constructs exact closed JSON Schema properties from `MeasurementFact`, `ComponentFact`, `CategoryFact`, `PopulationFact`, `AssociationFact`, `RequirementsFact`, and `RequestStatusFact`, with `x-bvbrc-fastqutils` selectors. Rebuild and compare this schema on input. Empty/conflicting selection fields fail explicitly. A `request_status` targets an existing non-status field. Measurement/component selectors require the corresponding exact finite metric and saved record reference; categories/populations/associations require the record reference and null metric/target; requirements has null selectors; status uses only target_field.

Provider parameters explicitly select already acquired content bindings and already supplied metadata sources. `producer_version` is a declared expectation, never evidence of deployment: compare it with native reported version, and preserve disagreement or unknown. For each supplied metadata document, C validates the generic `SourceEvidence` custody then A validates the finite `Metadata` shape and relationships. Parent-supplied asserted mappings remain explicitly asserted until native/source evidence establishes them; merely passing typed fields is not proof of actual executed lineage. Pure readers cannot follow the source locator to acquire missing content.

The arithmetic oracle deliberately stipulates complete paired populations and quality histogram. Its sheet is labelled `shape_only_sheet` because it is not a real custody/lineage fixture. Production must require observed lineage and compatible pair evidence before publishing those retention components. This avoids confusing a mathematically valid6/8 with proof that six output reads belong to eight inputs. A must deliver full source-linked fixtures before C/D declare the real path tested.

Keep unbounded native result sets in retained native artifacts and their complete parse/index representation. Caller resource limits may produce typed partial scope, never silent top-N or preview-only scientific storage. Episode-facing facts remain explicitly selected small records. Large FASTQ/BAM parsing should stream under caller-owned bounds; no self-selected resource switch or background process is allowed.
