# Additive corrections after root review

This correction supersedes the P/B and proposed-return statements in BOUNDARY_001.md and PROPOSED_CONTRACTS_001.json. Preserve those files as the initial proposal, not approved report contracts. The current self-contained P/B handoff is PROPOSED_INTERNAL_CONTRACTS_002.json together with this correction.

1. Freeze only pure parsing/normalization (P) and service/publication binding (B). Internal native strings, complete sequence values and full metadata remain unrestricted by arbitrary lengths. They are not automatically legal parent-return strings. All eight initial fact-source schemas and the example parent form in 001 are withdrawn from the coding freeze. R still needs a bounded, parent-selected projection design: exact requested source/record/field selection, reference or explicitly selected sequence window, constrained identifiers/values, native-text retrieval operands, full tuple validation and explicit omission/window metadata. Do not solve that design by truncating native data, calling valid long text invalid, or copying arbitrary paragraphs/sequences into returns. Names/signatures for R remain proposals, not instructions to register 001 schemas. M presentation remains a separate reviewed template. No general provider schema/validator framework is authorized.

2. parse_uniprot_native(..., request=None, ...) has no original request evidence. Page.effective_request is null and request_verification is unknown. The envelope may establish operation=record/search; it cannot establish the requested accession/query/cursor/size. Identity.requested_accession is null and accession_relation is unverified. The legacy parser wrapper must not fabricate a request from primaryAccession. If a canonical request is supplied, request_verification=caller_supplied means precisely that: the pure parser can check returned content correspondence, but B must separately validate SourceSnapshot.request/service/transport against the selected request before publishing a bound result. Unknown original request prevents a new bound API result, not retention of raw bytes.

3. NativeRecord.legacy_publication closes the existing _import dependencies. P alone calculates:
   - source_name and source_name_pointer: use the current legacy ordered candidate list: a nonempty recommendedName object first, followed by submissionNames in original order. The first candidate's fullName.value supplies the legacy name. Do not skip its missing value to invent a name from a later candidate; the current function's next(...) semantics choose that first value, possibly None. Missing/null is None; a malformed non-string value is None plus an issue, with the full native value retained.
   - source_ec_numbers and source_ec_number_pointers: all valid textual ecNumbers[*].value in that same candidate order and original EC order, preserving duplicates. Arrays have equal lengths and each pointer dereferences to the corresponding exact value. A malformed EC creates a field issue without removing other ECs or records.
   - interpretation is the exact existing constant external_annotation_not_target_experiment.
   B consumes these fields verbatim for source-name/EC term publication and must not reopen proteinDescription or derive name/EC meaning independently. No newly selected alternativeNames are silently added to the legacy publication. All alternativeNames and other native description/EC/evidence data remain intact in source bytes and are available to the separate existing read_uniprot_metadata consumer or later explicit projection. This preserves current legacy behavior while making its limitation explicit.

4. Alias child ownership is exact: add literal query_uniprot to UniProtService.capabilities and filter it in launch_catalog for operation=query_uniprot. APIServiceExecution.operation_contracts collects those actual service capabilities. ExecutionEpisodes.resource_tool_contracts declares resources=api and invocation_route={kind:commission,routes:[{entry_role:launch,resource_id:<actual bound UniProt resource>,resource_role:launch_api}]}. resource_tool_information.bound_resource_tool_contracts/tool_information_contracts validates the owner and route; tool_information.workflow_execution_catalogs supplies declaration discovery, and scientific_tool_retrieval consumes the actual tool map. Empty action arguments are bound to the immutable original typed service request. No new direct root query_uniprot entry is added to ToolRegistry.catalog. Existing public.uniprot.* routes retain compatibility where already available. No hidden LLM or endpoint generator.

5. Owner split: P owns new uniprot_native.py (including internal schemas/validator) and only the parse_uniprot/uniprot_pagination wrappers in acquisition.py. B owns api_uniprot.py and relevant tools.py publication/partial paths. To avoid concurrent edits, keep schemas in uniprot_native.py in this increment rather than optionally creating another owner. B consumes P's native shape plus legacy_publication. The two can proceed concurrently against 002. No source edits have been made by this boundary task. R later owns uniprot_returns.py and receipt/report consumers only after its selected projection contract is reviewed.
