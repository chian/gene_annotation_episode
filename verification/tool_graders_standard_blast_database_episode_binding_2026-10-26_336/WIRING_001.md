# Standard native database E implementation trace

This workload owns four new E modules, their four tests, thirteen narrowly
additive shared consumers, and one knowledge entry with its exact registration.
It does not modify native6 E modules, N331, M332, R333, scoring sheets/formulas,
axis definitions, prompts, controller/scheduler behavior or accounting.

## Selection, original execution and custody

`ExecutionEpisodes.resource_tool_contracts` consumes N's real
`standard_blast_database_tool_contracts`. Five `native.<program>.database`
names remain distinct from paired `native.<program>` names and native6 names.
Assignments retain the exact original `native_blast_standard_database` logical
job. The practical records schema requires an explicit HPC resource; the local
executor rejects this key. The launch child retains its original caller
constraints, queue/account/allocation and selected action.

`PBSPracticalOperations` validates the explicit selected software/database and
producer binding. Its existing remote worker writes the standard plan once
inside that original attempt, and writes its exact path and SHA256 to both
submission.json and job-request.json. It invokes N's real selected-plan driver.
The authentication branch reads that original attempt's ledger/request directly,
checks run, episode, original action, attempt, submission token and PBS identity,
and exposes `{identity, attempt_directory, plan_sha256}` independently of bundle
claims. `ExecutionTargetReader` checks the witness against the original receipt.
No results operation follows current.json or starts another search.

The new acquisition module authenticates this witness before interpreting the
plan/bundle. It captures complete declared files in at most 1 MiB windows, keeps
all artifact slots even for shared bytes, and seals the exact original bytes.
The same selected interrupted action may resume only a byte-verified prefix.
Closed replay uses retained custody without another remote call. Failures keep
specific codes, complete siblings and diagnostic artifacts.

## Numerical worker and frozen publication

The new publication module validates the original results commission and actual
received handoff, selected metadata/source artifacts and complete scoped query
subjects. Store presence grants no input authority. It consumes R's actual
closed request/manifest schemas, identity helpers and fresh imported source
inventory. One caller-policy local_jobs worker runs with 20 GiB RAM, 4 GiB
scratch and no wall cap. M receives artifact_ref-keyed supplied contents and a
separate sequence_artifact_ref map for complete subject symbols.

The generation preserves exact inputs, collection, sheets, calculations, full
rows, byte index, metric definitions and diagnostics. Projection, saved
validation, return and forwarding invoke no native parser or calculator.
Source and original request identities remain separate from calculation and
projection identities. Worker source inventories name actual current files;
historical generations retain their original hashes.

For an HSP observation, publication resolves R's qualified pointer into the
saved direct303 result using original row keys and explicit hit/HSP component
indices. The corresponding saved sheet query binding, full subject symbols,
length, molecule, digest, selected interval and assigned scope must agree.
Original nt/aa paired intervals supply the query-only observation geometry.
Reported-axis cells remain unchanged. No database hit is fabricated as a
biological reference. Other families remain source facts; a missing biological
query binding leaves native numerical rows source_only.

Per-search null303 and per-artifact null PSSM calculations remain unavailable
with the original closed failure and diagnostics. They do not become zeros,
alternate-parameter retries or successful practical completion. Optional
query_unbound qualifications are preserved without gating a faithful numerical
acquisition on scientific subject availability.

## Actual return, credit and continuation

`StandardBLASTDatabaseResults` retains the original selected action, request,
capture, preparation and publication in durable result receipts. It supplies
only the assigned frozen rows and typed failures. `StandardBLASTDatabaseReturns`
authenticates original immediate-child commissions, original schemas, frozen
forms and actual received records. A complete stored row/index grants no
unrequested cells. Repeated received forms for the same calculation and row
union only their actual measurement/boolean cells in first-seen order, after
exact noncell-context equality. Conflicts are explicit; prior forms stay intact.

Authenticated failed standard HPC attempts are returnable to request partial
results. `usable_handoff` is unchanged. The launch completion/credit path still
requires a usable original handoff, so failed-only delivery adds no handoff
credit. Collection retains native execution failure even when numerical rows
are available. Duplicate acquisition/projection/return retains the same
underlying contribution and adds no observation or duplicate credit.

Validated successful acquisition plus faithful requested projection and original
native execution success supplies the existing practical completion proof.
The existing practical estimator sets future expected credit to exact zero
immediately while preserving the completed action's final gain and prior
observations. No extra turn or controller comparison is introduced.
