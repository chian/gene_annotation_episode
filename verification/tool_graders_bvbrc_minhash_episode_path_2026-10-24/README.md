The owned test is `tests/test_bvbrc_minhash_episode_path.py`; its fresh fixture is
`tests/bvbrc_minhash_episode_fixture.py`. Contracts 001–005 define the boundary.
Existing BV-BRC fixtures, retained A101/P01 entries, source records, annotation
scoring, goal text and fixed accounting were not edited by this workload.

Verification uses scripted choices in the existing in-process Workflow and
shared method_loop. The real configured resource service, urllib request and
response-capture code, scientific three-slot construction, source publication,
numerical sheet/calculators, typed forms, receiver qualification and practical
completion estimator are exercised. Only the provider choices and urllib I/O
response are fixtures. The HTTP body is explicitly synthetic; no socket or
BV-BRC connection is permitted. This is not a live-service or model-science run,
and does not verify independent subprocess execution.

The selected path is annotation → scientific_process → launch → launch_api,
then scientific_process → results. Genome and Workspace-FASTA modes each select
their actual operation plus `api.bvbrc.minhash.result` through full four-field
tool information. The production library fills the supplied selectors with
name, description, resources and instructions. The A101 and P01 bytes are
compared with their unchanged publication.

the harness stops at the real following decision without declaring completion.
