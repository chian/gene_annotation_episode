# E321 implementation and ownership trace

This packet binds six database modes to the existing resource-specific child and
results/return path. It does not run a native scientific executable or claim
live HPC verification. The controlled PBS transport and synthetic emitters are
explicit test fixtures; N, M, R, Store, runtime records and return validators are
the actual production implementations. Current test results are recorded in
separate immutable check directories; this wiring note is not a passing receipt.

## Selected execution and original custody

`ExecutionEpisodes` instantiates the database results/returns adapters only for
an explicitly configured native database resource. Its request schema and
resource tool contracts use N's declared database input contracts. Assignment
validation, parent-input checks, selection, target resolution, operation catalog,
execution and initial references preserve the original requested job, selected
scope, constraints and caller allocation. Database results cannot fall through
to generic current-filesystem windows.

`practical_execution_records.py` accepts the separate N requested-job contract;
`practical_execution_operations.py` rejects routing that HPC job through the
local executor.
`practical_pbs_operations.py` validates the explicit producer/software/database
bindings, constructs the original attempt plan, invokes the real N driver in
the selected PBS script, and pins its plan identity in the original submission
ledger and receipt. The attempt, operation, submission token and PBS ID remain
original. Capture reads are bounded to 1 MiB and reject symlink/path substitution.
No resource choice, retry, cancellation, polling loop or new episode is added.

`ExecutionTargetReader` reads the original practical receipt and exact N plan
identity. Its database authentication hook supplies the actual original ledger
witness before N's pure bundle validator runs. `read_file`
uses that same original attempt rather than a mutable latest-attempt pointer.
The accepted additive 010 `returnable_handoff` exposes a failed original database
attempt for partial-output acquisition. `usable_handoff` remains unchanged for
endpoint proofs and operational handoff credit; facts and credit explicitly keep
those predicates separate.

`capture_native_blast_database_bundle` retains intent, original witness, complete
plan/bundle bytes, every captured artifact in original order, complete hashes and
lengths, and a sealed capture receipt. Valid siblings survive missing/changed
files. A resumed interrupted capture compares already retained bytes against the
same authenticated original selection before appending missing bytes; it neither
overwrites a mismatched prefix nor launches new work. The private finalization
record permits sealing an already completed transfer without another remote
read. Only actual missing plan/bundle files are labelled plan_missing or
bundle_missing; other I/O and mutation failure meanings remain specific.

## Numerical preparation, publication and frozen validation

`prepare_native_blast_database_grading` checks original commission/handoff and
actual received input scope, then builds the accepted M/R catalogs. Every
original metadata descriptor tuple and its order survives. Equal input keys may
serve distinct consumer/schema tuples only with identical original bytes. A
Store artifact without receipt authority cannot become selected metadata.
Subject snapshots are complete normalized ASCII sequence bytes and are retained
in the artifact catalog.

The fresh import-only `_implementation` inventory hashes actual scientific
modules and loaded dependencies; only PSI/DELTA add the native convergence
bridge and extractor. The R public implementation/input/calculation identity
helpers build the canonical identities. The worker executes once inside the
existing local_jobs 20 GiB RAM / 4 GiB scratch / no wall-cap boundary. E passes
the original job's grading_parameters; there is no E model-override selector.
Changed-model saved-sheet recalculation is a separately tested R interface.

Invalid requests/models preserve their exact attempted request and exception
diagnostics, with calculation_failed/calculator_contract_invalid, before a
valid generation exists. No valid manifest/model is fabricated. Worker failure
and interruption retain diagnostics, logs and any already sealed siblings.

The manifest validator recognizes exact v1 and v2 role/schema/path sets and
verifies full retained bytes, counts and row index. V1 remains readable without
adding convergence. V2 registers native_convergence only when an actual listed,
sealed extraction artifact exists. The saved binding, complete collection,
original source context, canonical extraction bytes and content identity must
agree. Each native convergence row points to its actual extraction record and
matching saved calculation/sheet/marker occurrence; equal marker bytes remain
distinct occurrences. Frozen validation invokes no extractor, parser, binder,
populator or calculator and performs no remote read.

Publication preserves complete artifacts and exposes only requested cells.
HSP observations require exact complete query/subject identity, molecule,
orientation, interval and saved traceback qualification. MSA masters use the
saved complete column relation; PSSM masters use the actual complete retained
306 master relation. Non-HSP or unqualified biological rows remain useful
source-only rows. The original bundle source and observation identities do not
depend on projection or selected calculation model. Empty equal-byte stdout
and stderr produce ordered unique content references while their original
artifact keys, roles and order remain in the bundle/capture.

## Return authority, consumers, credit and continuation

`NativeBLASTDatabaseResults` owns the selected status/collect action, durable
receipt, exact facts, resolver, existing operational contribution identity and
practical endpoint proof. Complete requires authenticated acquisition, faithful
requested projection and independently observed successful exact native work.
Nonzero native output can retain useful rows while native success and complete
remain false. One completed collect is one own action; internal parsing and
rows do not add actions or controller observations. Successful practical
completion uses the existing immediate exact-zero future expectation.

`NativeBLASTDatabaseReturns` authenticates actual immediate-child commission,
contract, original return attempt, saved form and frozen facts using existing
EpisodeReturnRecords and receipt tables. No separate authority journal exists.
The accepted 009 union groups only actually received numerical rows by exact
(calculation_id, record_key). Common fields and repeated cells must agree with
strict JSON equality; only new actually received cells append. Contradictions
raise received_row_context_conflict or received_cell_conflict. A frozen ancestor
may retain its historical subset only with original unchanged form authority.
No full-row lookup adds unreceived cells, and other fact arrays keep their
existing meanings. Duplicate projection or delivery adds no observation/credit.

The host-only observation marker is declared in domain/state and validated by
`validate_native_blast_database_observation` against original action,
preparation, publication, exact retained data and the received record itself.
The approved numerical consumers are evidence_geometry extent validation,
evidence_axis_contracts.native_metric_facts, blast_result_views and
alignment_site_native. Their existing formulas are unchanged. Native metrics
are copied only after qualification. The separate pure receiver presentation
omits automatic native database observations while retaining explicit typed
child returns; it does not resolve or qualify records. Paired/reference
consumers validate authority then return biological_reference_unavailable;
query-only database evidence cannot fabricate a biological reference.

No prompt, investigation task, evidence-axis sheet, annotation rubric, W05,
literature workflow, global accounting or local continuation policy is changed
by this packet. Historical failed receipts remain facts and are retained.
