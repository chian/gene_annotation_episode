## Construction and receiving-decision trace — outside the prompt

This revision preserves the original HMMER-specific 011 draft. It corrects the
episode definition rather than renaming HMMER operations. The opening names the
actual assigned service job. TASK explains how to make the execution decisions
for that job and expands the complete relevant selected service instructions.
It is included on every exchange. STEERING is built independently from relevant
recorded facts and own yields; empty optional tables and irrelevant rows are
omitted. Braces specify text construction, not literal JSON or instructions to
the model to invent missing content.

| Fill | Actual source and selection | Decision it enables |
| --- | --- | --- |
| Job, inputs, service, constraints and requested use | Original parent goal and concrete validated API assignment; parent return purpose. Preserve exact request omissions and settings. | Choose an operation for the job actually commissioned, without substituting another analysis or service. |
| Full service guidance and action meanings | Actual service operation catalog plus relevant selected launch-instruction sections. Render substantive instructions, native input requirements and outcome/recovery meanings. | Distinguish immediate retrieval from asynchronous work and choose a useful request, supported repair or available wait. Documentation cannot create a callable. |
| Initial and current service facts | Only explicitly supplied or actually received preparation/access facts, native responses, original-job observations and actionable failures. | Determine what is already established, stale, missing, failed or uncertain. Configuration alone is not a live-access observation. |
| Exact attempts and yields | This episode's original selected operations/outcomes and existing own category estimates. | Avoid unchanged repetition and compare useful categories while preserving raw observations and uncertainty. No parent yield/history or private descendant work enters. |
| Completion and return | Actual validated original handoff, original parent form meanings, current declared interpretation values and existing completion-proof/controller path. | Preserve the difference between usable execution information, acquired results and scientific annotation; preserve the final actual gain at the practical endpoint. |

The existing inputs remain structured internally; the proposal presents selected
text and tables. Typed JSON output and parent-return forms are unchanged. Host
IDs, hashes, versions, receipt/session tracking, secret values and raw stored
contexts remain outside model-facing text. Native scientific accessions, exact
query terms, units and meaningful locations remain when needed for the work.
