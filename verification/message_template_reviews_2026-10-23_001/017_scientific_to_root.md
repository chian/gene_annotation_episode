## DECISION trace: this receiver only

The annotation root decides whether scoped findings change its current interpretation of the fixed ybhP/b0790 target, qualify a claim, retain competing explanations, or motivate another investigation. It needs the job it actually commissioned and the returned scientific distinctions relevant to that decision. It must distinguish an observation on a reference protein from a target measurement, a predicted label from an assay, and family/domain support from activity, role and localization when those distinctions were requested. The template does not ask the child to choose the root's next action or rewrite the root annotation.

The root can also steer approaches when it expressly requested existing process results. An ordinary child with different tools is not automatically a `process.revise` alternative. Explicit original revision origin establishes that relationship; the root may then consider original local results without pooling scores, inventing a trend, or treating controller closure as scientific completion. The return supplies no private child decisions or chronological work history.

## Existing mechanics to reuse

The inspected path is scientific `DecisionSource.finish` → `Workflow.facts` → `ScientificProcessEpisodes.facts` → frozen `runtime_forms` → original-contract admission → `Workflow.receive_form` → received-information projection → the root's next decision context.

- `finish` freezes `form_with_facts(self.report_values, original_schema, facts)` and releases the closed source. `form_with_facts` fills recorded fields directly; the model fills exactly the nonsourced interpretation fields. No reporting model is needed.
- `Workflow.facts` copies committed/changed references and the actual closing yield. Its scientific snapshot uses the original initial credit, same closing credit and actual controller binding. `build_process_result` verifies original assignment, parent relationship, completion count and yield count; `merge_process_results` preserves own-first received rows and rejects conflicting bodies.
- `TypedReportContract.admit` and `validate_form` enforce the closed shape, constrained strings and resolvable references. `ScientificProcessEpisodes.validate_report` resolves pinned process selections. `ScientificProcessProvenance._received_results` reads only successful admitted fields explicitly bound to `scientific_process_results`; it does not read private descendant histories.
- `admit_return` compares sourced fields with the original frozen child facts, admits the original contract and records the attempt. `receive_form` records the received references; admission then projects the parent's cumulative received information. This completes one original commissioned action, not the child's internal turns. Replay reuses the original admission; a closed parent is not repriced.
- `DecisionSource.next` passes admitted `view.child_reports` into `model_inputs`; `method_loop._model_inputs` accepts only reports actually admitted for that parent. The root's received immutable record view and separately bound annotation context supply its existing integration context.

## Gaps this draft makes visible

1. There is no scientific-to-annotation text renderer. `providers._SessionConnection.complete` currently serializes the context with `json.dumps(context)`; `model_inputs` appends bare report values. The original purpose and field meanings are not rendered alongside each result for this receiver. Implementing a deterministic boundary renderer is future work, outside this review.
2. Existing validation establishes shape, namespace, scope and source-fact authenticity; it is not an explicit field-level content-disclosure declaration. `_references_in` identifies references, and `EpisodeReceipts.receive` recursively follows existing forward references. `Store.reasoning_view` can subsequently expose their model record representations. A future renderer needs the exact allowed field paths for each requested reference role. It must not equate this recursive receipt closure with permission to display all linked records, source anchors, raw source bytes or unseen replacement revisions. If the original form does not declare needed content, the draft exposes that absence rather than silently enriching the return.
3. The scientific finding table requires permitted source propositions, target issue, conditions, applicability and qualification together. A return requesting only generic changed-record references may lack these meanings. Such a form cannot acquire a scientific summary through formatting alone; the original requested information must support every displayed cell. There is no universal scalar or scientific summary hidden in `scientific_process_results`.
4. `scientific_process_results` already carries initial/closing credit, count and final local yield. It carries no action-category trend, process-success probability, new biological evidence or per-candidate annotation-support decomposition. Keep those unavailable. A readable binding meaning must come from actual bound metadata or an already declared parent-known meaning, not from a digest or score label.
