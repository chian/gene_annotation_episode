# C4 AppService execution planning handoff

The proposed production workload is in
[the execution proposal](../../docs/TOOL_GRADER_BVBRC_APPSERVICE_EXECUTION_PROPOSAL_2026-10-24_001.md).

- `CONTRACT_SCHEMA.json`: 72 proposed named contracts, including all eleven selected operations; not a runtime-loaded schema file.
- `SCHEMA_EXAMPLES.json`: five positive and five negative synthetic shape cases; not native output or scientific measurements.
- `INSPECTION.json`: precise read extents and source hashes; inspected source is not deployed-service proof.
- `VALIDATION.json`: Draft 2020-12 schema/reference/operation-closure and example checks only.
- `AUTHORITY_RESET.json`: final original objective and full sixteen-principle reread receipt.

C4a consumes `contract_schema(name)` and `validate_contract(name, value)` signatures,
with detached schemas containing only reachable definitions. C4b owns the service
and tool-information modules. C4c alone owns passive effect identity, exact custody,
shared API/monitor/publication integration. C4d verifies the actual complete path.
Scientific adapters consume the artifact bundle independently; none is implemented here.

No production code, live request, credentials, accounting/goal/template change,
or user-specific NCBI job work occurred in this workload.
