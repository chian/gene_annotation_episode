# Root receiver-template review, additive413/003

The metadata/consumer trace and explicit unresolved operand-selection seam are
useful. No proposed template is accepted or coded by this review. The parent's
own TASK stays separate and unchanged; root's earlier results-episode TASK is a
different message boundary.

Before showing the receiver template as a finished proposal, reduce routine
bookkeeping in the displayed examples. Full D1 values remain in internal records.
The normal requested measurement row needs its value, unit and scientific
population. It does not also need an always-present row-count/state/origin table
when those fields add no distinction. Show missing/partial/omitted results and
selected-window limits when they change what the parent can conclude.

Preserve model/chain/residue/insertion-code distinctions where they identify the
requested comparison or site. Do not repeat a full fixed/moving description or
all invariant qualifications merely because those fields exist. Likewise,
sequence letters, residue maps, coordinates and transforms are shown only when
requested. Artifact availability describes later-use information, not knowledge
of unread contents. Original and later parameter results need distinct labels
and the parameters that explain their different populations.

Readable display may explicitly mark a short approximation while retaining the
exact numerical value in the typed record. This is a formatting proposal for
feedback, not a changed score or a rule for interpreting rounded thresholds.
No formatter may compute changed/unchanged or stability from an RMSD display.

The current direct-action schemas still require exact sequence references and
saved descriptors. A readable table does not solve that action-selection seam;
it remains open. No alias transport is introduced by this review. The accumulated
history-selection issue also remains explicit, rather than claiming that every
received row is relevant on every subsequent iteration.
