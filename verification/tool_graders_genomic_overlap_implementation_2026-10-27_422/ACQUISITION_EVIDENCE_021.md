# Actual acquired overlap population

Additive 2026-10-27 correction to 016. Creating a valid numerical sheet whose
only content records missing native output does not acquire a native result
population. A parsed copy of an already supplied interval set does not do so
either. This changes no scientific formula or operational credit unit.

Workload 436 adds one closed private `acquisition_evidence` record to its
results receipt. Native collect supplies either null or:

- `version = genomic_overlap_acquisition_evidence_v1`;
- `sheet_file`: the actual qualified NativeFileIdentity;
- `comparison_receipts`: the exact G1 NativePairReceipt entries from that
  qualified sheet, in original comparison order.

Read the qualified sheet once during the selected original publication. Freeze
these facts there. Historical verification checks original controls and Store
metadata, without reopening scientific bytes. Join the sheet identity to the
qualified output and the comparison identities to the original run, resource,
execution, attempt, selected action and originating episode. Preserve actual
source-action and closure references.

One original population has been acquired if at least one comparison records:

1. Actual captured `bedtools_intersect` output, with a closed writer and stdout
   equal to that comparison's captured `overlap_stdout`. A genuine zero-byte
   result and a partial native result remain acquisition. Preserve the exact
   capture qualification; an unsealed current file cannot acquire stronger
   original-output provenance merely from its path.
2. The original validated analytic-empty comparison: derivation
   `validated_empty_input`, outcome `not_executed`, closed writer, complete
   capture/native extent, completeness basis `validated_empty_input`, no
   stdout, verified original driver start and actual captured batch or pair
   manifest provenance.

Do not infer acquisition from a parsed input, a batch record alone, a favorable
scientific value or a non-null manufactured sheet. Never-started and
all-invalid-input cases have no qualifying comparison. Saved calculations and
status actions have null acquisition evidence and add no original population.
Retain once-per-population identity, inherited baseline subtraction and the
existing caller-owned operational units. Annotation and monitoring credit are
unchanged. This is not a completion or scientific acceptance gate.

Verify never-started, all-invalid, actual valid-zero and partial native cases,
and unchanged replay/baseline semantics. Earlier checks remain recorded at
