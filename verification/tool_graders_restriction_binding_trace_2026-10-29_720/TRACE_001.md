## Finding and route decision

The smallest suitable implementation is a **bounded ordinary sequence tool in
the existing scientific_process child**, using ToolRegistry's native worker and
local_jobs boundary, plus a restriction-specific retained-input/result/return
adapter. A one-off RestrictionBatch search is a primitive operation. It does not
need a new complete episode or a copied FBA/NMF execution family. This is a
recommendation for an explicitly local primitive contract, not permission for
infrastructure to replace a commissioned job with an ordinary call.

That distinction is real in current code. resource_tool_information.py builds
ordinary ToolRegistry rows with invocation_route.kind=direct. Actual configured
ExecutionEpisodes.resource_tool_contracts() builds commission routes to launch
and launch_local/launch_api/launch_hpc, or to results. ScientificProcessEpisodes
resolves the parent's selected child_tool_info and exposes only its direct
subset as callable ordinary tools. A commissioned operation cannot be enabled
there by adding an information entry. The binding must choose and advertise one
real route; the receiver validates that route against its actual capabilities.

The direct primitive recommendation follows EPISODE_STRUCTURE's distinction
between iterative episodes and tool calls, TOOL_KNOWLEDGE's nonmandatory category
levels, and TIME_AWARE_ESTIMATION's implemented ordinary native alignment/XLSX
lane. It does **not** cite the older flat homology launch as ownership proof.
The latest launch direction still applies whenever the scientific parent
commissions an execution job or leaves an execution approach open: launch owns
the choice and its selected resource child owns execution. In that case use an
explicit launch_local binding, retaining the same finite restriction worker and
pure reader; do not silently invoke it directly from a scientific child or root.
There is no API/HPC restriction deployment demonstrated by this trace.

Root must settle the actual invocation contract at the separate information/
template feedback boundary. This report supplies neither prompt text nor a
placeholder catalog entry. No new runtime approval gate is proposed.

## Why generic commissioned results are not a complete scientific host

ExecutionEpisodes._request_schema and prepare_assignment preserve explicit
requests, immutable versions, parent launch ownership and selected resource
identity. Resource children currently delegate to PracticalResourceEpisodes;
its execute validates the selected primitive, freezes one intent, runs it once,
assesses actual output predicates and publishes the original receipt. The
resource catalog is practical preparation/start/status/collect operations.
No restriction family or restriction requested-job schema is installed.

ExecutionEpisodes._execute_native_results is an authenticated bounded status/
collect/window reader. Its selected paths, offsets and limits are validated
against the original target and immutable receipt. It is not a full NativeResult
file parser/capturer and cannot treat a log window as the complete623-enzyme
native mapping. A generic argv submission plus this collector is therefore
insufficient for the required molecular return.

NativeFluxBalanceResults demonstrates additional real family work: require the
original writer to be terminal and quiescent; retain original start/closure
proofs; capture declared native files; run a finite reader worker; validate
qualified outputs; publish requested facts; authenticate saved-sheet origins;
deduplicate acquired populations; retain exact completion proof. Its worker,
receipt, input witness and projection contracts are FBA-specific. Copying that
host or changing family names would duplicate authority/state boilerplate and
does not automatically authenticate sequence inputs.

For an explicitly commissioned future restriction job, the missing seams are
new local deployment/request/input binding, a selected native start plan and
result target/selector, full closed-file capture, restriction fact/return
projection and their original receipt authority. Reuse PracticalResourceEpisodes,
native_lifecycle, native_file_capture and EpisodeReturnRecords. No new episode
class, scheduler, monitoring cadence or private agent loop is justified. This
larger route is conditional on a commissioned job contract; it is not needed
solely because the small primitive happens to spawn a protected subprocess.

## Selected operand and immutable mapping seam

SequenceBinding's namespace is a semantic reference namespace, not an authority
label. WorkflowServices.reference_in_scope accepts subject for input, feature,
product and read_subject; a real reference record uses reference. Keep the718
subject|reference enum. Do not narrow selected_sequence to original inputs, add
a derivative enum merely for record types, or turn an external derivative into
a new annotation target.

ToolRegistry._check_sequence_operand accepts input, feature, product, reference
and read_subject. Its target-scope check applies when Store.roots is nonempty;
source-grounded external operands without roots remain legitimate evidence.
ToolRegistry._sequence resolves stored sequence bytes, packed selected reads,
and feature segment traversal with strand handling. A whole read library is not
a sequence operand. The binder must preserve these existing distinctions.

Store.sequence_mapping is the exact physical traversal, separate from coverage/
credit footprints: original/reference/read subjects have identity traversal;
features compose ordered segments and strand with the parent's map; products
need their existing explicit mapping. Unmapped legacy products can still have
sequence bytes, but their unavailable subregion map must remain unavailable.
Store.has_exact_mapping exposes that distinction. An empty input footprint is
not permission to fabricate an original-target coordinate map.

Proposed binding procedure, before dispatch and without choosing more work:

1. Authenticate the actual selected reference against the child's supplied/
   received information, namespace, original assignment and scope. Use existing
   sequence-operand and target-root rules, not a new input-only whitelist.
2. Freeze the immutable selected operand and relevant ancestry/source records,
   actual source/revision, source artifacts, and read library/member identity
   where applicable. Use immutable_record's existing identity conventions as
   the source pattern; a supplied SequenceBinding is never its own authority.
3. Read the exact selected sequence using the existing resolver, then retain its
   UTF-8 bytes, hash and length. Preserve original case separately from native
   uppercase normalization. Do not use a whole FASTA/file digest as sequence
   content_sha256. DNA interpretation, topology and enzyme population stay
   explicit selected operands, with validation in the common718 contract.
4. Retain the exact Store.sequence_mapping result in the original bound input
   receipt when available. Existing inline mapping need not have a separate
   origin_mapping_ref; preserve null without inventing a reference. If an
   actual separately identified mapping is selected, authenticate that join.
   Preserve unavailable mapping and its reason distinctly from available inline
   mapping. Keep ancestry, source version and scope beside the718 narrow binding;
   do not overload source_ref or sequence_version with an execution ID or
   timestamp. sequence_ref identifies the selected operand record, not its
   sequence-blob artifact property. Coordinates stay on that selected operand.
5. Revalidate these frozen witnesses against the selected request and worker
   output at publication; saved reading uses these same received witnesses,
   not the latest source alias or a similarly sized sequence.

Current execution_input_versions is useful for generic revision/artifact digest
checks and explicit selected family witnesses. Its generic branch follows a
record's sequence_ref/artifact_ref. It does not hydrate feature traversal or
packed read_subject bytes, nor freeze their exact mapping/ancestry. The FBA
witness extension proves that authenticated per-family selected-input witnesses
can be threaded through the existing launch/start boundary; it is not a ready
sequence binder. Reuse the namespace/resolver/mapping/identity interfaces and
add a small sequence binding adapter. No namespace enum expansion is needed.

## Custody, return, credit and continuation joins

The host must join: original run/episode/decision operation key → selected tool
name/arguments/scope → frozen selected sequence/source/version/mapping → actual
native worker result and software/dictionary source pins → complete NativeResult
artifact → MappingResult.native_sha256 and selected_sequence → exact saved
tool result → requested child fact projection → original parent contract and
successful admission. Catalog names/ordinals/mapping order are validated by718/
719; independently sorted arrays, equal lengths and equal cut numbers are not
authority. A hash proves bytes, not permission or a genuine native execution.

One selected native operation yields one local completed-own-action observation.
Capturing files,719 reading, typed projection and report construction add none.
If a later selected saved read is an action, it remains a read of inherited
science: no fresh native measurement or repeated scientific contribution.
Repeated delivery uses frozen original observations and received-information
projection. Parent commission admission is one parent action, not every child's
internal operation. Supporting cut positions/counts are conditional predictions,
not annotation-confidence components. Do not add their magnitudes to scientific
confidence, monitoring credit or annotation support. No new scalar or W05
aggregation is proposed; root must verify the existing progress binding through
the completed path rather than awarding progress for record creation alone.

The configured method_loop controller retains continuation. No acceptance gate,
fixed retry/poll count, timer or stopping override is added. The bounded ordinary
tool path does not need a practical endpoint. If root selects a practical job
route, authoritative completion must set future expected credit to exact zero
through the existing practical controller binding, preserving the final actual
gain and original observations. Parsing/reporting must not add a zero turn.
