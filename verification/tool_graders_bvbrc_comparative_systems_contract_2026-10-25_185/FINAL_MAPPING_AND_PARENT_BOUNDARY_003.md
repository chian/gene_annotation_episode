# Final additive mapping and parent-form boundary

This closes the last explicit producer mapping and distinguishes the provider's internal schema from the existing parent communication schema. The proposal is ready for root's freeze/review; it does not authorize production coding by itself.

`DocumentSelectionV1.documents[]` now has a required nullable `producer_evidence_id`. P copies exactly that selected ID into SourceDocumentV1. Non-null resolves exactly once to the matching QualifiedProducerEvidenceV1 for this document/task; it must also match the requested producer evidence selection and actual qualified source binding. Wrong task, conflicting records or incompatible evidence basis fails this binding. There is no search for the first evidence record or presumed shared commit across documents. Null leaves this document's producing provenance unknown even if unrelated selected source records exist. N receives the explicit mapped evidence through the signatures in `HANDOFF_CLOSURE_002.md`.

`RequestedSelectionV1` and `ProviderFactsV1` are **internal provider contracts**. Their JSON Schema `$ref`, nullable anyOf, conditionals and free-form native identifiers are not passed directly to `communication.validate_closed_schema`. P's provider-requested schema can use the provider's `x-bvbrc-comparative-systems` selection marker. The **parent** form uses only the existing communication keyword set and a registered top-level `x-source`. I owns this deterministic rendering and registration; it makes no scientific calculation.

The parent renderer specializes each top-level fact-source field to a single selected kind. `measurement` and `computed_measurement` use NumericCellV1 values; ratio uses RatioComponentV1; population uses PopulationFactV1; membership uses MembershipFactV1; requirement/qualification use their respective closed records; status uses the closed request-status record. Each list cardinality is the original requested cardinality. A shared source family may have multiple parent fields when their value kinds differ. No arbitrary union or unconstrained JSON object crosses the parent boundary.

For a selected kind, the renderer expands references, uses an explicit single type (or that type plus null), required closed object properties and typed arrays. Scalar-plus-null anyOf becomes the corresponding type list. The stored value is copied unchanged. State/value, population, unit, original-source and selector relationships remain checked by the original provider/saved projection and I's return validator; the renderer does not recalculate them. Structural patterns/conditionals unsupported by communication do not become prose or newly accepted data.

All strings are enums/codes or declared semantic identifiers. The original outer source_ref uses the existing execution_result namespace. Stable internal identifiers/pointers use these new finite namespaces, owned by I's `resolve_own`/`resolve_received` bindings:

* `bvbrc_comparative_systems_analysis`: exact saved analysis identity;
* `bvbrc_comparative_systems_population`: exact saved population/reference-membership identity appropriate to the selected field;
* `bvbrc_comparative_systems_owner`: exact saved native document, supplied record set, analysis or component owner named by a retained CellReference;
* `bvbrc_comparative_systems_pointer`: a valid retained pointer under its original CellReference owner/kind;
* `bvbrc_comparative_systems_identifier`: remaining exact entity/document/field identifiers from the selected saved row.

Identifier existence alone never establishes the relationship. For example, a pointer string may occur in several analyses; `validate_received_report` must compare the complete returned fact with the original admitted source's saved projection, including owner/kind/source/task and frozen schema. These namespaces do not permit searching other runs or creating identifiers from arbitrary parent strings. Missing/invalid original references remain typed failure, not unrestricted text. Native descriptive strings needed only for internal context remain in stored data; selected native identity labels must be exact saved identifiers with semantic validation.

The supplied `PARENT_RATIO_FORM_EXAMPLE_001.json` specializes one ratio field and validates with the existing `communication.validate_closed_schema`. `PARENT_RATIO_FACT_EXAMPLE_001.json` is a labelled synthetic value matching that form. This verifies the renderable structural contract only; no actual child admission/episode communication was performed. The full parent path, source-family registration, reference resolution, preserved latest/closed returns and tamper rejection remain I's finite implementation/verification workload. They do not block N's native/sheet or C's calculators once root accepts their shared handoff.
