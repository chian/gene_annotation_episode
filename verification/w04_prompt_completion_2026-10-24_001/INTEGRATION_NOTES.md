## Checks implemented

The publication check freezes all ten A entries and nineteen P entries. It
compares all retained source rows with the documented original entry files,
checks their provenance hashes, verifies unchanged P bytes and all published
entry bytes, and counts 344 provenance rows. After deleting only the temporary
source copy, it reopens every frozen entry and source page with unchanged
identities and bytes. It verifies that A lookups project investigation text and
publish no target records.

Each of A101–A108, A110 and A111 is commissioned through the actual Workflow
from a supplied 21-aa protein, with no initial candidate annotation or public
identity. The real registry supplies `sequence.inspect` and its frozen local
instructions. The first actual child decision frame retains the complete
selected investigation text, unchanged P01 guidance, parent scope, supplied
sequence/context, constraints, closed return form and allowed result meanings.
The capture occurs before a scientific action. No source, observation,
hypothesis, assessment or annotation is created by construction; no numerical
observation is added. A trap rejects any scoring-route metadata dispatch on
this path.

One bounded scripted Workflow completes this path:

1. The parent requests the actual A101 composition entry inside its pending
   decision, then selects the scientific child.
2. The child runs actual local `sequence.inspect` on the supplied protein.
3. Its next decision receives the measured outcome, requests the A101 entry
   through a same-decision lookup, then reads the actual retained measurement
   source through `source.read`.
4. The child closes with the original constrained status/reference form. The
   parent admits that form and receives the actual inspection source and
   sequence-composition observation through ordinary receipt handling.

The test uses the ordinary `YieldController` and its unchanged comparison with
an explicitly scripted expected-gain input and zero-credit projector. These
are fixture inputs, not production scoring/estimation choices. The child has
two completed own actions; its parent has one completed child action. Five
model exchanges occupy three decisions and produce exactly three controller
observations. Neither composition lookup creates an action or observation.
The actual two registry operations create one sequence-composition observation
and no annotation or assessment.

The bounded run's actual child bootstrap, update and lookup inputs are replayed
through the real provider presentation and `turn/start` input construction with
a controlled transport. Every input repeats the complete selected TASK and
retains the typed output schema. A fresh provider reconstructs the latest
actual state and its answered lookup using the existing bootstrap protocol.
This transport exercise creates no additional action or observation. It is
distinct from a live model call or a detached worker deployment.
