# Original RNA TASK and provider delivery

This packet implements the original RNA message integration specified in 384.
It does not change RNA scientific fields, calculators, native execution,
authority, credit, continuation or the parent's typed response form.

## Implemented boundaries

- `rna_structure_prompt.py` builds detailed recurring instructions from the
  already assigned original job and result selector. It distinguishes native
  MFE prediction, supplied-structure analysis, optional native energy evaluation,
  and saved-sheet recalculation. It names the selected rows, numerical meanings,
  relevant parameters, units, qualifications and existing status/collect choices.
- `ExecutionEpisodes.instructions` dispatches the two original RNA selector
  versions to that TASK using the already selected target's original job.
- `scientific_process_prompt.py` selects the original RNA facts through 387's
  supplied-value renderer. It handles results, receiving parents, own progress,
  own outcomes and explicit lookups without acquiring or recalculating data.
- The existing requested-return helper compacts original recorded-field schemas
  as well as comparison schemas. It preserves the parent's constrained
  interpretation fields and meanings. The corresponding copy in the assigned
  goal's result contract is handled too.
- `providers.py` recognizes original-results and original-recipient capability,
  including an initially empty facts list. Full TASK remains present across
  initial delivery, updates, same-decision lookups and restored frames. Host
  journals, frame hashes, response schemas and fixed instructions are unchanged.

The pure original presenter is owned by 387 and its separate handoff. The narrow
one-input structure-only opening is owned by 385; this packet composes the
requested-form change into that released shared prompt. Original artifacts,
source references, saved descriptors and selected numeric values remain typed
host data. Presentation does not create new scientific facts or observations.
