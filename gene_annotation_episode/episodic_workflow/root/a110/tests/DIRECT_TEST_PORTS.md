# Direct a110 Launch/Results engineering controls

Four real private owners are selected: annotation Launch/Results and scientific
Launch/Results. Each original owner and registry is constructed. A real retained
mathematical HPC plan supplies a validated practical assignment, but none of the
selected invocation paths has an HPC ancestor. No native process or remote job
runs. Required inputs remain in the project's tests and examples.

The own-axis annotation parent binding is absent. Its current registry fallback
and runtime route are tested explicitly; no axis head is manufactured. The real
scientific parent is registered, but its ancestor request metadata is controlled
and is not a scientific invocation/admission claim. The direct Launch assignment
passes real child admission and initialization; Results target/receipt operands
are controlled and do not authenticate an external handoff.

Selected task methods use object.__new__ with declared state. The separate
Workflow.build test uses the actual selected constructor and actual saved
EpisodeRequest, with only Episode identity and FeedbackEpisode wrapper ports.
Returned tool/reason/wait acquisition outcomes are controlled. The real selected
task executor, action key, Journal persistence, invalid/failure iterator decision,
original credit projection and saved action replay execute. Minimal reasoning
payloads are not claimed to pass scientific action admission. A110 Results has
no newly advertised wait/reason action; A107 API Results exercises its real wait
permission. Dynamic caller job membership remains allowed to overlap a private
binding, and the original job instruction callback must still be evaluated.

Task.instructions continues to call workflow.services.instructions unchanged.
Only the actual default WorkflowServices implementation selects the own task's
complete original instruction composer. Custom callable/exception identities,
inherited defaults and a foreign bound default service are checked. A temporary
Python profile observer records the real foreign service frame and self identity;
it changes neither the service callback nor its composer. Prior profile state is
restored. Provider transport is controlled, while original and private context
presentation functions run on the same inputs without transport.
The saved-provider check declares an existing session, matching the inherited
LaunchConnected fixture; it does not establish a live provider session. The
scientific parent receipt observer wraps the actual imported callback alias,
while retaining the complete original endpoint and its arguments.
The saved-provider fixture explicitly declares the empty `required` list that
the original action-schema normalization supplies; full call assertions remain.

Parent receipt authentication and receipt side effects are declared ports; actual
saved counterpart rows, own endpoint selection, complete receipt implementation,
progress operation identity and redelivery run. These do not replace retained
carrier custody, actual Store reopening or descriptor reconciliation.
The original caller supplies its already-known child role. No extra counterpart
lookup is used to select an endpoint: cached receipts prohibit such a read,
annotation receipts require none, and scientific progress retains its original
lookup count. Original generic dispatch runs once centrally; the private endpoint
contains the exact original post-dispatch body. A distinct private selector avoids
adding a new legacy child_report_receiver hook or entering the same receiver
recursively. Actual default bound receive methods accept the known-role keyword;
original-signature overrides receive the original call shape.
The actual Workflow.selected report callback also runs through typed admission,
a saved report attempt and the actual receive_form transaction; its semantic
validator is an explicit port. This checks the role handoff from the original
caller without running a child workflow or assigning scientific credit.
That callback test sets receipts and branch lifecycle to None and exercises the
legacy report branch. It does not validate the receipt-enabled admitted_report
or C4 return path. Its build and TimedChildUnit construction ports remain
controlled; real constructor coverage is a separate Workflow.build check.
Native API/local/HPC receipt cases use the actual registry selection and actual
private role selector, saved child/action/attempt metadata, original cached path
and redelivery. All counterpart queries are forbidden because the original
Launch parent receipt performs none. Native child request metadata is controlled;
these cases do not validate native admission or run a native action. Results
cases check that those native children are unavailable rather than invoking them.

Yield tests run the actual binding factory, PracticalYieldEstimator.as_record,
YieldController and original nested callback definitions. Completion evidence,
verification and selected received sets are controlled. Saved controller inputs,
signed correction positions and serialized estimates are compared against the
retained original baseline. This is controller replay, not full Store workflow
replay, autonomous research, scientific evidence or measured scientific credit.

`direct_saved_carriers.py` is a separate required helper derived from the retained
saved-carrier engineering port. It publishes actual runtime descriptors for the
four direct owners plus their native children and real scientific parent. It
uses real typed identities, Journal, archives, completion ledger, closed credit
and standard reconstruction checks. Initialization, completed outcome and closure
projection are declared metadata ports. Capture records annotation_parent_binding
as null, and no HPC ancestor is used. The original HPC helper/captures remain
untouched. Post-application probing reports actual descriptor/restore failures;
it does not substitute old hashes for current descriptors or create an alias.

A separate real Workflow.selected check covers the existing annotation fallback
and scientific parent transmission before child admission. It uses the actual
configured scientific child roles and actual Launch admission. Scientific
ancestor invocation validation and Results target admission are controlled ports;
the real outbound route and original assignment object/body reach those ports in
order. Child construction is observed there; the independent Workflow.build test
covers actual selected task construction. These scopes are intentionally separate.
