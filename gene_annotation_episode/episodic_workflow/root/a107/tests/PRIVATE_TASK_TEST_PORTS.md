# a107 private task refinement checks

The required test uses this axis's real Store, Journal, complete 31/27-owner HPC
fixture, actual private binding constructors and registry selection. Its fixture
source is the retained `tests/launch_connected.py`; queue inputs/resources remain
required project assets. Eight named test classes select four actual HPC parents
and their Launch/Results children. This excludes direct annotation/scientific
placements and native child task extraction.

Selected task methods are invoked on the actual type declared by the binding
(or the original DecisionSource in a baseline). Task state initialization is a
controlled engineering fixture: object.__new__ plus copied __dict__ bypasses
the constructor. A separate test invokes actual Workflow.build and the selected
constructor for both Launch and Results, with controlled Episode.identity and
FeedbackEpisode wrapping ports, then checks initialized state and persisted
request. This does not run the full FeedbackEpisode iterator. Original/default
instruction composition is compared with the original
runtime_prompt function. Actual WorkflowServices defaults, inherited defaults,
custom functions/methods, a callable that spoofs __func__, foreign bound methods
and exact custom exceptions are distinguished. No model call occurs.
The foreign-default case records the actual original bound service frame and
foreign self identity using a temporary profile observer. A task-side bypass
would produce zero observed calls. The observer restores any prior profile.
Default-composition checks use the unpatched original composer. Task.instructions
keeps its original services callback; only the default WorkflowServices method
selects the full own-task composer. That service need not call runtime_prompt
after extraction.

Results uses an explicitly controlled local target and empty received set. The
actual selector/union-credit calculation returns zero; no scientific/native
result or positive progress is invented. Acquisition returns are controlled
completed/invalid/failed/unavailable dictionaries. The actual selected task
records its original action, returned outcome and original progress measurement,
with the observation and controller-input callbacks recorded once. Same-key
replay retains the measurement without a new acquisition; changed reconstruction
is rejected. Saved wait replay uses an explicitly saved synthetic original
measurement and forbids a new wait/projection. These are task-to-controller-input
checks, not proof of a complete numerical iterator/scientific workflow.

Outgoing endpoints preserve the original assignment object, even when it has
not been validated as an admissible child request. They add no Store write or
prevalidation exception. Actual original child admission and typed report/
redelivery checks remain required separately; an identity transmission check
cannot establish admission. Existing launch_connected checks cover actual
native child preparation, task/receipt ports and Workflow.build. Full Results
saved payload, byte-window/provenance and union-credit tests remain separate.

The environment variable GENE_PRIVATE_TASK_PHASE is optional for ordinary test
collection. The coordinator driver sets baseline or connected explicitly; the
fixture then rejects the other implementation phase. Without it the test checks
the actual installed phase without claiming a retained pre-change baseline.
This is test selection only, not application/runtime configuration.

All process creation and network connections are denied during these tests.
Run serially through the established whole-workflow launcher, with original
CPU/RAM/swap bounds and all pytest temp/cache/output under the owning run. No
elapsed-time, token, turn, action-count or process-count gate is introduced.
