A104 API task/service boundaries
===============================

These helpers run only under the repository single-workflow launcher. They
contain no external transport, model, native execution, or new stopping policy.
The caller's configured scientific yield controller remains the application
controller. Fixed action indices identify original test observations; they are
not execution limits.

`api_cases.py` constructs the existing six private API owners through five
actual parent factories and the direct constructor where the immediate axis
factory is absent. Store, Journal, EpisodeRef, EpisodeReceipts, API service,
selected action, saved intent/snapshot, projection, completion proof and
controller input use own-A104 code. Controlled HTTP response bytes preserve the
original UniProt/HMMER/NCBI protocol fixture forms. Source metadata are never
claimed as target evidence.

The ordinary service/iterator fixtures use explicitly saved standalone API
contexts. They are separate from actual parent admission. Non-HPC parent
admission currently encounters the missing parent launch schema; four real HPC
plan fixtures retain their Aurora-only request and actual API denial. Controlled
saved-parent tests separately exercise real typed handoffs and receipt readers
where the current parent contract admits that request. They do not authorize
API execution through an HPC commission.

The completed/invalid/failed/unavailable iterator tests retain the entire
returned payload, operation key, selected action, receipt, operational credit
and original controller input. Failure/unavailable operation returns are
explicit controlled ports; invalid arguments use the real API service.
Completed replay performs no additional request, receipt or credit projection.
Saved reason/wait results and unfinished wait behavior remain distinct from
fresh action availability. The wait service is controlled; its original return
enters the actual iterator without a new credit projection.

Decision tests use actual tasks, Journal/exchange codecs and a controlled model
return. They compare full instructions and context/schema payloads. Provider
presentation uses the actual provider, including ordinary/bootstrap/update/
lookup/JSON forms and HPC-before-API precedence. The named presentation protocol
must be installed once by the combined source composition.

Report tests use real child validation, parent readers, saved request/form/
attempt/action rows and receipt storage. The progress callback and optional
native timing projection are explicitly controlled ports; their original keys,
order and persisted reuse are tested without claiming a native measurement.
Cached original admission cannot reprice work. Saved-parent identity failures
are retained. A successful typed-report test is not whole-tree integration.

`api_saved_carriers.py` supplies only the completed UnitRecord observation and
closure boundary. Actual Workflow.build, selected API/capabilities execution,
on_close, archive, facts and credit readers create the carriers. All eighteen
API/Launch/Results captures must succeed before the source split. Results uses
the real saved handoff and actual UniProt result acquisition. These are supported standalone
invocations of existing homes with literal caller factories, not invented HPC
children or former global factory authority. The exact original descriptors,
configuration, action/credit rows, receipt prefixes and bytes are retained.
The supported Store constructor opens a verified copy for post-change reads.
Current descriptor construction and saved-descriptor composition are separate
observations. A refusal remains a refusal; no digest alias or historical-row
rewrite is permitted. Constructor success is not complete saved-action restore.

Required retained assets and original methodology
------------------------------------------------

The promotion receipt pins the source originals and reusable dependencies:
root/tests/hpc_launch_task_checks.py, hpc_planning_allocation_task_behavior.py,
hpc_prediction_inputs.py and its Aurora queue fixtures; root/examples retained
Aurora resources; root/tests/test_api_service_integration.py and
test_execution_closed_credit.py; tests/api_execution_fixture.py,
test_api_execution.py, test_api_service_recovery.py, test_public_search.py.
Old shared-package imports are methodology, not an execution dependency: the
promoted helper imports actual A104 application modules exclusively.

Broader received-reader/context conflicts, old descriptor composition refusal,
private version mismatch, real native parent repairs and count-ceiling removal
remain separate. The source transition must account exact final parent/API/
Results/native source lists, the single provider hook and protected first-base
callbacks. The independently corrected sixty protection checks remain required.
