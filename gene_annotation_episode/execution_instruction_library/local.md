Local execution

Lightweight reads and bookkeeping can remain immediate. For a substantial
algorithm, commission launch -> launch_local with its native requested_job, or
the existing detached homology launch. Launch prepares inputs/environment and
uses practical.job.start or homology.submit; return the original handle when
usable. Do not wrap a long calculation in practical.command.run or call a known
blocking ordinary algorithm and expect the parent to continue meanwhile.

Use the existing local resource reservation and owned systemd service. Account
for worker, coordinator and provider resource use together. One workflow per window
does not mean one workflow globally. Other windows' load affects availability,
but their independent workflow slots remain theirs. A busy admission preserves
prepared work; observe again when useful rather than create duplicate attempts.
Use the original status/collect operations and release only after the service
is quiescent. Retain actual elapsed times and terminal failures for future work.
